# v0.43 计划 — **布尔 flag 的三条语义**

> 范围来源：[v0.42 复盘](./v0.42-retrospective.md) §7 候选 1。
>
> 一句话目标：v0.41 / v0.42 管的是**取值 flag**。这一版管**布尔 flag**——
> 它的语义由 Go 标准库定，而有一条**产品自己写下**的不变量要一并钉住。

---

## 0. 四条断言

依据两处，都是产品自己写下的：

| 依据 | 出处 |
|------|------|
| Go 标准库 flag 对布尔 flag 的语义 | `--flag` ≡ `--flag=true`；`--flag=false` ≡ **不给**；`--flag=x` 是**错误**；布尔 flag **从不消费下一个 token** |
| 「`--all`（布尔）**绝不能吞掉**紧随其后的 positional」 | `normalizeArgs` 的注释——它存在的理由就是"重排时别把位置参数吃掉" |

于是：

| # | 断言 |
|---|------|
| ① | `--flag=true` ≡ `--flag`（逐字节相同） |
| ② | `--flag=false` ≡ **不给**这个 flag（逐字节相同） |
| ③ | `--flag=x` **必须失败**（静默当成 true 是最坏的处置） |
| ④ | `--flag ZZ-JUNK` **必须失败**（那个 token 是 positional，不是 flag 的值——被吞掉就是**静默丢了一个参数**） |

## 1. 表**从源码派生**，不手抄

`fs.Bool("name"` 出现在 `cmd/ngm/<command>.go` 里。这样表就不会带上我记忆里的错条目。

> 初版就是我凭记忆手抄的，里面有 `remove --force`、`typecheck --json`、`css --sourcemap`
> 这些**根本不存在的组合**——判据于是把「flag provided but not defined」当成缺陷报了出来。

## 2. 派生规则的**公开误差**

子命令文件（`cache` / `store` / `config` / …）里可能有属于**某个子命令**的 flag。
那种组合在运行时会说 `flag provided but not defined`——**公开跳过、计数、报出来**，
并保证"派生表里的每一对要么跑完、要么被公开跳过"。
