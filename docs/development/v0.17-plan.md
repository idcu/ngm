# v0.17 计划 — 解释输出必须有界

> 范围来源：[v0.16 复盘](./v0.16-retrospective.md) §7 候选 1（`why` / `tree` 的 `paths` 语义）。
>
> 一句话目标：`ngm why` 与 `ngm tree` 是这套工具的**解释力**所在。先审语义，再审规模——
> **语义是对的，规模是失控的**：两者都随图"宽"指数增长，而图形状来自**上游清单**。

---

## 0. 为什么有这一版

### 0.1 先审语义（结论：正确）

构造了三类既有测试没覆盖的图形，实测：

| 图形 | 期望 | 实测 |
|------|------|------|
| 菱形（两个 mid 都依赖同一个 leaf） | 两条路径 | ✅ 两条 |
| 根声明 + 也被传递引入 | 直接路径与传递路径**同时**给出 | ✅ 3 条（1 条两元素 + 2 条传递） |
| 环（alpha ⇄ beta） | 不挂住、标出来 | ✅ `install`/`verify` 退 0；`tree` 标 `↺ cycle (not expanded)`；`why` 给出路径 |

**没有发现语义缺陷。**（这条"负面结果"本身就是结论：工具的核心解释力是对的。）

### 0.2 再审规模（结论：失控）

`FindPaths` 枚举**全部简单路径**（这是语义要求：多父时必须都给出），
`tree` 把同一份图**按路径展开**。实测格状图：

| 节点数 | 路径数 | 耗时 | 分配 | 存活堆 |
|--------|--------|------|------|--------|
| 33 | 65 536 | 0.073s | 63.3 MB | 30.1 MB |
| **41** | **1 048 576** | **0.778s** | **626.1 MB** | **453.3 MB** |

**41 个节点 → 626 MB**；再宽一层是 16 倍。而图的形状来自**每个依赖自己的 `ngm.json`**，
不是本项目的输入——一个写坏或恶意的上游就能让 `ngm why` 在 CI 里 OOM，
而**没有任何现有检查会红**：退出码 0、输出"正确"，只是多到没法用。

## 1. A 组 — 上界：可见、且同时约束工作量（[ADR-024](../adr/adr-024-bounded-explanations.md)）

| 命令 | 默认上界 | 解除 | 达到上界 |
|------|---------|------|---------|
| `ngm why` | 64 条路径 | `--all` | 文字写明"已列出 64 条（还有更多未列出）"；`--json` 带 `pathsTruncated` / `pathsLimit` |
| `ngm tree` | 4096 个条目 | `--all` | 文字写明"树不完整"；`--json` 带 `entriesTruncated` / `entriesLimit`；停止处条目带 `truncated` |

三条判据（缺一条这个决策就是错的）：

1. **同时约束输出与工作量**：达到上界即**停止枚举/展开**，而不是先算完再砍短。
2. **截断必须可见**：静默截断比不截断更糟——它让"只看到 64 条"被读成"只有 64 条"。
3. **不许多报**：恰好等于上界时 `truncated` 必须是 `false`（实现上用"多枚举一条"区分）。

**退出码不变**——截断不是错误。

## 2. B 组 — 输出示例必须与快照同形

审 A 组时顺手发现：`docs/architecture/observability.md` 的 `ngm why` 与 `ngm tree`
两段**输出示例**都在画渲染器**从不产生**的形状（树形方块 + `├──`），
而该页自己声明"输出即当前真实行为"。

| 项 | 内容 |
|----|------|
| 修文档 | 两段示例改成**快照本身**（`testdata/why.golden` / `tree.golden`，用 `<sha>` / `<digest>` 占位），并注明"这段就是快照" |
| 网 | `TestV17DocOutputExamplesMatchTheGoldens`：从文档里取出这两段示例，与 golden **逐行对照**（先归一化：依赖标识 / sha / digest / 时间 / 数字 → 占位符；**形状必须逐字相同**） |
| 边界 | 它证明"示例与快照同形"，**不**证明示例覆盖了所有输出形态（那是 golden 的事） |

---

## 3. 明确不做

| 不做的 | 理由 |
|--------|------|
| 按**时间**限制（超时截断） | 同一份输入在不同机器上会给出不同结果，与"确定性"冲突。上界必须是**输入规模**的函数 |
| 给"深度"设上界 | `why` 的路径长度与 `tree` 的层数由解析器的环保护兜底；没有真实案例证明深度会失控（见 ADR-024 的重开条件） |
| 统一 JSON 形状（v0.16 已记） | 破坏性变更 |
| 让 `tree` 变成"去重树"（节点只展开一次、重复处标 `(见上)`） | 那是**语义重设计**，不是上界问题：它会让条目数变成线性，但也改变 `tree` 的形状与快照。记录为候选 |

go test -count=1 -run 'TestV17' -v ./internal/observability ./cmd/ngm
