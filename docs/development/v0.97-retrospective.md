# v0.97 复盘 — **两条实现必须对同一批输入给出同一批结论**

> 计划：[v0.97 计划](./v0.97-plan.md)
>
> 一句话结论：链接检查的两条实现（shell 管存在性、Go 管大小写）第一次被放在**同一份语料**上对账——
> 当场抓出**两处**分歧，其中一处是 shell 侧的**语义错误**（根相对链接解析错了）。

---

## 1. 为什么要对账（而不是"两边都过就行"）

v0.78 的教训就在隔壁：当年"**自检器比产品严**"——同一件事两份实现，谁也没对过账，
而发现它的代价是一次**误判**。v0.96 引入 Go 侧解析时也留下了一处不一致（§2 第 1 条），
说明"两条实现都过"推不出"它们会对同一批输入给出同一批结论"。

## 2. 对账抓到的三件事

### 2.1 Go 侧漏了围栏代码块规则（v0.96 的不一致）

shell 在 v0.96 加了"围栏块整块跳过"，Go 侧没有 ⇒ 围栏块里的**示例**链接会被 Go 侧
当成真链接去查大小写（潜在误报）。处置：把扫描核心抽成 **Go 侧唯一的实现**
（`linkrefs_test.go`），大小写判据与对账判据共用它。

### 2.2 shell 侧：根相对链接解析错了（语义 bug）

一致性网第一版就红在 `[坏（绝对根）](/nope.md)`：**shell 报、Go 不报**（Go 当时直接跳过它）。

顺着查下去发现是 **shell 错了**：Markdown 里以 `/` 开头的链接相对**仓库根**
（与 GitHub 一致），而 shell 把它按**文件所在目录**拼 ⇒ `[x](/LICENSE)` 会去找
`docs/adr/LICENSE`。先量：全仓**0 处**这样的链接 ⇒ 修它不影响现网，纯粹是让它符合语义。

修的时候又踩到一处：剥前导 `/` 要**在规范化之前**做——留着它会让 `normalize` 走
"绝对路径"分支，于是 `[x](/README.md)` 去找 `C:/…/Git/README.md`（实测）。
两处都是**对照网自己抓出来的**（它先报分歧，我再去查是哪一边错）。

### 2.3 Go 侧的一处自身错误（v0.96 的牙齿抓的）

抽共享实现时 `resolveRef` 写成 `filepath.Rel(绝对, 相对)` —— 这在 Windows 上**直接报错**，
而报错被当成"这条链接不用查"静默跳过 ⇒ 牙齿（临时树）当场指出"应当报 1 条，报了 0 条"。

## 3. 判据形态

| 项 | 做法 |
|----|------|
| 语料 | 25+ 形态，把 v0.91 ~ v0.97 各自的坑都摆上（反引号 · 围栏块 · 平衡括号 · `.go` / 目录 / `vendor` · `..` · **根相对两侧** · 含空格的文件名） |
| 比较 | "坏链接三元组（文件:行号:原文）"排序后**逐条相等**，失败时说清"只有谁报了" |
| 真仓库 | 两边都应当为空，且 Go 侧扫到 **> 1000** 处（防"范围缩了、变成空比"） |
| 刻意不放 | 括号**不配平**的形态：按 CommonMark 那根本不是链接，shell 的回退路径消息形态不同（判定相同）——它的判定由 v0.91 的黄金用例守着 |

## 4. 顺带：443 冲突改成"显式登记的环境条件"

v0.95 的 https 端到端要求独占 443（ngm 不接受显式端口）。端口被占是**环境条件**，
不是缺陷 ⇒ 改成 `t.Skipf` 并把原因打印出来（SKIP 在 `-v` 与 CI 摘要里都看得见，
不静默通过、也不误报成缺陷）。先例：v0.88 的 `.ps1` 判据在没有 powershell 的机器上就是这样。
