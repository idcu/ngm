# v0.28 计划 — 可行动的建议不许在包装时丢掉

> 范围来源：v0.27 之后的一次普查（"错误有没有下一步"）。
>
> 一句话目标：`ngm` 的错误文本里那句 `hint:` 是**给用户的下一步**。
> 这一版修一个实测缺陷——**它在包装时会被丢掉**。

---

## 0. 为什么有这一版

普查（用 `go/ast` 扫非测试代码）：全仓库 **300 个** `errs.New/Wrap` 构造点，
其中 **129 个**的 hint 是空字面量；用户层（`cmd/ngm`）47 个构造点里 11 个是空的。

但**数量不是重点**。重点是探针量出来的这一条：

```
inner : GitFetch: fetch failed
          hint:  check your credentials
outer : ConfigInvalid: cannot read the lock
          cause: GitFetch: fetch failed          ← 建议不见了
```

`FormatHuman` 只打印**最外层**那条错误的 hint。内层带着可行动的建议、
外层 `Wrap` 时给了空 hint——用户就再也看不到那句话了。

## 1. A 组 — 在**渲染处**修，而不是在 129 个构造处修

`FormatHuman` 在自身 hint 为空时，沿 `Cause` 链取**第一条**非空 hint。

为什么是这个位置：

| 选项 | 代价 |
|------|------|
| 给 129 个构造点逐个补 hint | 要凭空发明 129 句建议，且每处都得重新判断 |
| `Wrap` 时继承 cause 的 hint | 改动错误**数据**（`--json` 与 `errors.As` 的消费者会看到变化） |
| **渲染处回退**（采用） | 一次覆盖全部站点；**不改任何错误数据**——hint 本来就是给人读的 |

## 2. B 组 — 两道网

- `internal/errs`：内层 hint 熬过 1 层与 2 层包装 · 自己的建议优先 ·
  整条链都没有建议时**不许凭空造一句** · 标签仍来自最外层（v0.23 不许被碰掉）·
  `Error()` 一直不含 hint，这次也不许长出来。
- `cmd/ngm`：**棘轮**——用户层的空 hint 构造点不许变多（当前读数 **11/47**，
  上限就是 11）。它**不**要求零：有些错误确实没有比"它不存在"更有用的下一步。

## 3. 顺带 — `update:1` 的逐步骤量

v0.22 起 `update` 的 1 / 2 / 5 一直是"已知缺口"。这一版用"把一条命令拆成
前后两次 `verify` + 中间的 `update`"的方式逐步骤量，看清了它为什么测不到：

- 上游挪 tag、mirror 停在旧提交时，`verify` **确实**看到漂移 → **1** ✓；
- 但 `update --all` 退 **0**，且写进 lock 的是**新提交**（它已跟上新 ref），复检与它一致。

⇒ 走到 1 需要"更新写完、复检仍看到漂移"，即**上游在两步之间又动一次**——竞态，不是夹具能固定的状态。
声明的代码路径真实存在，只是**无法被确定性触发**。缺口记录已按实测链改写。
