# v0.12 计划 — 让读数说真话（第二轮：文档与静默失效）

> 范围来源：v0.11 复盘 §7 的候选 0 / 1 / 4，外加 2026-10-04 的一次**外部复核**
> （直接问两个发行源的 API、本地全量构建与测试、一次"静默失效"专项审计）。
>
> 一句话目标：**让项目对外说的每一句话，都能被一条命令或一次 API 读数验证。**
>
> 本版**几乎不加新能力**（唯一的例外是子命令帮助）。它修的是"读数与真实行为不一致"——
> 包括**文档自己**的读数。

---

## 0. 为什么有这一版

v0.11 的 C 组证明了一件事：**内部一致性检查全绿时，项目仍然可能一条命令都跑不通**
（端口被丢、输出自相矛盾、文档里的命令跑不通）。v0.12 沿同一条线再走一圈，
把检查对象从**代码**扩到**状态页与发行源**——两边都抓到了东西：

| 抓到了什么 | 出处 |
|-----------|------|
| 6 处文档与事实不符（其中 1 处是"两个源都可取到"被证伪） | 本轮外部复核 |
| 5 处"静默失效"缺陷（2 处高危） | 静默失效专项审计 |
| 1 处门禁级缺陷：子命令 `--help` 是**死代码** | 实现子命令帮助时发现 |

## 2. B 组 — 许可证

根 `README.md` 与 `docs/README.md` 此前写"**保留所有权利、未授予任何许可**"。
那让**评估之后想用的人也无法合法使用**，而项目的下一步恰恰是"找一个真实使用场景"：
一个没人有权运行的工具，收集不到它唯一需要的那样东西。

- 新增 `LICENSE`（**MIT**，与 pnpm / Bun / Deno / Vite / esbuild 同一取向）
- 两处 README 的许可证段落改写，并说明这次改动**为什么不是立场变化而是纠错**

## 3. C 组 — 子命令帮助（本版唯一的功能增量）

| # | 计划 | 结果 |
|---|------|------|
| C1 | `ngm <cmd> --help` 打印**该命令自己的用法** | ✅ 复用它的 `xxxUsage` 常量，不另写一份帮助文本（同一件事写在第二个地方就一定会有一处不一致） |
| C2 | 根级 flag 的作用域：子命令**之前**才算根级 | ✅ 修掉一个**门禁级**缺陷：此前根级 `--help` 扫描**整条** args，于是 `ngm verify --help` 拿到的是根帮助，子命令帮助那一分支**永远走不到**——它打印的 "help not yet implemented" 没有任何人见过 |
| C3 | 21 个命令逐个断言 | ✅ `TestV12SubcommandHelpPrintsItsOwnUsage`：逐字等于该命令的用法常量（不是"包含关键字"） |

## 4. D 组 — 五处"静默失效"缺陷

同族的判据（前几版已多次吃过）：**内部一致性检查全绿，而对外行为是错的**。

| # | 缺陷 | 后果 | 修法 | 严重度 |
|---|------|------|------|--------|
| D1 | `ngm outdated --offline` **实际会触网**：它把在线版 `EnsureMirror` 交给检查器（mirror 在则 `fetch`、不在则 `clone`），而检查器只在 branch 分支读 `Offline` | `--offline` 被绕过；失败时报 `mirror unavailable: <net 权限错误>`——指向 mirror 可用性，一个**错误的方向** | 与 `verify`/`update`/`install` 对齐，改用 `offlineEnsureMirror`；文本报告把 `unknown` 的**原因**打印出来（此前原因只存在于 `--json` 的 `note` 字段） | 高 |
| D2 | `ngm audit --json --hook` 把 hook 的横幅与它的 stdout **追加进同一个 stdout** | stdout 不再是一份 JSON 文档，而它标着"给 CI 用"；`verify` 修过同一形态（`--json --sandbox`） | 与 `finishVerify` 同一条规矩：`jsonMode` 时 hook 的输出走 stderr | 高 |
| D3 | `ngm css a.css b.css`（或 shell 展开的 glob）只编译第一个、exit 0、**一句话不说** | glob 是它最常见的用法，用户没有理由怀疑自己丢了一半输入 | 补位置参数计数校验（本目录里唯一缺这一处） | 中 |
| D4 | `GenerateTypeDecl` 把整个进程结果丢掉（`_ = res`） | 引擎**退出 0** 时写下的提示（tsc 的跳过提示）一个字都到不了用户；Bundle / Transform / Compile / Check 四条路径都转发，只有它在吞 | `TypeDeclResult` 增加 `Warnings`，命令层转出 | 中 |
| D5 | `integrations.Apply` 声明"全有或全无"，但**那道门只挡冲突**：逐个 `os.WriteFile`，写到第 k 个失败时前 k-1 个已落盘 | 磁盘上留下半套脚手架，错误只点名失败的那个文件 | 两阶段：先全部写临时文件 → 再改名就位；失败清理临时文件，改名阶段失败则**列出已就位的文件** | 低-中 |
| D6 | 非默认端口被**静默丢弃**（v0.11 D1 的"静默"这一半） | 连到错误主机，报错指向网络 | 明确拒绝（exit 3 + 报出端口）。按 **scheme** 判定默认端口（`:443` 在 https 下接受、在 `git://` 下拒绝）；真正的端口支持仍等真实需求 | 中 |

## 5. E 组 — 机械网

| # | 网 | 守什么 | 牙齿验证 |
|---|---|--------|---------|
| E1 | `TestV12EveryRegisteredFlagIsDocumented` | 扫源码：注册到 flagset 上的 flag 必须在该文件中被写下过。命令行 flag 此前**没有任何机械网**（配置结构体字段有 `field_wiring_test.go`，flag 没有） | ✅ 用一个临时探针文件注册 `--zz-teeth-flag`，网变红并**点名文件与 flag**；删掉探针后恢复绿 |
| E2 | `TestV12RootHelpIsScopedToBeforeTheSubcommand` | 根级 flag 的作用域（`ngm --help` vs `ngm verify --help`） | ✅ 与 C2 的缺陷同源 |
| E3 | `TestV12ApplyIsAllOrNothingOnWriteFailure` + 对照 | 脚手架写入的全有或全无 | ✅ 对照用例是必须的：一个"永远失败"的实现也能让"什么都没写"变绿 |
| E4 | `TestV12PortIsRefusedNotDropped` | 端口：默认端口接受、非默认端口拒绝、**按 scheme 判定**、空端口号也拒绝 | ✅ |
| E5 | `TestV12TypeDeclForwardsEngineDiagnostics` | 诊断通道 | ✅ |
| E6 | 审计 `outdated --offline` 的端到端用例 | 冷 mirror + `--offline` **不许**去够远端，且必须说出原因 | ✅ 断言的是**原因文本**（只有 `offlineEnsureMirror` 会产出 "no local mirror"），不是退出码 |

**E1 的边界写在测试注释里**：它证明"这个 flag 至少被写下来过一次"，
不证明"写得足够清楚"；反方向不断言，因为**会误报的门禁会被忽略**。
判据取"原始字符串字面量里出现过"，而不是搜整份源码——否则注册调用自己的描述文本
会让网被自己满足。

## 5.1 F 组 — Gitee 侧的发布读数（**追加**，不在原计划里）

A 组在核对"两个源都可取到"时暴露了一个空白：`scripts/check-release-status.sh --published`
**只问 GitHub**，于是 Gitee 侧"到底有没有这个发行版"只能靠人去点——
而正是这条空白长出了那句错的"两个源都可取到"。

| # | 计划 | 结果 |
|---|------|------|
| F1 | `scripts/check-gitee-release-status.ps1`：只读公开 API，逐 tag 报"有没有发行版 / 7 个附件齐不齐" | ✅ 实测：**就位 3 个、缺 8 个**（`v0.1.0` 及 `v0.5.0`~`v0.11.0`） |
| F2 | 判据与 GitHub 侧对齐：**查不动不报成功**（exit 3） | ✅ 实测（指向死地址 → `NOT CHECKED` + exit 3） |
| F3 | 处理"Gitee 自动附 2 个源码包"的计数差异 | ✅ 按**名字**排除 `<tag>.zip` / `<tag>.tar.gz`，而不是按数量相减 |
| F4 | 不需要 token | ✅ 公开 API 即可读；"补发"才需要 token |

> 它是**本地读数**（CI 跑 ubuntu、没有 PowerShell），这一点在脚本头部写明了理由——
> 与 `upload-gitee-assets.ps1` 同一条纪律：Gitee 侧的工序只有 .ps1 一份实现。

## 6. 明确不做

| 不做的 | 理由 |
|--------|------|
| 非默认端口的**真正支持** | 要给 `Canonical` 加字段，且 mirror 目录在 Windows 上不能含 `:`——schema 级变更，先有真实需求 |
| 可达性删除（store GC） | [ADR-018](../adr/adr-018-store-reclaim.md) 的两个条件未变（缺项目注册表） |
| 任何性能优化 | 本版的问题是"读数不真"，不是"读数不快" |
