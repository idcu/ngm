# v0.90 复盘 — **登记表是待办清单，不是永久豁免**

> 计划：[v0.90 计划](./v0.90-plan.md)
>
> 一句话结论：v0.89 把"没人跑"变成必须登记的事实；这一版把那张表**变短**——
> 而且每接一个进判据，就顺着发现交接处的问题：**两个入口在吞参数**、
> **一个每次 CI 都跑的检查慢得像忘了关的灯**（133.72s），以及
> **一条网被自己的注释骗过去**。

---

## 1. 入口与实现之间：参数被吞

| 发现 | 处置 |
|------|------|
| `check-mirror-coverage.ps1` 只声明 `-Repo`，**不转发 `--api-base`** —— 而那个选项存在的全部理由就是"给判据指一个本地假 API" | 入口补 `-ApiBase` |
| `check-library-standard.ps1` · `check-vendored-standard.ps1` 漏了 `--help` | 补 `-Help`（直接转给实现） |
| `check-release-status.sh`（"开工先对状态"那条读数）**没有** Windows 入口 | 新增入口，转发 `--published` / `--repo` |
| 两个旧入口里用的是 `$args`（PowerShell 的**自动变量**） | 改名 `$shArgs`（掩盖未绑定参数是给自己下绊子） |

**纪律**：实现支持的选项，入口必须**带引号地转发**。这条由新网 `TestV90WrapperOptionsParity` 守着；
没有入口的脚本必须在 `noWindowsEntry` 里写明原因（目前只有 `probe-reproducibility.sh`：CI 专用探针）。

> **这条网第一次写错了，是牙齿抓出来的**：第一版查的是"入口文本里有没有 `--api-base`"，
> 而入口的注释里**正解释着这个选项**——于是"提到"冒充了"转发"，牙齿不红。
> 改成必须**带引号转发**（`@('--api-base', $ApiBase)` 这种形状）后才对。
> 这与 v0.89 那条网写明的是同一件事：**按文本记账是筛子**——但用在这里糊弄不过去。

## 2. 判据与入口之间：五个入口真的跑一次

`TestV90PowerShellWrappersRunTheirImplementation`：五个 `.ps1` 各跑一次，
每个都用**必然失败的输入**验它的退出码与点名传了回来：

| 入口 | 反面输入 | 断言 |
|------|---------|------|
| `check-vendored-standard.ps1` | 不合格的 vendored 夹具 | exit 1 + 输出里有点名的依赖与判据 |
| `check-release-status.ps1` | 合成仓库（删掉 tag） | exit 1 + 点名缺哪一版 |
| `check-mirror-coverage.ps1` | 本地假 API | 读数（`2 tag(s)` / `UNPUSHED: 1`）必须出现 |
| `write-readings-summary.ps1` | 假 API + 预先写好的 `-Out` | 摘要写成、两段都在、追加语义成立 |
| `check-docs-links.ps1` | 真实 README | exit 0（整树的语义由下面那条负例网守着） |

**登记表因此从 5 条缩到 2 条**（`upload-gitee-assets.ps1`：需凭据 ·
`check-gitee-release-status.ps1`：没有离线模式）——它是**待办清单**，不是永久豁免。

## 3. 实现与自己之间：一个检查慢得像忘了关的灯

新网的第一个版本跑出 **132 秒**，而我一直以为它是一两秒的（输出只有一行 `all docs links OK` ✗）。
量了才发现**实现本身**就慢：

| | 耗时 |
|---|---|
| `.sh` 扫 `docs` + `README.md` | **133.72 s** |
| 只扫 `README.md` | 0.38 s |

**根因**：内层循环对**每一条链接**都起子进程（`dirname` + `cd … && pwd`）。
docs/ 有 **248 个文件、上千条链接** ⇒ 上千次 spawn。

**处置**：`normalize_path` 用纯 bash 折叠 `./` 与 `../`（不做符号链接解析——本检查只问"文件在不在"，
仓库里也没有链接目录）。实测 **133.72 s → 33.07 s**（4×），结论不变。

**为什么要配一条负例网**：加速最容易顺手改坏语义，而改坏了会**伪装成"全过"**。
`TestV90DocsLinksStillCatchesBrokenLinks` 造 4 条链接（存在的 · `../` 形式 · 子目录形式 ·
反引号里的示例 · 一条真坏的），要求恰好报 1 条，且反引号里的那条**不许**被算进来。

> 剩下的 33 秒来自每文件一次 `sed` + 一次 `grep`（约 500 次 spawn）。
> 一次进程搞定能到秒级，但那是**重构**，留给 v0.91（数字与做法都写在这里，不用重新发现）。
