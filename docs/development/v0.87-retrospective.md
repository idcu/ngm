# v0.87 复盘 — **把"逐字对齐"从人工声称变成机械判据**

> 计划：[v0.87 计划](./v0.87-plan.md)
>
> 一句话结论：v0.78 修好"自检器比产品严"之后，两边是**人工**对齐的——
> 这条版本把它变成一条网：11 种形态，两侧必须给出**同一个入口**。
> 顺带明确了一处**说不清就不说**的边界（`Types` 没有机械对账）。

---

## 1. 交付

### 1.1 入口对齐网（`TestV87EntryInferenceAgreesBetweenProductAndChecker`）

11 种 `package.json` 形态，两侧各推断一次，**必须相同**：

| # | 形态 | 两侧都该给出 |
|---|------|-------------|
| 1 | `ngm.json` 的 `main`/`types` | 第 1 层（即使 `package.json` 另有 `main`） |
| 2 | `exports` 字符串 | 那个字符串 |
| 3 | `exports` 的 `"."` 是字符串 | 同上 |
| 4 | `exports` 条件（`types` + `import`） | `import` 的目标 |
| 5 | `exports` 没有 `"."`（本身就是条件映射） | `import` 的目标 |
| 6 | `exports` 只有 `require` | `require` 的目标 |
| 7 | `exports` 的 `default` 先于 `require` | `default` 的目标 |
| 8 | `main` / `types` 字段 | `main` |
| 9 | 只有 `index.js` | index 约定 |
| 10 | 只有 `index.cjs` | index 约定（v0.78 补的那一层） |
| 11 | 什么线索都没有 | **两侧都为空** |

一侧是 `mappings.InferEntry`（产品真正会写进 `mappings` 的入口，判据里给了它一个**真实目录**读器），
另一侧解析自检器**自己打印的那句话**（`入口 <path>（来自 …`）——
因此它同时守着"报告里写出来的"与"产品真正用的"一致。

**牙齿**：把自检器的候选层次里 `exports` 那两层拿掉 ⇒
`exports 字符串` / `exports 的 "." 是字符串` / `exports 条件` / `exports 没有 "."` **四条子测试当场红**；
恢复 ⇒ 全绿。

### 1.2 一处边界，写下来（而不是留给猜）

自检器只打印 **Main**；`Types` 只判"有没有"（`types-provided`），不判"是不是同一个路径"。
所以这条网对账的是 Main —— `Types` 的逐字一致**没有**机械判据。
写在测试注释里，因为它是一处**已知缺口**：下一个想改 `Types` 推断的人要知道自己走的是没有网的路。

## 2. 为什么不让自检器直接调用产品代码

那会更"省事"，但会把两条实现合并成一条：自检器的价值正在于**独立**——
标准由它执守，产品自己读；两边对账才叫一致，合并之后只剩自证。

> 一般的话：**"两边应当一致"必须有一条网**；没有网的"一致"只是上一次有人看过。
