# v0.40 计划 — **参数怎么写**

> 范围来源：[v0.39 复盘](./v0.39-retrospective.md) §7 候选 1。
>
> 一句话目标：v0.39 枚举的是"**有没有**参数"。这一版枚举"**参数怎么写**"——
> 顺序 · 重复 · `--`。三族各自都对应产品自己写下的一句话。

---

## 0. 三族与它们各自的"产品原话"

| 族 | 产品原话（出处） | 判据 |
|----|----------------|------|
| **顺序** | `normalizeArgs` 注释：「flag.Parse 在遇到第一个 positional 时停止，因此 `ngm init <name> --dir=x` 需要重排」 | 两种顺序**输出逐字节相同**（路径归一化后） |
| **重复** | Go 标准库 flag 的语义：**最后一个胜出** | `--dir=<坏> --dir=<好>` 与 `--dir=<好>` 一次运行**行为相同**；反向亦然 |
| **`--`** | `normalizeArgs` 注释：「`--` 之后一律视为 positional」 | `--dir=<好> -- --dir=<坏>` **绝不让坏目录生效** |

判据不是我编的，而是**把产品已经写下的三句话变成可执行的断言**。

## 1. 判别式要选**不会说谎**的证据

"坏目录生效了"这件事，不能用"输出里出现过 <坏>"来判——把 token 当 positional 的命令会**回显**它
（`why` 说 `--dir=<bad> is not in the dependency graph`、`engines` 说 `unknown subcommand: --dir=<bad>`）。

可用的证据只有两种：

- **文件系统痕迹**：创建型命令（`init`）会在那个目录里留下东西；
- **输出把它当目录**：`<坏>` **后面跟着分隔符**（`<坏>\ngm.json`）。

## 2. 每一族都要有"区分得开"的前提

重复 `--dir` 这一族，只有当**好目录与坏目录给出不同结果**时才有牙齿。
若某命令对两者给出同一份结果（实测 3 个），**如实跳过并报出来**——
比让它静默通过诚实。

## 3. 每一次运行都用**全新目录**

夹具的状态耦合会把读数说谎：`init` 的第一次运行会把坏目录**建出来**，
`add` 的第一次会把依赖**加进去**——后面几次看到的是别的状态
（`created` 变 `already exists`、`added` 变 `updated`）。
