# v0.101 计划：把三句承诺变成可测量的，并让证据能被消费

> 选题原则只有一条：**每一件都指着一个已经发生的事**——一条实测失败的探针、
> 一条自相矛盾的文档、或者一个被自己的判据抓到的缺陷。没有"也许将来有用"的条目。

## 一、为什么是这一版

v0.100 之后，代码层面已经"能做很多事"，但有三个性质从未被验证：

1. **对外的安全承诺是不是真的**（沙箱"无网络"、`install` 不丢文件、`run:git` 覆盖全部路径）；
2. **证据能不能被别人的流水线消费**（只有人读文本与 ngm 自己的 `--json`）；
3. **"结论"是不是都有证据**（有几处把"没查成"写成了"查出来是坏的"）。

三条各有一个实测例子。本版把它们收口，且**每条新判据都先红过**。

## 二、做什么

### A. 三个安全承诺，实测都不成立

| 承诺 | 实测 | 处置 |
|---|---|---|
| 沙箱"无网络" | `--deny-net --no-remote --deny-write --deny-run --deny-env --deny-read` 全给时，`import "npm:is-number@7.0.0"` **真的下载成功**，落进 `DENO_DIR/npm/registry.npmjs.org/…` | `DenoArgs()` 追加 `--no-npm --no-config --no-lock`。`--deny-net` 管的是 Deno API 的 `fetch`，而 npm 解析走运行时自己的 registry 客户端 |
| 依赖不能影响沙箱 | 依赖目录里的 `deno.json` **被自动加载**，`imports` 由上游控制 | 同上 `--no-config` |
| `install` 不静默丢文件 | `Foo.txt` 与 `foo.txt` 在折叠大小写的系统上竞争同一路径：`install` **报成功**、vendor 少一个文件，紧接着 `verify` 判 `critical exit 2` | 落地前**探测目标磁盘**，命中即在**清理旧 vendor 之前** fail-closed |

### B. 权限模型的两处缺口

`run:git` 不覆盖 `ngm modules`（6 处 `Options{Dir}` 无 `Policy`，而那条路径**写 ref**）
⇒ 单一构造点 `modulesGitOpts` + 源码级全称判据（含例外表与反向对账）。
`deny: ["env:X"]` 从未到达引擎子进程 ⇒ 新建叶子包 `internal/envutil`，三处施加点共用一份实现。

### C. 两个面向消费方的出口

`ngm verify --format=sarif|github`：**只做渲染，不引入新判定**；不编造行号（ngm 不知道行号，
写 `line: 1` 会把每条注解钉在文件第一行），级别跟着阻断语义走，两次渲染逐字节相同。
`ngm adopt`（[ADR-040](../adr/adr-040-adopt-proof-layer.md)）：为**已被别人装好**的
`node_modules` 出具内容证明，不接管安装；registry 来源**明确不是**它的轴。

### D. 证据链上五处"输出正常但结论错"

`attest` 给清单签名时**读两次** · `TagSignature` 把"git 没跑起来"说成"签名不可信" ·
`mappings` 入口可 `../` 逃出 vendor（存在性检查反而放行） · `why` 只约束**命中**不约束**搜索**
（不可达目标 1 048 576 条路径 / 626 MB，而报告说没截断） · `atomicfile` 不同步目录项。

### E. 两处不可信输入

`digest.ValidateRecord` + 模块重放入口校验：清单以 NUL 分隔字段，一个带 NUL 的 `Path`
能把**一条记录变成两条**。`BlobPath` 只认 64 位小写十六进制：此前一个 `../../…` 的"sha"
会让 `verify --deep` **去读那个文件**——篡改清单不只能骗过校验，还能选择校验读什么。

### F. 三个真实远端夹具

`gitee.com/idcu/ngm-fixture-{basic,monorepo,content}`，用底层命令造出来，因此任何机器重跑
得到同一批 SHA。只覆盖本地 mirror 假不出来的三件事：`ls-remote` 的 ref 广播形状、
真实 clone、`net:<host>` 门禁在出网前生效。默认 `t.Skip`。

## 三、明确不做

registry 互通与 pnpm/yarn lock 解析（pnpm 项目走**共存**）· `attest --sign` 与
`verify --format=policy`（没有消费方）· 新增命令（25 个已过多，本版只加**出口**）·
新契约网（下一张必须先指着一个**已经发生**的缺陷）。

## 四、验收

`go build` / `go vet` / `gofmt` 干净；`go test ./internal/...` 全绿；全部契约网绿；
M1–M7 与功能级 acceptance 绿。真实二进制复验：沙箱拒绝 `npm:`、大小写冲突 fail-closed
且不破坏既有 vendor、annotated tag 锁到剥离后的 commit、`--format=github` 出注解、
`adopt` 改一个字节后 digest 变。
