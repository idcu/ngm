# v0.70 复盘 — **接一层谓词：attestation（不做签名）**

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：新增 `ngm attest` 与 [ADR-027](../adr/adr-027-attestation.md)——
> 把"内容 ↔ commit ↔ 输入"写成**未签名**的 in-toto Statement v1（谓词 SLSA provenance v1）。
> 本版最有分量的决定是**不做什么**：ngm 不签、不发明格式、不分发密钥。
> 另外顺手修掉了 ADR 索引里一处挂了数版的缺陷（见 §4）。

## 1. 逐组验收

### 1.1 ADR-027：三问逐条写死

| 问题 | 答案 | 落处 |
|------|------|------|
| 谓词声称什么 | subject = purl + `archiveDigest`；输入 = 两个文件的**字节** sha256；materials = commit（`gitCommit`）+ 声明的 ref；**不声称**上游构建、可复现构建、许可证、依赖图形 | `internal/attest` 的字段映射逐字段可核对 |
| 谁签 | 用户/CI，用标准工具（`cosign attest-blob`）。ngm 产出**未签名**语句是刻意的：签名证明"谁说的"，不证明"说的是真的"（与 ADR-014 同一论证） | ADR-027 §2 + 命令用法文本 |
| 验什么 | 签名与策略由消费方用标准工具验；内容一致性仍由 `ngm verify` 验——**两条正交，互不替代** | ADR-027 §3 的对照表 |

### 1.2 `ngm attest`

| 决定 | 落处 |
|------|------|
| 只读 lock | 不触网、不重解析、不写项目（除 `--out`） |
| 确定性优先 | **没有时间戳**；`invocationId` = lock 的 `sha256`（SLSA 建议"唯一"，这里**有意**取"输入的哈希"——理由写进 ADR：审计复核要能比对字节） |
| 哈希语义写进数据 | subject 注解 `ngm/digest-scope`：`sha256 over the canonical archive manifest (ADR-008); not the tarball bytes`——最容易被误读的地方写在数据里，不只写在文档里 |
| 输入钉在字节上 | `ngm.json` / `ngm.lock` 的原始文件字节（重新序列化会掩盖手工编辑） |
| 出口 | `--out=<file>`；`--out=`（空值）与"没给"等价（v0.42 的不变量） |

**读数**：

```
同一 lock 两次导出          → 逐字节相同（本版比 sbom 更强：不需要剔除时间戳）
输入顺序打乱                → 逐字节相同
空依赖集合                  → 仍是合法语句（`"subject": []`，不是 null）
缺任一输入哈希 / 缺版本      → 报错（"wiring error"，而不是导出一份假完整的语句）
无 lock / 无 ngm.json        → exit 3 + hint
stdout 永远写失败            → exit 6（同其它报告命令）
```

### 1.3 既有契约网对新命令的接管（四张，模式与 v0.69 相同）

| 网 | 它问了什么 | 处置 |
|----|-----------|------|
| **V37**（23 命令 × 8 配置形状） | 参数表 22 项 ≠ 命令 23 个 ⇒ Fatal | `matrixArgs` 加 `"attest": {}` |
| **V22**（退出码声明对账） | 0/3/6 三个码各要实测或登记 | 0 与 3 进 `exitCodeMeasured`；6 进 `exitCodeElsewhere`（指针指向新增的 `…/attest` 子测试） |
| **V57**（码来源登记） | `runAttest` 的新出口 | 登记为 `catInternal`：`write report: %v`（v0.70 新增） |
| **V19 / V15**（用法文本与命令表） | 用法文本要有自己的 EXIT CODES；`cli.md` 要有一行 | 两者都在交付里 |

### 1.4 复用与搬移

`ngm attest` 与 `ngm sbom` 读同一份输入。为此把 lock → 导出条目的映射
从 `cmd/ngm/sbom.go` 搬进 `internal/sbom/entries.go`（`FromLock` / `Sort`）——
**规则不写在第二个地方**；两个命令、两种出口共用同一处排序与 purl 构造。

## 3. 设计偏离登记

| # | 计划写的 | 实际做的 | 为什么 |
|---|---------|---------|-------|
| 1 | SLSA 要求 `invocationId` "唯一" | 用 **lock 的 sha256**（确定性） | 审计复核要能比对字节；一次运行的唯一性由签名者的时间戳/身份补上——这比随机 id 提供的信息更多，且不破坏可复现 |
| 2 | 未细想语句粒度 | **单个**语句、多 subject | 一次物化的所有产物共享同一份 provenance；按依赖拆文件只会让签名次数翻倍 |
| 3 | 曾考虑逐依赖 `--dependency` 过滤 | 不做 | 没有具体消费方要求它；先交付最小完整形态 |
| 4 | 曾考虑 `internalParameters` 字段 | 省略 | ngm 版本已在 `runDetails.builder.version`；同一事实写两处会漂移 |
| 5 | 计划未写"注解命名空间" | 用 `ngm/` 前缀 | 不用我们没有的域名（不发明 `ngm.dev` 这类假 URI） |

## 5. 过程洞察

### 5.1 这一版的核心决定是"不做什么"

评估报告说"接一层谓词，**不是自造签名**"，而它点出的混淆（ADI-014 被读成"不做 attestation"）
值得记下来：ADR-014 拒绝的是**给不可信自述加签名**与**发明密钥体系**，
它明确留下一条缝——"出现跨生态标准时，实现该标准"。
本版就是走那条缝：**输出标准信封，不输出信任**。信任留给用户的工具。

### 5.2 确定性可以覆盖规范里的一条"should"

SLSA 建议 `invocationId` 唯一（UUID 是常见做法）。本版有意用输入哈希，
换来的是一条更强的性质：**同一份 lock 导出同一份语句**，于是
"我本地算的"与"CI 里签的"可以逐字节比对，签名前的 diff 也有意义。
代价是"一次运行"的身份不再由语句表达——那正好是签名者的位置（时间戳/身份）。
**规范的建议不是不可以偏离，但必须写清换到了什么。**

### 5.3 加命令的边际成本已经变成"登记"，而那四问都值得回答

v0.69 为 `sbom` 交过一次四张网的学费，本版照方抓药：矩阵、退出码账本、
码来源登记、文档。四处登记加起来大约占本版工作量的一半——
但逐条看下去（它在矩阵里吗 / 码有实测吗 / 出口登记了吗 / 用户看得到吗），
**没有一条是形式主义**：它们正是"命令半吊子存在"的四种形态。

## 补记：提交与 tag 的拆分（2026-10-09）

v0.66–v0.70 这一批工作在**一次连续会话**里完成，交付时才补记提交与 tag
（`scripts/check-release-status.sh` 判定 v0.66–v0.69 MISSING TAG 是这件事的直接动因）。
拆分原则与验证记录在此，供后来者核对：

- **文件按"它包含的最早版本"归属**：跨版本共享的 5 个产品文件
  （`internal/git/tree.go` · `internal/vendor/content.go` · `internal/resolve/graph.go` ·
  `cmd/ngm/install.go` · `cmd/ngm/update.go`）与登记类文件（命令表 / 用法文本 / 四张契约网 /
  help golden / cli.md）按版本手工回退与推进，使**每个 tag 的树都能编译、并通过该版自己的测试**；
- v0.67 的 README"为什么你应该用"一节随本版的文档批次一并提交（各提交说明里已注明）；
- 每个 tag 的验证：worktree 构建 + 该版测试子集 + `check-release-status.sh` 全绿；
- 教训与 v0.71 候选 1 同源：**"每次交付立刻提交并打 tag"应当是流程的一部分**，
  而不是事后靠脚本把一批工作切回五个版本——这次靠的是文本替换脚本 + 逐文件 numstat 对账，
  能做，但成本远高于当时随手 `git commit`。
