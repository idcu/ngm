# v0.10 实施计划 — 把检查推到最外圈

> 范围来源：[v0.9 复盘 §7](./v0.9-retrospective.md)（候选 6）与两处收尾时发现的空白。
>
> 性质：**不新增能力**。v0.9 让 store 的读数说了真话；这一版补的是两个**没人看的角落**——
> 最外圈的文档（根 README）与用户真会遇到的一种失败（store 不完整）。

---

## 任务组

```
A store 不完整：把两条承诺钉进测试
B 检查边界：根 README 的链接与锚点
```

| 组 | 内容 | 为什么是它 |
|----|------|-----------|
| A | "store 里少了一个 blob"时的报错与残骸行为 | `ngm install` 会因为 `Has` 为真而短路，失败发生在落地那一刻；这条路径此前**没有任何测试** |
| B | `README.md` 的链接存在性与锚点 | 它是最多人读的一份文档，却不在任何检查范围内（`docs/` 之外全无覆盖） |

## A — store 不完整（清单在、blob 没了）

用户会遇到的情形：手工清理过 `~/.ngm/content`、磁盘坏了、别的工具动过 store。
这时 `Has(digest)` 仍为真（清单在），于是 `install` **短路**，失败推迟到落地那一刻。

- [x] A1 报错**点名缺的是哪个条目**，并给出出路（`re-run ngm install`）。
      断言的是**用户看到的那几行**（`errs.FormatHuman`），不是 `err.Error()`——
      `NgmError.Error()` 按设计只给 message + cause，hint 由呈现层渲染
      （[errs.go](../../internal/errs/errs.go)）。CLI 在 `main.go` 里走 `FormatHuman`，已核对。
- [x] A2 读路径（`ReadFile`，供 `ngm mappings` 等消费方）同样给出路。
- [x] A3 失败**留下的残骸必须能被 `verify` 认出来是不完整的**——
      也就是不许"看起来通过"。

      > 计划里原本写的是"失败不留半棵树"。**实现时发现那不是契约**：
      `Materialize` 先清空目标再重建，重建中途失败时已落地的文件会留下
      （`links.go` 只承诺"下次重建前清空"）。于是断言改成两件**代码真承诺**的事：
      残骸可被 verify 认出 + 恢复后再落地会先清空。

- [x] A4 反向断言：不许把"blob 缺失"说成"清单不可读"（那是另一类故障，
      出路也不同）。

**验收**：`TestV10MissingBlobIsReportedWithAWayOut` 与 `TestV10MissingBlobResidueIsDetectable`。
两条都在实现**未改动**的情况下通过——它们钉的是既有承诺，不是新功能。

## B — 检查边界：根 README

- [x] B1 `scripts/check-docs-links.sh` 改为接受**多个根**（目录递归、文件直取），
      默认 `docs README.md`。
- [x] B2 **显式点名的根不存在 = 调用方写错了**（`BROKEN ROOT`，计入失败），
      而不是静默跳过——静默跳过正是本项目反复吃亏的"看起来通过"。
      默认根缺失时保留旧的 `skipping` 行为（CI 里 `docs/` 一定在）。
- [x] B3 锚点检查（`cmd/ngm/docs_anchors_test.go`）同样把根 README 纳入，
      并把路径空间改成**相对仓库根**（这之前是 docs 相对）。
- [x] B4 CI 的调用显式写出两个根（`docs README.md`），让范围可见。
- [x] B5 `.ps1`（Windows 入口）默认也传两个根。

**验收**：53 个锚点（含根 README）全验；两条检查都做过**双向牙齿测试**——
在 README 里种一个坏链与一个死锚点，两边分别报出，且**报的是正确的文件**
（见下）。

## 落地时发现的一处缺陷（B3 的副作用）

把路径空间改成相对仓库根之后，`describe()` 里**硬编码的 `"docs/"` 前缀**没跟着改：
失败信息会声称问题在 `docs/README.md`，而实际在根 `README.md`——
**报错指错文件，等于让人去翻错地方**。

它是被 B 的牙齿测试逼出来的（测试把坏链接种在根 README，输出却写着 `docs/README.md`）。
已修，并在那里留了注释说明为什么现在"原样打印"。

## 本版明确不做

| 方向 | 为什么不是现在 |
|------|---------------|
| workflow 的 YAML 有效性门禁 | 改坏 `release.yml` 会**静默不跑**（没有 run 就没有失败可读），值得一条门禁；但**判据还没确认**（`js-yaml` 要引入依赖、GitHub 对坏文件的呈现未验证）——先记着，不造会说谎的仪器 |
| 锚点检查扩到更多文件 | 已覆盖全部 `docs/**` + 根 README；仓库里没有别的 `.md` |
| `remote` 门槛 b / `symlink` 模式 / blob 回收 | 都需要**决策**，不在本版 |
