## 1. 逐组验收

### 1.1 A 组 — "缺引擎时报错要列出候选"：**已经成立**

实测（本机真跑 `ngm`）：

| 调用 | 退出码与措辞 |
|------|------------|
| `ngm typecheck` | `3` · `ConfigInvalid: no engine configured for \`typeCheck\`` · hint: `pass --engine=<name>, or set engines.typeCheck in ngm.json (available: self, typescript)` |
| `ngm typedecl` | `3` · hint: 同上（`typeDecl`） |
| `ngm css a.css` | `3` · hint: `… (available: postcss, self)` |

**报错已经把候选列出来了**，也指向了 `ngm.engines.json`。所以那一条"待决"是**空**的。

顺带量到一处形状差异：目录里**同名多 kind**（`esbuild` 同时是 bundler 与 transform、`typescript` 同时是 typeCheck 与 typeDecl）——这也是 `engines info` 返回**数组**的原因。

三条同类事实（目录不存在 / 没有 `ngm.json` / `ngm.json` 损坏），
**21 个命令全部 exit 3**，并且报错里点名了是哪个路径。

## 5. 过程洞察

### 5.1 "待决"清单会自己变脏

两条候选都挂了不止一版，都是"听起来很合理"。
本版先量，两条都**不成立**。
**一条候选只有被测量过才算数**；没被测量的候选，会一直待在清单里假装是工作。

### 5.2 脚手架编译不过时，别硬塞

这张网最后没落地。处置是：删掉脚手架、保住绿色的树、在复盘里写"未达成"。
**"我写了个网"不是交付，"它能编译并通过"才是。**

### 5.3 探针的夹具会被前面的探针改掉

第一版配置错误探针把 `add` 跑在共享目录上，于是后面的 `remove` 合法地退 0。
与 v0.16 那次"篡改掩盖漂移"是同一个坑：**状态耦合会让读数说谎**。
处置是每个命令都用独立目录。
