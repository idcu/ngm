# v0.21 计划 — 声明的退出码必须可核对

> 范围来源：[v0.20 复盘](./v0.20-retrospective.md) §7 候选 1（上一版的脚手架卡在编译上，这一版收口）。
>
> 一句话目标：v0.19 给 9 个命令写下 `EXIT CODES` 段，那是**声明**，不是证据。
> 这一版让"每条声明都被一条命令盯着"变成门禁。

---

## 0. 为什么有这一版

v0.20 的侦察把两条待决候选都**证伪**了（报错已列候选；配置错误已一致），
也留下一条真正待办的：v0.19 新写的 9 段 `EXIT CODES` **没有任何东西核对**。
上一版的脚手架编译没过，这一版先让它编译，再让它有牙齿。

## 1. A 组 — 用法文本里的 `EXIT CODES` 段必须**格式正确**

每个命令的用法文本都必须有这一段，且：
至少声明一个码；每个码 ∈ **0…5**；同一个码不出现两次；每个码都带一句说明。

判据来源是**运行时的命令表**（`root.go` 的 `commands`），不是另抄一份清单。

## 2. B 组 — 每条声明都要有**能离线触发它的命令**，且实测一致

触发命令一律离线：只看本地 mirror / vendor / lock，或故意给"声明了但没装"的引擎名。
凡需要真实网络或真实引擎的码，不进这张表（进了就是一张会自己变红的网）。

## 3. C 组 — 缺口名单自己会过期

没被测量的声明进入 `exitCodeGaps`，并断言**该命令确实还声明着这个码**。
哪天那段声明被删改，对应条目就会红，逼着人一起删掉。

## 4. 明确不做

| 不做的 | 理由 |
|--------|------|
| 穷举每个命令的**全部**状态 | 那是数据流分析，不是一张网能做的事 |
| 用真实网络去覆盖 1 / 2 / 4 | 违反"网必须确定性、离线"这条纪律 |
| 改 `cache` / `store` 的 `--dir` | 它们操作的是全局层，与项目目录无关 |
