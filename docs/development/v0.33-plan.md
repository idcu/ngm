# v0.33 计划 — 建议要**指名道姓**

> 范围来源：[v0.32 复盘](./v0.32-retrospective.md) §7 候选 1（"让行动行也检查质量"）。
>
> 一句话目标：v0.32 断言"每一条失败项都配了一行 `→ …` / `Fixed in: …`"——
> 但那只**数条数**，于是一行 `→ 出错了` 也能过。这一版给那一行加一条内容判据：
> **它必须点名一个用户能照着做的东西。**

---

## 0. 判据：三种锚点，且**每一种都要能被核对**

| 锚点 | 长什么样 | 怎么核对 |
|------|---------|---------|
| **命令** | `` `ngm audit` `` | 子命令必须**真的在命令表里** |
| **配置键** | `supplyChain.osvIgnoreSeverities` | **逐段**都必须在 schema 源码里找得到 |
| **修复版本** | `Fixed in: 1.2.4` | 一个可对比的版本号 |

三类可核对的对象都来自**运行时/源码**，不是测试里抄的常数：

- 命令表：`commands`（21 个命令）
- 配置键：`collectSchemaKeys(repoRoot(t))`（48 个键，来自 `internal/config/config.go` 等三份 schema）

## 1. 为什么 ①② 值得核对

**一个指错地方的指引，比没有指引更糟**：没有指引用户还会去查，指错了用户会照着做然后失败。

所以：

- 建议里写 `` `ngm audits` `` ⇒ 红（不是命令）
- 建议里写 `supplyChain.osvIgnoreSeveritiesX` ⇒ 锚点消失 ⇒ 红（这一行什么都没点名）

## 2. 判据的边界（刻意不做的）

- **不判断措辞好不好**——那是人读的事；
- **不要求三种锚点等量**——只要求三种**都还有样本**（一种整块消失 ⇒ 红）。
