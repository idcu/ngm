## A — wasm / remote adapter

- [ ] `wasm` adapter：宿主运行时（wasmtime 等）选型评估后引入；沙箱内执行引擎，输入输出沿用 subprocess 协议语义
- [ ] `remote` adapter：自托管构建服务的协议定义（请求 / 产物 / 失败语义）、认证、超时与重试
- [ ] 两类 adapter 进入引擎清单与 `engines validate` 覆盖范围

**验收**：wasm 引擎可在无外部二进制的环境完成 transform；remote 端到端在本地 mock 服务上验证；失败路径退出码与 Hint 明确。

---

## B — 集成脚手架

- [ ] `ngm integrations add vite|esbuild|deno`：生成各工具配置片段（Vite `resolve.alias` / esbuild `alias` / Deno import map）
- [ ] **一并生成 tsconfig `paths`**（解决 `github:` 前缀的类型解析，见 [build.md](../guides/build.md)）
- [ ] 生成策略：不覆盖已有配置，冲突时报错并给出 diff 提示
- [ ] Webpack 集成（`resolve.alias`）
- [ ] `ngm integrations` 命令进入 CLI 参考与 help

**验收**：在样例 Vite / esbuild / Deno / Webpack 项目上，脚手架生成后无需手工修改即可消费 mappings；冲突场景报错可操作。

---

## C — Deno sandbox

- [ ] `ngm verify --sandbox`：core Go 决策 + Deno 沙箱执行具体校验脚本；权限按 [安全模型](../architecture/security-model.md) 的 default-deny 映射
- [ ] 未安装 Deno → exit 5 并提示，**不得静默降级**
- [ ] 沙箱内可执行：依赖自带 `verify.js`（若提供）、自述文件签名检查、用户自定义 audit hook

**验收**：沙箱内禁止访问 `~/.ssh` / `~/.git-credentials` / 网络（除非白名单）的用例；无 Deno 环境的行为测试；`--sandbox` 与默认 verify 的结果一致性（对象相同、权限不同）。

---

## D — 权限与凭证

- [ ] `~/.ngm/config.json` 的 `permissions`：命名空间（`read:` / `write:` / `net:` / `run:` / `env:`）解析与执行（对齐 [configuration](../guides/configuration.md) 示例）
- [ ] 凭证纪律落地审计：ngm 输出、日志、lock 中不得出现 token（自动化断言）
- [ ] 权限违例的错误码与 Hint（指向具体配置键）

**验收**：权限矩阵测试（允许 / 需配置 / 默认禁止三档）；凭证泄露自动化检查纳入 CI。

---

## E — mappings v2（monorepo）

- [ ] 协议扩展：monorepo 子路径依赖的映射（`path` 字段与 `to` 的关系）、多入口场景
- [ ] `mappings validate` 覆盖 v2 校验；向后兼容 v1（读取旧文件）
- [ ] 协议版本策略：遵循 [schema 版本策略](../guides/configuration.md)（minor 兼容 / major 迁移）

**验收**：v1 文件在新工具下可用；monorepo fixture（两子包互相引用）映射正确；类型解析（tsconfig paths）在 monorepo 下通过。
