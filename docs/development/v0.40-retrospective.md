# v0.40 复盘 — **参数怎么写**

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：这一版枚举"参数**怎么写**"（顺序 / 重复 / `--`），
> 并**抓到一处真实产品缺陷**：`normalizeArgs` 把 `--` 之后的 token 正确归为 positional，
> 但**重排时把 `--` 丢了**——于是它们又回到 flag 位置，被 `flag.Parse` 当成 flag 解析。
> 实测 **9 个命令**受影响，与函数自己开头写的那句承诺正好相反。

---

## 1. 逐组验收

### 1.1 三族 ✅

| 族 | 读数 |
|----|------|
| **顺序**：`--dir` 在前 / 在后 | **19/19** 输出逐字节相同（归一化后） |
| **重复**：`--dir=<坏> --dir=<好>` 与反向 | **16/16 通过**，**3 个公开跳过**（好/坏目录对它们给出同一份结果 ⇒ 那一族没有牙齿） |
| **`--`**：`--dir=<好> -- --dir=<坏>` | **19/19** 坏目录未生效 |

覆盖：**19 个命令**（21 减去 2 个全局命令——它们不接受 `--dir`，这三族对它们无从谈起）。耗时 1.5 秒。

### 1.2 产品缺陷（本版修掉）✅

```
$ ngm verify --dir=<好项目> -- --dir=<不存在的目录>
修复前：ConfigInvalid: ngm.json not found at <不存在的目录>\ngm.json   ← 那个 flag 生效了
修复后：它在 positional 的位置上被看见（本项目的命令各自有自己的说法）
```

**根因**：`normalizeArgs` 的分类是**对的**（`afterDoubleDash` 之后一律进 `positional`），
但函数末尾 `return append(flags, positional...)` **把这个信息丢了**——
`--dir=<坏>` 被原样放到列表末尾，而 `flag.Parse` 的规则是"遇到第一个非 flag 才停"，于是它又被当成 flag。

**修法**：在它们前面**重新插入一个 `--`**（`flags ++ positional ++ ["--"] ++ rest`），让 `flag.Parse` 在那里停下。
`--` 自身会被它吃掉，下游看不到任何变化。

### 1.3 一处**把缺陷固化下来**的既有测试 ⚠️→✅

`cmd/ngm/root_test.go` 里有一条：

```go
{
    name: "double dash terminates flag scanning",
    in:   []string{"--dir=x", "--", "--not-a-flag"},
    want: []string{"--dir=x", "--not-a-flag"},   // ← 这个期望**就是缺陷本身**
},
```

它要求 `--` 被丢掉——而那正是让 token 回到 flag 位置的原因。
修产品时它必然变红；处置是**改期望并写明为什么**（而不是让它挡住修复）。

### 1.4 牙齿 ✅

| 探针 | 结果 |
|------|------|
| **忠实**退回修复（把 `--` 之后的 token 原样放回去） | **9 个命令**精确命中：`-- 之后的 --dir= 被当成了 flag——root.go 承诺的是「-- 之后一律视为 positional」` |
| **不忠实**的退回（我第一版：把那些 token **丢掉**） | 那是**第三种行为**，只命中 2 个（另一条断言）——见 §5.3 |

## 3. 设计偏离登记

| # | 计划写的 | 实际做的 | 为什么 |
|---|---------|---------|-------|
| 1 | 重复 `--dir` 用"退出码相等"判 | 改成**与单 flag 那次运行逐字节比对** | 退出码在若干命令上**区分不开**（`remove` 在两种目录下都退 3），而输出能区分 |
| 2 | 用"输出里出现过坏目录"当判别式 | 换成两种**不会说谎**的证据（文件系统痕迹 / "目录+分隔符"） | 见 §5.1 |
| 3 | 每一族共用一对目录 | 每次运行都用**全新**目录 | 见 §5.2 |

## 5. 过程洞察

### 5.1 分类对了，**传递丢了**——承诺与实现之间差的就是这一步

`normalizeArgs` 的实现里，`afterDoubleDash` 的判断**完全正确**：
`--` 之后的 token 一律进 `positional`。问题出在最后一行：

```go
return append(flags, positional...)   // ← 分类结果还在，但"它是 positional"这件事没了
```

下游 `flag.Parse` 只看到一串 token，于是按自己的规则又把 `--dir=<坏>` 认成了 flag。

这一族缺陷的形状是：**中间层知道的信息，在传递时被压成了"看起来等价"的形式**，
而下游按**别的规则**重新解释它。修法的本质不是"再判一次"，而是**把那个标记还回去**。

### 5.2 既有测试可能**把缺陷固化下来**

`root_test.go` 那条 `want` 就是缺陷本身。这不是第一次遇到"测试守旧行为"，
但这一版它值得单独记：**修产品时必须同时问一句"有没有测试在守旧行为"**——
否则你会看到一片红，而其中至少一条红的**来源是产品缺陷被写成了期望**。

处置不是"删掉那条测试"，而是**改期望 + 写下为什么**（改完之后它反而成了这条修复的证据）。

### 5.3 又一次"探针没造出它自称的状态"（第五次）

牙齿第一版我想"退回修复"，写成了：

```go
return append(flags, positional...)   // 把 rest 丢了
```

那不是修复前的行为，是**第三种行为**（token 消失）。它只命中 2 个命令，
而我差点据此记成"修复只影响 2 个地方"。

忠实版本是 `append(append(flags, positional...), rest...)` —— 命中 **9 个**。
两次都跑得出来，区别只在于我有没有把 `rest` 放回去。

同一族教训到这一版已是**第五次**（v0.31 删了个不存在的路径 · v0.34 只改了一半消息 ·
v0.35 的死赋值探针 · v0.39 改错了地方 · 这次丢了一半）。每次的发现方式都一样：
**牙齿没咬住时，先怀疑牙齿，再怀疑网。**

### 5.4 判据的判别式要选**不会说谎**的证据

"坏目录生效了"这件事，第一版用"输出里出现过 <坏>"来判——于是把三个**做对了**的命令
（`why` / `engines` / `init`）报成了缺陷：它们把那个 token 当成 positional，
并且在错误信息里**把它回显了出来**。

改成两种证据之后才稳：

- **文件系统痕迹**（创建型命令会在那个目录里留下东西）；
- **输出把它当目录**（`<坏>` 后面**跟着分隔符**）。

前者的启示更大：**当"行为"可以用"副作用"表达时，就别用"文本里出现过什么"**——
文本会被回显，副作用不会。

### 5.5 夹具的状态耦合，这一版踩了两次

`init` 的第一次运行会把坏目录**建出来**，`add` 的第一次会把依赖**加进去**——
于是第二次运行看到的是 `created → already exists`、`added → updated`，
两边的输出当然不同，而**产品完全正确**。

这是同一族的第五、六次（v0.16 · v0.21 · v0.31 · v0.39 前两处 · 本版两次）。
处置固定成一条纪律：**每一次运行都用全新的目录**，并把"每个命令每条路径"都做成独立夹具。
