# v0.33 复盘 — 建议要**指名道姓**

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：v0.32 给"每一条失败项"配了一行"接下来做什么"，但只**数条数**——
> 一行 `→ 出错了` 也能过。这一版把那条判据抬到**内容**：**建议必须点名一个真能执行的东西**，
> 而且那个东西**要被核对是真的**。**产品代码 0 行改动**——
> 但过程中两次"红"都不是产品的问题，而是**我的检查**（见 §5.1）与**我的探针**（见 §5.3）。

## 5. 过程洞察

### 5.1 又一次"红的不是产品，是我的检查"

判据第一遍跑，报的是：

```
this next-step line names nothing a user can act on
next-step lines: 7 inspected, anchors: map[command:5 version:1]
no next-step line used a **config** anchor
```

指向的那一行是：

```
→ no fixed version is recorded for this advisory: read https://osv.dev/vulnerability/GHSA-1,
  or record the acceptance via supplyChain.osvIgnoreSeverities in ngm.json
```

**它明明点名了一个真的配置键。** 根因是我的检查：键表里存的是**单个键名**
（`supplyChain`、`osvIgnoreSeverities` 各一条），而建议里写的是**点分路径**，
我拿整串去查表——查不到。

修法：逐段核对（每一段都要是真键）。

这是**第三次**同族事故：

| 版本 | 形态 | 谁错了 |
|------|------|-------|
| v0.31 | 删的路径不存在 | 我的假设 |
| v0.32 | 失败项不在行首 | 我的正则 |
| **v0.33** | 点分路径 vs 单个键名 | **我的查表方式** |
| **v0.33** | 共享正则改成取整行，把**上一版**的守卫的键全改了 | **我的改动** |

三次都是：**判据红了 → 先怀疑产品 → 最后发现是我的判据**。
这条经验已经值一版：**判据红了的第一件事，是确认判据本身能对。**

第四例值得单独说，因为它是**上一版**的网被这一版的改动弄红的：

`reActionLine` 是 v0.32 与 v0.33 **共用**的。v0.33 要读行动行的内容，
把它从"匹配行首记号"改成"匹配整行"。v0.32 的守卫原本拿匹配到的文本当键统计约定
（`→` / `Fixed in:`），现在键变成了整行文本——于是它报
*"两种约定都没有走到"*，而实际上 7 行都在。

修法是把约定记号**显式抽出来**（`actionKind`），不再依赖"正则刚好匹配了多少"。
教训：**改一个共用的辅助设施，要回去看还有谁在用它的哪一种含义。**

而抓到它的不是 `go test -run TestV33`（那是绿的），是 **`go test ./...`**——
v0.28 定下的那条纪律（整套跑，不手挑）在这一版**又一次直接兑现**。

### 5.2 核对的对象必须来自**运行时/源码**，不能是测试里抄的常数

这一版最值的地方不是"三种锚点"这个分类，而是 **①② 可以被核对**：

- `` `ngm audits` `` ⇒ 拿去问运行时的**命令表** ⇒ 不存在 ⇒ 红；
- `supplyChain.osvIgnoreSeveritiesX` ⇒ 拿去问 schema **源码** ⇒ 不存在 ⇒ 红。

如果我把"合法命令清单"抄进测试里，那么**命令改名之后测试还是绿的**——
它核对的是我抄的那份记忆，不是产品。这与 v0.20 的"凡是能复读的数字都该绑一条命令"是同一条。

### 5.3 我的探针**没造出它自称的状态**——而网是对的

牙齿 C 第一次我做的替换是：

```
"  → no fixed version is recorded for this advisory: " +     ← 只改了这半句
"read https://osv.dev/vulnerability/%s, or record the acceptance " +
"via supplyChain.osvIgnoreSeverities in ngm.json\n"           ← 这半句还在
```

改成 `→ something went wrong with this advisory:` 之后，**配置键还在后半句里**——
于是网**正确地放行**了（那一行确实还点名了一个真键）。

我当时的反应是"牙齿没咬住"，差点把它记成网的问题。**真相是我的探针没造出它说的那个状态**——
而 v0.31 的网里恰恰有一条断言专管这件事：
*"a fixture no longer builds the state it names"*。

手工探针没有那条断言护着，所以我在**自己身上**又踩了一遍。
把它写下来是因为：**那条断言值得，而且它值得的范围超出网本身。**

### 5.4 判据点名了"有东西"，判不出"东西对不对"

这是这一版**真正的边界**，必须写在明处：

一行 `→ run \`ngm install\`` 即使与失败毫无关系，也能过这张网。
判据能保证的只有两件事：**有下一步**、**下一步点名的东西真实存在**。
"那一步是不是**这一步该做的事**"——只有人能判。

所以这一版给出的不是"建议写得好"的证明，而是**"建议没有空转"的下限**。
下一版若想再抬，得先找到能机械化的那部分（例如：建议里的命令**是否承认这次失败的类型**）。
