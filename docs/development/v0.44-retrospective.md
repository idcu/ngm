## 1. 逐组验收

### 1.1 那条分支终于被走到了 ✅

```
$ ngm verify --offline          # 锁钉了一个本机 mirror 没有的 commit（上游又提交了，而我离线）

✗ github:x/dep@v1 (tag) → 41065fe (now …) [stale] — check incomplete
    ref: tag v1 was moved: ngm.lock pins … but it now points at …
    digest: commit … from ngm.lock is not present in the local mirror
    error: commit … from ngm.lock is not present in the local mirror
  → driftKind: unexpected; the local mirror is cold; run once without --offline (or `ngm install`) to warm it

verified 1 dependency(ies): 1 incomplete (exit 4)
note: --offline — refs were compared against the local mirror snapshot (stale)
```

**那句建议正是 v0.35 那行"死赋值"写下的**（`the local mirror is cold; run once without --offline …`）✓
——也就是说，**"算好了又丢掉"的那一处，现在既不再丢、也确实送得到**。

### 1.2 顺带量到一件更有价值的事：那句话**真的能分辨**

同一份锁、同一个世界，**去掉 `--offline`** 再跑一次：

```
✗ … — unexpected drift
    digest: commit … is not present in the local mirror; the refreshed mirror no longer
            contains it, so the upstream discarded that commit
  → driftKind: unexpected; confirm the change with the upstream owner, then run
    `ngm update github:x/dep`; if nobody moved it, the upstream repository may be compromised
```

**在线跑一次之后，结论变了**（"镜像里没有" → "上游丢弃了它"）——

于是离线那句建议（"run once without `--offline`"）不是敷衍：**它是分辨率最低的那一步，
而这一步正是把两种情形分开的唯一办法**（ADR-010 的设计）。

## 5. 过程洞察

### 5.1 "未证明"会一直挂在候选里——直到有人真的去造那个状态

这条缺口从 **v0.35** 记到 **v0.44**（九版）。每一版的候选表里都有它，每一版都没做——
因为它**不像缺陷**（没有用户投诉、没有红），只是"我这里没证据"。

而做它花的成本：**一次探针**。

> **"没有证据"和"没有缺陷"在候选表里长得一样**，区别只在有没有人去造那个状态。
> 这一条值得写进方法：**候选表里的"未证明"要标出代价**——
> 如果造状态的代价是一次探针，它就不该挂九版。

### 5.2 触发条件是**从代码读出来的**，不是猜的

我先读了 `verifyOne` 的分支结构，读出三个条件，其中关键的一条是：

```go
if refCheck.Operational {
    res.Err = refCheck.Detail
} else {
    digestCheck, derr := checkDigest(...)   // ← 漂移也算"非操作性"，所以这里会继续
```

**"漂移也算"**这一点让构造从"造一个畸形镜像"（ref 指向缺失对象）降级成
"锁钉一个本机没有的 commit"——后者只要**上游再提交一次**。

先读结构、再设计夹具，比先想夹具、再撞运气便宜得多。

### 5.3 用**真实存在**的 commit，而不是假 SHA

假 SHA 同样能触发分支，但它把两件事混在一起：**镜像没取过** 与 **上游丢了它**。
用真 SHA 之后，同一份世界在线跑一次就能看到结论**从前者变成后者**——
于是"那条建议到底有没有用"这个问题**当场有了答案**（§1.2）。

> **夹具的每一个"假"都会在读数里留下说不清的余量。**

### 5.4 判据的"两两"结构：别让它在规模变化时静默降级

v0.35 的断言原来是：

```go
if len(advice) == 2 { … 两句不相同 … }
```

成因涨到三种之后，这段代码**照样绿**——它只查了前两句 ✗。
改成两两核对（用 map 找重复）之后，"三种都不同"才是真的被断言了。

这与 v0.30 的"两类样本缺一即红"、v0.36 的"扫描必须真的扫到东西"同源：
**判据要能察觉自己的范围在规模变化时缩了。**
