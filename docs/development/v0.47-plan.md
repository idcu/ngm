# v0.47 计划 — **两 token 的写法**

> 范围来源：v0.46 候选第 1 条。它是参数维度最后一块：
> v0.41 / v0.42 管的是"**一个 token 里**的写法"（`--dir=` 的空值语义），
> 这一版问**两种 token 数**。
>
> 一句话目标：`--flag ""`（两个 token）与 `--flag=`（一个 token）必须是一回事；
> 而布尔 flag 后面那个空 token 是**位置参数**，不许被当成噪声滤掉。

---

## 0. 起点：先量，不先改

| 侧 | 问题 | 待测 |
|----|------|------|
| 取值 flag | `--flag ""` ≡ `--flag=`？ | 37 条（`valueFlagPairs`） |
| 布尔 flag | `--flag ""` 与 `--flag ZZ-JUNK` 同处置？ | 42 对（两张布尔网） |

## 1. 判据

```go
取值：run(`--flag=`) 与 run(`--flag`, "")  必须**逐字节相同**
布尔：run(`--flag`, "") 与 run(`--flag`, "ZZ-JUNK")  必须**同退出码**
```

第二条的**理由**（也是它的写法）：两者都是"布尔 flag 后面跟一个位置参数"，
唯一区别是那个 token 的内容——**空 token 不该被滤掉**。

> 探针的第一版判据是"`--flag ""` 必须**不等于**只给 `--flag`"，
> 结果一堆命令被判红——而红的不是产品：那些命令的 base 运行**本来就失败**
> （`verify` 在没有锁的项目里退 3）。**"与基准相同"在基准失败时什么也证明不了。**
