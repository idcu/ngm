# v0.7 实施计划 — 让 store 的占用可见、残骸可回收

> 范围以 [internals/roadmap.md](../internals/roadmap.md) 为唯一事实源。前置：
> [ADR-018](../adr/adr-018-store-reclaim.md)（**本版范围就是它决策 2 的实现**）与
> [v0.6 复盘](./v0.6-retrospective.md) §7（候选池）。
>
> 性质：v0.7 **不做大改**（层 2 的写入侧去重单列一版），只补两个**低风险、
> 且没有"删除真实数据"路径**的工具，让"磁盘到底被什么占了"第一次可以被回答。
>
> 背景：v0.6 量出层 2 **只增不减**、每个 commit 复制一整棵树（源码真实增量的 **20×**），
> 而 ADR-018 裁定**不做**按可达性自动删除的 GC。于是剩下的可做的事只有这两件。

---

## 任务组

```
A ngm store usage（只读报告）
B ngm store prune（只清解包残骸，带 --dry-run）
```

| 组 | 内容 | 关键参考 |
|----|------|---------|
| A | store 占用的只读报告 | [ADR-018 决策 2](../adr/adr-018-store-reclaim.md) · [vendor 层模型](../architecture/vendor-layers.md) |
| B | 只清 `Put` 的解包残骸 | 同上；`internal/vendor/content.go` 的 `Put`（`.unpack-*` 临时目录） |

---

## A — `ngm store usage`（只读）

- [x] A1 报告内容：store 根路径、**digest 数**、**合计字节**、逐 digest 的体积与
      它来自哪个 repo / commit（读 `meta.json`；读不出来就如实标"meta 不可读"，
      **不猜**）。
- [x] A2 排序必须**确定**：体积降序、同体积按 digest 升序。输出要可 diff、可快照——
      依赖调度顺序的输出会让人以为"内容变了"。
- [x] A3 解包残骸（`.unpack-*`）**单列一行**：它是中断留下的垃圾，数量不为 0 时
      顺带提示"可以用 `ngm store prune` 清掉"。
- [x] A4 **只读**：不创建、不修改、不删除任何东西。断言方式：`usage` 前后 store 的
      字节数不变（`TestContentStore_UsageReportsWhatTheStoreHolds`）。

**验收**：有验收测试（含 A2 的确定性与 A4 的只读性）；store 不存在时明确说"nothing to report"
且 `exit 0`（没有东西可报告不是错误）。

---

## B — `ngm store prune`（只清残骸）

- [x] B1 **只删** `sha256/.unpack-*`（`Put` 解包用的临时目录名）。**绝不碰任何
      `sha256/<digest>/`**——那是一条写死的边界，不是"看起来没用就删"。
      前缀收成常量 `unpackPrefix`，`Put` 与 `Prune` 共用一处定义。
- [x] B2 `--dry-run` 可用：破坏性操作先看清楚（本项目对删除类命令的一贯要求）。
- [x] B3 报告删了哪些、**释放多少字节**，以及**"留下了 N 份内容树没动"**——
      后一句是安全声明，让用户不必去猜"它是不是顺手删了别的东西"。
- [x] B4 幂等：没有残骸时 0 删除、`exit 0`（不报错）。

**验收**：断言 digest 目录一个不少；`--dry-run` 一个都不删；再跑一次幂等。

---

## 总验收

- [x] `ngm store usage` 只读且输出确定
- [x] `ngm store prune` 只清残骸、`--dry-run` 可用、幂等，且**没有任何代码路径删除真实内容树**
- [x] 文档同步：命令参考、help 快照、ADR-018、路线图与总览
- [x] CI 验收组纳入新用例（`TestV07StoreAcceptance`）

**落地时新增的一个测试**：`internal/vendor/content_maintain_test.go` 里有一条
"长得像残骸但前缀不对的目录必须被留下"——因为"按名字前缀判断"这种规则，
一旦两边写法不一致，后果就是删错东西（前缀已收成 `unpackPrefix` 常量）。

---

## 本版明确不做（避免范围蔓延）

| 方向 | 为什么不是现在 |
|------|---------------|
| 层 2 **写入侧去重**（blob 池 + 树清单） | **schema 与迁移方案已出**：[ADR-019](../adr/adr-019-content-addressed-blobs.md)；实现**单列一个版本**——它要动 `Put` / 读路径 / `LinkTree` / `verify` 层 2，与本版是两个量级的改动 |
| 任何按可达性删除真实内容树的代码 | ADR-018 决策 1/5：那需要一个 ngm 没有的项目注册表 |
| `remote` adapter 门槛 b、3s 目标重定义、`deno bundle` | 见 v0.7 候选池；本版不排（前两项需要决策/凭据，最后一项等上游） |
