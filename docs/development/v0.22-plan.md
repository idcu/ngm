# v0.22 计划 — 把"已知缺口"压下去

> 范围来源：[v0.21 复盘](./v0.21-retrospective.md) §7 候选 1。
>
> 一句话目标：v0.21 把 70 对（命令, 退出码）声明分成"44 条实测 + 26 条已知缺口"。
> 这一版把缺口表**尽量清空**——每条缺口要么变成可跑的实测，要么带着**实测记录**说明为什么测不到。

---

## 0. 为什么有这一版

v0.21 的网立起来后，缺口名单里躺着 26 条"我知道这里还没人盯着"。
名单本身不会干活，它只会一直待在纸上。这一版逐条处理：

| 缺口 | 触发它需要什么 |
|------|--------------|
| `typecheck` / `typedecl` / `build` / `transform` / `css` 的 0 与 1 | 一个**真能跑**的引擎（成功与失败各一次） |
| `verify` 的 1 / 2 / 4 / 5 | 漂移夹具 / 篡改夹具 / 冷 mirror / 缺 Deno |
| `install` 的 1 / 2 / 5 | verifyOnLock + 漂移 / 篡改 / 缺 Deno |
| `update` 的 1 / 2 / 5 | 同上 |
| `audit` 的 1 / 5 · `tree` 的 1 | 本地 OSV 替身（有发现）+ 缺 Deno |
| `mappings` / `integrations` 的 0 | 一个合法的 `ngm.mappings.json` |

## 1. A 组 — 引擎类 10 对（假引擎）

用仓库已有的 `internal/adapter/testdata/fakeengine`：`FAKE_EXIT` 控制成功/失败，
五个 kind（typeCheck / typeDecl / bundle / transform / css）各测 0 与 1。

**关键细节**：`FAKE_EXIT` 必须**每个用例显式设一次**——它靠 `t.Setenv` 生效，
而 `t.Setenv` 是全局的，上一条用例设的 1 会污染下一条"预期 0"的用例。

## 2. B 组 — verify / install 的 1 · 2 · 4 · 5

| 码 | 夹具 |
|----|------|
| 1 | 上游把 tag 挪到新提交（非预期漂移）；`install` 再加 `verifyOnLock: true` |
| 2 | 把 lock 里的 `archiveDigest` 改成全零（形状合法、内容不可能匹配） |
| 4 | 装好之后**删掉本地 mirror**，再 `--offline` |
| 5 | 依赖自带 `verify.js` / `postinstall.js`，`--sandbox` 或 `allow` 且**没有 Deno** |

## 3. C 组 — audit / tree 的 1 · 4 · 5

- **1**：本地 OSV 替身返回一个 HIGH 发现；
- **4**：冷 mirror（同 B 组）；
- **5**：`--hook` 指向一个真实存在的脚本，但没有 Deno。

## 4. D 组 — mappings / integrations 的 0

`ngm install` 会**写出** `ngm.mappings.json`（`install.go`）。
因此这两个命令的 0 用 `setupDep`（装过的项目）就能触发。

## 5. 结构上的硬要求：清空 PATH 必须单独成测

`t.Setenv("PATH", …)` 是**全局且不可逆**的（到测试结束才还原），而夹具要用 git 建。
所以那几个"缺 Deno"的用例进不了主表，必须**各自成测**：
先建夹具 → 再清 PATH → 再断言。主网把它们记在 `exitCodeElsewhere` 里。
