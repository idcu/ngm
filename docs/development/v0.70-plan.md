# v0.70 计划 — **接一层谓词：attestation（不做签名）**

> 范围来源：[assessment-2026-10-09.md](../internals/assessment-2026-10-09.md) 第 3 层第二条：
>
> > **给 manifest 加 SLSA attestation**（不是自造签名，是接一层谓词）
> > → 把 ngm 从"L2 的一半"推到"内容侧的 L2"，且与 npm 的 L3 **互补而非竞争**。
>
> 一句话目标：**让"内容 ↔ commit ↔ 输入"这三个事实有一个标准信封，可以被别人签。**

---

## 0. 起点：缺的不是事实，是"可被签的形态"

v0.69 用 `ngm sbom` 交出了**清单**；第 3 层剩下的两条里，attestation 是唯一
还能在"只读 lock"这条纪律下做掉的（第三条 `verify --json` 成为"证据"缺消费方，
评估报告自己也说"在没有具体消费方之前设计它是猜"）。

- lock 里已有：commit（不可变锚点）、`archiveDigest`（内容绑定）、ref/refType（声明）；
- 缺的是：一个**跨生态的既定信封**，让这些事实能被 `cosign` 之类的标准工具签、
  被策略引擎按标准字段读；
- 而"签名"本身**不该由 ngm 做**：ADR-014 已经论证过——签名证明"谁说的"，
  不证明"说的是真的"，而"谁说的"只有用户的信任配置能回答。

## 1. 处置

| 项 | 决定 |
|----|------|
| 形态 | **单个** in-toto Statement v1，多 subject（全部依赖）；谓词 SLSA provenance v1 |
| subject | 每个依赖的 git purl + `archiveDigest` 的裸 hex；注解 `ngm/digest-scope` 写明**它是清单哈希、不是 tarball 哈希** |
| 输入 | `ngm.json` / `ngm.lock` 的**字节** sha256（不是你重新序列化后的形态） |
| materials | `git+https://…@<commit>` + `gitCommit` digest；注解 `ngm/declared-ref` 记下 `refType:ref` |
| 确定性 | **无时间戳**、`invocationId` = lock 的哈希（不是随机 UUID）；同一份 lock 两次导出字节相同 |
| 签名 | **不做**。给出 `cosign attest-blob` 的路径；CI 现场生成再签，签名者补上"何时/谁" |
| 登记 | 新命令照例进四张网（配置矩阵 / 退出码账本 / 码来源登记 / 文档） |

**先立 ADR**（[ADR-027](../adr/adr-027-attestation.md)）："签什么 / 谁签 / 验什么"三问逐条写死，
并说明它与 ADR-014 的边界（ADR-014 拒绝的是自造签名体系，不是标准谓词）。

## 2. 验收

```bash
go test -count=1 -run 'TestV70' -v ./internal/attest ./cmd/ngm
go test -count=1 ./...          # 新命令会被 23 命令 × 8 形状的矩阵自动纳入
```

**牙齿**：
- 打乱输入顺序 ⇒ 输出逐字节相同；两次导出 ⇒ 字节相同（**不需要**剔除时间戳——它不存在）；
- 去掉 subject 的 sha256、或把 `invocationId` 换成随机值 ⇒ 测试红；
- 缺输入（任一哈希/版本）⇒ 报错，而不是导出一份"看起来完整"的语句。
