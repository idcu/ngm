# v0.47 复盘 — **两 token 的写法**

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：参数维度最后一块量完了——**取值一侧 37 条全部等价（0 处不等价）**，
> **布尔一侧 42 对同处置**。过程中两个"红"都不是产品：
> 一个是我**判据选错了对照**，一个是**夹具又隔离出新路径**（本系列第五次）。
> 另外量到一条**判据边界**并把它写进了网：取值那一组对某类突变**不敏感**。
> **产品代码 0 行改动。**

---

## 1. 逐组验收

### 1.1 取值一侧：37 条全等价 ✅

```
two-token spellings: 37 value flag(s) {=, ""} equivalent · 42 bool flag(s) {"", ZZ-JUNK} same disposition
```

`--flag=`（一个 token）与 `--flag ""`（两个 token）在全部 37 条派生出的取值 flag 上
**退出码与输出逐字节相同**——包括 `--dir ""`（两者都被明确拒绝）与 `--older-than ""`（两者都解析失败）。

### 1.2 布尔一侧：42 对同处置 ✅

判据是 **`--flag ""` 与 `--flag ZZ-JUNK` 必须同退出码**：两者都是"布尔 flag 后面跟一个位置参数"，
唯一区别是那个 token 的内容——**空 token 不该被滤掉**。

### 1.3 读数的分布（如实）

多数命令在"布尔 flag 后面多一个位置参数"时**直接拒绝**（exit 3）；
少数忽略它（两者都成功）。两种都合格——判据只要求**两者一致**。

## 2. 产品改动

**0 行。** 两种写法本来就一回事，空 token 本来就没被滤掉。

## 3. 两个红，都不是产品

### 3.1 红一：**我的判据选错了对照**

探针第一版的判据是"`--flag ""` 必须**不等于**只给 `--flag`"——结果一堆命令被判红：

```
verify --offline   base=(3) empty=(3) junk=(3) EMPTY-SWALLOWED(?)
```

而红的不是产品：**那些命令的 base 运行本来就失败**（`verify` 在没有锁的项目里退 3），
三者自然一模一样。

> **"与基准相同"在基准失败时什么也证明不了。**
> 判据要选两个**处在同一状态**的对照——这次是 `""` 与 `ZZ-JUNK`：
> 它们都是"flag + 一个位置参数"，所以无论命令接受还是拒绝，判据都有意义。

### 3.2 红二：**夹具又隔离出新路径**（本系列第五次）

改成正确判据之后，`build --engine` 报"两种写法输出不同"：

```
一个 token: ConfigInvalid: permission denied: run:esbuild
  hint:  add "run:esbuild" to `permissions.allow` in C:\...\...2624772562\001\.ngm\config.json …
两个 token: ConfigInvalid: permission denied: run:esbuild
  hint:  add "run:esbuild" to `permissions.allow` in C:\...\...2624772562\003\.ngm\config.json …
```

**hint 里印了本次隔离 home 的绝对路径**，而两次 run 各自 `isolateUserEnv` 到**不同的** temp 目录。

同一族的第五次（v0.36 归一化全路径 · v0.41 隔离没一起做 · v0.45 store prune 印绝对路径 ·
v0.46 子命令参数底子 · v0.47 hint 里的 home）——值得立成一条纪律：

> **凡是归一化，先问一句：本次运行会生成哪些路径，而输出里会出现哪几个。**

## 4. 一条判据**边界**（量出来并写进网）

牙齿那一刀是：让 `normalizeArgs` 把空 token 当噪声滤掉。

| 组 | 命中 |
|----|------|
| 布尔（`--flag ""` vs `--flag ZZ-JUNK`） | **13 处** ✅（`--force ""` exit 0 vs `--force ZZ-JUNK` exit 3 …） |
| 取值（`--flag ""` vs `--flag=`） | **0 处** ❌ |

原因是 Go 的 flag 包把两种写法归一到同一件事，重排器的差异落不到最终行为上。

处置：**把这个边界写进网里**（那段注释），并说明它为什么还留着——
它钉的是一条对外承诺（两种拼法是一回事），成本 74 次进程内运行（约 0.6 秒），
它挡的是**将来换掉 Go 的 flag 包或自己写参数解析**的那一天。

> **绿不等于它在盯着什么。** 一条判据的**敏感度**和它的**通过**一样要实测；
> 量到"不敏感"时，把它写下来——而不是把那条判据删掉假装没这回事。

## 7. 过程洞察

### 7.1 对照要选**同状态**的

这是 v0.42 那句"两个都成功就必须一模一样"的补集：
**两个都失败时，也要说清"哪两个失败才该一样"**。

v0.42 的写法（只在都成功时比输出）在失败态的输入上会静默放过；这一版把它补成
"与同类的另一条路比处置"——判据因此在**任何**状态下都有意义。

### 7.2 夹具的第五次，值得升格成纪律

五次里有三次是"**本次运行生成的路径跑进了输出**"。所以纪律写成：
**归一化清单要从"输出里出现过什么"反推，而不是从"我以为会变什么"正推。**
