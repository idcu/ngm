# v0.76 计划 — **端到端：由用户自己的库驱动 ngm**

> 来源：用户把 `canonical-json` 推到 Gitee（GitHub 镜像已配）；
> 范围是 [v0.75 复盘](./v0.75-retrospective.md) §7 候选 1。
>
> 一句话目标：**让"标准 → 实现 → 被 ngm 消费"这条链第一次真正闭合**，并把沿途
> 真实输出留成证据；顺手修掉 dogfooding 才暴露的自检器误报。

---

## 0. 起点

到 v0.75 为止，"库"与"ngm"是两件分别验证过的事：
库过标准自检、ngm 过自己的全量测试。**它们从没在同一个真实场景里相遇过**——
而这类"两半都对、合起来不对"的缝，正是本项目一贯要找的东西。

## 1. 实跑清单（全部在真实公网仓库上）

```bash
ngm install     # 首次真实拉取 gitee:idcu/canonical-json@v1.0.0
ngm verify      # 内容 ↔ commit ↔ lock
ngm mappings    # 入口推断：应命中 ngm.json 第 1 层
ngm why         # v0.73 的头条：0 次 git 子进程
ngm sbom        # 依赖关系段（v0.73）
ngm attest      # SLSA 谓词（v0.70）
```

额外两项（本版特有的证据）：

- **在 vendored 副本上跑库自己的测试**——"免构建"最硬的证明；
- 用标准自检器扫 **vendored 副本**——"ngm 的产物本身就是一份合规的库副本"。

## 2. 预期与判据

| 判据 | 期望 |
|------|------|
| lock 里的 `requiredBy` | `["(root)"]`（v0.73 的图，真实依赖上第一次出现） |
| mappings 的入口 | `main=./src/index.js` / `types=./src/index.d.ts`，来源 `ngm.json` |
| verify | `✓ match`，exit 0 |
| why | 报告末行写明 **0 次 git 子进程**；`--json` 的 `source` = `lock` |
| vendored 测试 | **25/25 通过**（不装依赖、不构建） |
| vendored 自检 | 全绿（`semver-tag` 显示"不适用"，不计入） |

## 3. 已知约束（诚实记）

- **GitHub 从本机不可达**（`https://github.com` 连接失败；SSH 亦无凭据）⇒ 实跑走 Gitee 源；
  GitHub 侧由 Gitee 的镜像推送，本机不直接验证。
- 首次 `install` 会被**权限系统**拦下（`net:gitee.com` 既没允许也没拒绝）——
  这是默认拒绝的预期行为；实跑用独立 HOME（演示配置只放开 `net:gitee.com`），
  不动用户真实的 `~/.ngm/config.json`。

## 4. 流程

交付即提交、提交即打 tag。
