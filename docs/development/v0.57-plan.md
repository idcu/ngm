# v0.57 计划 — **码 1 的来源必须有据可查**

> 范围来源：v0.56 普查列出的候选 1——"V24 的 4 词关键词表只有单向",
> 当时写着"先定义**哪些源码位置可以产出码 1**"。
>
> 一句话目标：把"码 1 有哪些来源"从**手写关键词表**换成**从源码派生 + 双向对账**，
> 并让文档的语义列与事实一致。

---

## 0. 起点：三处说法互不相同

| 出处 | 说有几个来源 | 是哪些 |
|------|------------|-------|
| `internal/errs/errs.go` 的注释 | **3** | 漂移 · 漏洞 · 引擎 |
| `TestV24…` 的手写关键词表 | **4** | 漂移 · 引擎 · 漏洞 · 钩子 |
| 源码里的站点 | **？** | 先量 |

而那条判据只有**单向**：文档少一个词会红、**代码多一处来源不会红**。
它自己的注释写着"靠人记得"——这一版就是要把"记得"拿掉。

## 1. 要回答的两个问题

1. **宇宙是什么**：哪些形态算"能让进程以 1 退出"？
   （候选：字面量 `return 1` / `exit = 1` / 构造 `CodeRefDrift` / 取它的 `ExitCode()`）
2. **每处归哪一类**：类别名必须出现在 `observability.md` 的码 1 那一行里。

## 2. 判据

1. **从源码派生**站点（`cmd/ngm` + `internal`，跳过测试与 testdata、跳过纯注释行）；
2. 派生 ⊆ 登记：**新增一处来源即红**；
3. 登记 ⊆ 派生，**且逐函数对账条目数**（一个条目对应一处站点）；
4. 每个 source 类条目都要有 category，每个 category 都要在文档那一行里被写到。

## 3. 验收

```bash
gofmt -l . && go vet ./... && go build ./...
go test -count=1 -run 'TestV57|TestV24|TestV53' -v ./cmd/ngm
go test -count=1 ./...          # 整套，不手挑
bash scripts/check-docs-links.sh
```

**牙齿**：① 在**已登记的函数**里多写一处 ⇒ 红（这一条决定"条目数"要不要对账）；
② 在**新函数**里写一处 ⇒ 红。
