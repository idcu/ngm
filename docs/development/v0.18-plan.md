# v0.18 计划 — 第一次真实联网复核

> 范围来源：v0.11 C 组留下的"端到端可用性复核（可按季度重跑）"与"找一个真实使用场景"这条主线。
>
> 一句话目标：本项目**所有**测试都用本地 mirror（这是对的——门禁必须确定性、离线）。
> 代价是"**第一次真实上手能不能走通**"这条最影响采用的路径，在 CI 里**没有任何证据**。
> 本版把它补上：一个可选的联网复核工具 + 一次真实运行记录。

---

## 0. 为什么有这一版

三个事实叠在一起：

1. **所有门禁都离线**：`cmd/ngm` 的夹具用 `seedMirror` 预置本地裸仓，从不碰真实远端。
2. **采用是当前最大的风险**（0 外部用户），而采用的第一步就是"对真实仓库跑一次"。
3. 项目交付了 17 个版本，**从未有过一条"对真实 GitHub 的整改路径"的记录**。

因此本版交付一个**可选**的联网复核，并**当场跑一次**、把读数写下来——包括**没跑通**的部分。

---

## 1. A 组 — 可选联网复核工具

| 项 | 内容 |
|----|------|
| 入口 | `TestV18RealUpstreamFirstRun`（`cmd/ngm`），**默认跳过**，`NGM_REAL_UPSTREAM=1` 才运行 |
| 跑法 | `NGM_REAL_UPSTREAM=1 go test -count=1 -timeout 1200s -run TestV18RealUpstreamFirstRun -v ./cmd/ngm` |
| 验什么 | ① 真实 ref 解析（会移动的 `master`）② 真实仓库**没有 `ngm.json`** 时的行为 ③ **可复现性**：两个独立项目装同一 commit，`archiveDigest` 必须逐字相同 ④ 真实错误路径：不存在的仓库必须**点名它自己** |
| 边界 | **联网部分只记录、不判定**：它会因别人的服务而变，而那种红不属于本项目。远端不可达（exit 4）时**如实判为"未证明"**（skip），只有别的退出码才算失败 |
| 为什么不做成门禁 | 联网门禁会因第三方而红，**那种红会训练人忽略红色**——v0.15 已为此拒过一张网 |

---

## 2. B 组 — 一次真实运行记录（含未完成的部分）

三次尝试（本机 2026-10-04）：

| # | 结果 |
|---|------|
| 1 | `add` ✓ · `install` **✓（真实 clone，算出 digest 与 commit）** · 在线 `verify` 被 `Connection reset` 挡住 → **exit 4 + "check incomplete"** |
| 2 | `install` 在 `git clone --mirror` 上被 reset（**19.5s**）→ exit 4 + 点名 URL + hint |
| 3 | 连不上（**21.1s** 后 `Could not connect to server`）→ exit 4 → 复核如实 skip |
| 补充 | git 层单独实测：`git ls-remote https://github.com/octocat/Hello-World.git` → **21.0s 后 exit 128** |

**三条结论**：

1. **ngm 在真实网络失败下的行为是如实的**：`install` 退 4 并点名失败的 URL 与操作，在线 `verify` 说 `check incomplete` 而**不是**"通过"。此前"诚实读数"的验证都是**构造的**失败，这一次是真实的。
2. **完整首次上手路径未能在本环境端到端验证**——如实记为未完成（本机对 `github.com:443` 的 git-https 三次里只成功过一次）。
3. **一条被测量否掉的假设**：原本怀疑"网络等待没有上界"（准备加超时），而三次失败分别由 RST（~20s）与 TCP 连接超时（~21s）终止——都是 **git 自己的界**。**因此本版不改代码**：不去修一个没测到的问题。

**顺带的一条正面证据**：`ngm add` 耗时 **2–4 ms 且不触网**（ref 解析与取物在 `install`），与 `runAdd` 的注释一致。

---

## 3. 明确不做

| 不做的 | 理由 |
|--------|------|
| 给网络操作加超时 | **假设没有测量支持**（见上）。要加也得先测到"真的没有界"的形态 |
| 把联网复核放进 CI | 会因第三方服务而红 |
| 用真实仓库替换测试夹具 | 门禁必须离线确定性 |

---

## 4. 验收

```bash
# 默认必须跳过（它不进离线门禁）
go test -count=1 -run TestV18RealUpstreamFirstRun -v ./cmd/ngm

# 有正常网络时，这条给出真实读数
NGM_REAL_UPSTREAM=1 go test -count=1 -timeout 1200s -run TestV18RealUpstreamFirstRun -v ./cmd/ngm

go build ./... && go vet ./... && gofmt -l .
go test -count=1 ./internal/... && go test -count=1 -timeout 40m ./cmd/ngm
```
