# v0.61 复盘 — **管道被打断是用户的意图，不是失败**

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：v0.60 把人读路径的写失败折算成码 6（对的），但它顺手把
> `ngm verify | head` 也变成了失败 ✗。这一版把"**对端关闭**"与"**真的写不出去**"分开：
> 前者安静退出（它是用户的意图），后者仍是 6。
> 而分开的前提——**能可靠识别对端关闭**——是**先量出来的**（平台相关的错误形态）。

---

## 1. 逐组验收

### 1.1 先量：本机的"对端关闭"长什么样

```
写一个读端已关闭的 os.Pipe →
  err  = write |1: The pipe is being closed.   type = *fs.PathError
  errors.Is(err, syscall.EPIPE) = **false**     ← Unix 的判法在 Windows 上不管用
  errors.Is(err, io.ErrClosedPipe) = false     os.ErrClosed = false
  errno = 232                                   ← ERROR_NO_DATA
```

顺带量到一件事：`syscall` 在 Windows 上**只导出了** `ERROR_BROKEN_PIPE`（109），
`ERROR_NO_DATA`（232）与 `ERROR_PIPE_NOT_CONNECTED`（233）**没有常量** ✗——
探针的第一版就**编译失败**在这里 ✓（"写字面量"这件事因此有了**实测出处**，
而不是我凭记忆填的数）。

### 1.2 处置：一个跨平台判定 + 一处例外

```go
func isBrokenPipe(err error) bool {
    if errors.Is(err, syscall.EPIPE) || errors.Is(err, io.ErrClosedPipe) { return true }
    if runtime.GOOS != "windows" { return false }   // 下面的 errno 只在 Windows 上有管道语义
    for _, e := range []syscall.Errno{109, 232, 233} { if errors.Is(err, e) { return true } }
    return false
}
```

记账 writer 里：**对端关闭不记账** ⇒ 命令本来的退出码保留（通常 0 ✓）；
其它写失败照旧记账 ⇒ 码 6 ✓。

`runtime.GOOS` 那道门是有理由的：109/232/233 在 **Unix 的 errno 空间**里另有含义，
拿它们去比对会**误判**（把别的错误当对端关闭）。

### 1.3 判据三半 ✅

| # | 情形 | 期望 | 实测 |
|---|------|------|------|
| ① | 人读 + 对端关闭 | **0**（安静退出） | ✅ |
| ② | 人读 + 一般写失败（对照） | **6**（v0.60 的规则不变） | ✅ |
| ③ | **JSON + 对端关闭**（有意的不对称） | **6** | ✅ |
| ④ | 判定函数本身（`nil` / 一般错误） | 都不算对端关闭 | ✅ |

第 ③ 条**写成断言**是刻意的：v0.60 的教训是"**无理由的不一致**" ✗；
这一版的 ③ 是**有理由的差异** ✓——要 JSON 的人多半在解析，半份 JSON 必须报失败
（v0.16 规则①"不会出现半份"说的就是这件事）。**把它写成断言，它就变成可查的事实，
而不是悄悄的不同。**

### 1.4 牙齿 ✅（两个方向都能红）

| 探针 | 结果 |
|------|------|
| 判定恒 `false`（回到 v0.60 的行为） | 红：`` `ngm verify | head` 这种用法退了 6，想要 **0**（安静退出）——管道被打断是用户的意图 `` |
| 判定恒 `true`（把一切写失败都当对端关闭） | 红**两处**：`一般的写失败退了 0，想要 **6**——例外不许把这条规则吃掉` ＋ `isBrokenPipe(一般错误) 说是对端关闭——那会把真失败也吞掉` |

> 两道牙齿分别对应这条例外的**两侧**：不管用（回到旧错）与管太宽（吞掉真失败）。

## 5. 过程洞察

### 5.1 "跨平台"要先量，再写

这一版的判定如果在 Unix 上写完就交差 ✗，它在 Windows 上会**静默失效** ✗
（`errors.Is(err, syscall.EPIPE)` 恒 false ⇒ 例外永不生效 ⇒ 用户照旧拿到 6 ✗）。
探针一次就把两件事量出来了：**错误的真实 errno**、以及**哪些常量根本不存在** ✗。

> 与 v0.48 那条"按文件名找源码"、v0.57 那条"按名字扫站点"同族：
> **要按事实写，不按印象写**——而印象在跨平台时最容易错。

### 5.2 "不一致"分两种：无理由的，与有理由的

v0.60 修的是**无理由的不一致**（同一通道两套判法 ✗）。
这一版**引入**了一处不一致（人读安静、JSON 报错）——但它**有理由**，
所以处置不是"消灭它"，而是**把它写成断言 + 写进文档** ✓：

> 判据能把"有意的差异"与"漏掉的不一致"分开：**前者是一行断言，后者是一处沉默。**
