# v0.45 复盘 — 把**公开跳过**归零

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：v0.43 报出的"3 对公开跳过"里，**只有 2 对真的是子命令层的**；
> 第 3 处是我的**派生规则太粗**——而修它的过程**顺带挖出一个更大的洞**：
> `css` 这个命令的 flag **从来没有被任何一张网看过**，它一直躺在一条**假跳过**的后面。
> **产品代码 0 行改动。**

## 1. 逐组验收

### 1.1 三处跳过的真相 ✅（每一处都量过）

| 跳过 | 真相 | 处置 |
|------|------|------|
| `store --dry-run` | **真的**是子命令层（`store prune` 的） | 由新网按 `store prune --dry-run` 测四条断言 |
| `store --orphans` | 同上 | 同上 |
| `typecheck --minify` | **不是**——它是 `css` 的，而 `typecheck.go` 里住着**两个命令** | 归还给 `css`，`typecheck` 不再派生它 |

### 1.2 修 ① 时挖出的更大的洞 ✅

按块派生（`newFlagSet("name"`）之后要回答一个问题：**去哪找这个块？**
v0.43 的答案是 `cmd/ngm/<命令名>.go` ✗ —— 而 **`css` 没有 `css.go`**（它住在 `typecheck.go` 里）。

于是：**`css --minify` 与 `css --dry-run` 从来没有被任何一张网跑过。**

而修 ① 之前，这个洞是**不可见**的——因为 `typecheck --minify` 那条**假跳过**正好盖在它上面：

```
跳过名单上写着：typecheck --minify   ← "属于子命令，跳过"（看起来：测过了，只是跳过了）
真相是：        那只属于 css，而 css 自己一条也没测
```

处置：派生改成**按块 + 跨文件找**（`sourceFiles()` 扫全部 `cmd/ngm/*.go`）。

| 网 | 改前 | 改后 |

| v0.43 命令层 | **38 对跑满 + 3 对公开跳过** | **40 对跑满 · 跳过 0** |

### 1.4 两层共用**一套**判据 ✅

`checkBoolFlagSemantics(t, label, flag, run)` 由 v0.43 与 v0.45 共用——
两层若各写一份，两份判据迟早会各自漂移（"同一件事有两套标准"是这类项目最容易长出来的病）。

### 1.5 牙齿 ✅

| 探针 | 结果 |
|------|------|
| 派生退回"只找 `<命令名>.go`"（v0.43 原版） | 红：`the flagset "css" (typecheck.go) contributes `--minify`, which neither net reaches — it would be silently unchecked`（`--dry-run` 同样） |
| 派生静默返回空 | 红：`only 0 flag(s) were fully checked — the derived table no longer covers what it claims` |

第一道牙**正是这一版存在的理由**：它复现了那个洞，并指出**没有任何一张网到得了**。

### 1.6 那处红是我的夹具 ✅（如实记）

第一版新网跑起来就红，报的是 `--dry-run=true` 与 `--dry-run` **不等价**（exit 都在 0）:

真相：`store prune` 的输出里印了**这一次隔离 home 的绝对路径**
（`no unpack residue in <path> (nothing to do)`），而我的 `run` 每次都 `isolateUserEnv` 到
**不同的** temp 目录 ✗ —— 判据把"路径不同"当成了"flag 不等价"。

处置：把 home 归一化成 `<home>`（与 v0.43 归一化 `proj` 同一个套路）。
**这不是产品的问题，是我的夹具第二次在同一个地方绊倒自己**（v0.41 那次是"隔离没一起做"）。

## 5. 过程洞察

### 5.1 "跳过"是最容易藏东西的地方

跳过名单看起来是**透明**的——它公开报出来、还计数。但它同时是**一个洞的掩体**：

```
typecheck --minify   ← 名单上说"属于子命令"
css --minify         ← 真正没人看的东西，就躺在它后面
```

**"测过了，只是跳过了"和"根本没测"在名单上长得一模一样。**
这两个版本都写着"3 对公开跳过"；真相是 **2 + 1**，而那 1 处遮着一个**完全没有覆盖的命令**。

### 5.2 守卫要能察觉**覆盖路径**，而不只是"名字对得上"

第一版并集守卫的写法是：

```go
switch {
case len(parts) == 1 && known[parts[0]]:   // "块名是个命令 ⇒ v0.43 覆盖"
```

**它对 `css` 放行了**——因为 `css` 确实是命令名，而 v0.43 却一条也派生不出来。

改成"把两张网**实际会跑**的 (命令, flag) 集合算出来，再要求每个 flag 都落进去"之后，
它立刻抓到了（见 §1.5 牙齿 A）。

> 这是 v0.30「判据要能察觉自己的范围缩到零」、v0.35「判据不能硬编码规模」
> 的同一族的第三种形态：这次不是**范围缩了**，是**范围看错了**。

### 5.3 修一个 bug 时，留意它遮住了什么

修 ①（`typecheck` 的派生太粗）之前，`css` 的洞**不可能被发现**——
因为触发它的那条假跳过看起来一切正常。

**一个"已知误差"往往不只是误差，它还是一块遮布。** 处理它的最好的时机，
就是把它拆开逐条看的那一次。
