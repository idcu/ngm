# v0.69 计划 — **打开唯一愿意付钱的市场：SBOM 导出**

> 范围来源：[assessment-2026-10-09.md](../internals/assessment-2026-10-09.md) 第 3 层
> （"合规/审计场景是 ngm 唯一的付费场景，而它现在缺入场券"）。
>
> 一句话目标：**把 lock 里已有的证据翻译成别人能读的清单**——
> commit + archiveDigest + 来源链已经在 lock 里，导出几乎是免费的。

---

## 0. 起点：缺的是"入场券"，不是数据

评估第 3 层的第一条：

> **SBOM 导出（SPDX / CycloneDX）**——lock 里已经有 commit + digest + 来源链，导出几乎是免费的。

对照 §4.1 的竞品表：ngm 的"文件级签名/attestation"一栏是 ❌（ADR-014 决定不做），
而 SBOM 是合规场景的**最低门槛**——没有它，前面 68 个版本攒下的
"可锁、可验、可审"就没有一个能递进采购流程的形态。

## 1. 处置

新增 `ngm sbom`（v0.69）：

| 项 | 决定 |
|----|------|
| 格式 | CycloneDX 1.5（默认）与 SPDX 2.3，均为 **JSON**（最小且够用的字段集） |
| 输入 | **只有 `ngm.lock`**（+ `ngm.json` 取项目名）——不触网、不重解析、不写项目 |
| 哈希 | `archiveDigest`（规范化清单哈希，ADR-008），裸 hex；properties/comment 里写明**它不是 tarball 哈希**，免得被拿去对比时误判 |
| purl | `pkg:git/<host>/<path>@<commit>`（子路径进 `#subpath` 段） |
| 确定性 | 组件顺序由导出器**自己排序**（不信任调用方）；`documentNamespace` 由内容哈希派生（不是随机 UUID）；**时间戳是唯一非确定字段**——与 lock 的 `resolvedAt` 同一处理 |
| 不猜 | 许可证 / 版权一律 `NOASSERTION`（SPDX）；`filesAnalyzed: false`——编一份文件清单只为过 schema 是 SBOM 最常见的失真来源 |
| 出口 | `--out=<file>`（`--out=` 空值与"没给"等价，都走 stdout——v0.42 的不变量）；缺省写 stdout |

## 2. 验收

```bash
go test -count=1 -run 'TestV69' -v ./internal/sbom ./cmd/ngm
go test -count=1 ./...        # 整套（新命令会被 22 命令 × 8 形状的矩阵自动纳入）
```

**牙齿**：
- 输入顺序打乱 ⇒ 输出逐字节相同（排序在导出器内部做）；
- 只改 `Now` ⇒ 除时间戳外逐字节相同；
- 删掉哈希 ⇒ 测试红（每个组件都必须带哈希）。

**既有的网会问新命令什么**（预计四张，全部要过）：
v0.37 的配置矩阵（22 × 8）· v0.21/22 的退出码声明对账（0/3/6 各要有实测或登记）·
v0.57 的码来源登记（新的 `return errs.CodeInternal.ExitCode()` 站点）· v0.19 的用法文本（EXIT CODES）。
