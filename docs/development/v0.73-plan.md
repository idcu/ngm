# v0.73 计划 — **实现 ADR-028：依赖图形进 lock**

> 范围来源：[ADR-028](../adr/adr-028-dependency-graph-in-lock.md)（v0.72 已裁决）·
> [v0.72 复盘](./v0.72-retrospective.md) §7 候选 1。
>
> 一句话目标：**`ngm why` 不再需要解析**（读 lock 即答、0 次 git 子进程、离线可用），
> SBOM 终于有依赖关系段。这是评估"每 3 版至少 1 版用户可见增量"的兑现。

---

## 0. 起点

形状已经在 v0.72 定死，本版只做"照着做"：

- `Node.RequiredBy` 本来就是直接引用者集合（v0.68 的菱形测试钉过它）；
- `observability.FindPaths` 只吃 `RootDeclared` + 边——因此**从 lock 重建出来的图
  能直接喂给它**，不必为离线路径另写一套枚举；
- lock 解码器忽略未知字段（契约），新增字段不破坏向前兼容。

## 1. 处置（ADR §5 的五条验收）

| # | 项 | 落点 |
|---|----|------|
| 1 | lock 字段 `requiredBy`（恒在、序列化时排序 + 去重） | `internal/lock/schema.go` |
| 2 | 幽灵边：`Validate` 拒绝指向不在 lock 里的引用者 | 同上（`validateEdges`） |
| 3 | install / update 写入直接边 | `cmd/ngm/install.go` · `update.go` |
| 4 | `why` 有图 ⇒ 读 lock（0 spawn）；无图 ⇒ 退回并**说明来源** | `observability.GraphFromLock` + `WhyReport.Source` |
| 5 | SBOM：CycloneDX `dependencies` · SPDX `DEPENDS_ON`（同一份边；旧 lock ⇒ 整段省略） | `internal/sbom` |

## 2. 判据（先写，再实现）

```bash
go test -count=1 -run 'TestV73' -v ./internal/lock ./internal/observability ./cmd/ngm
```

- **头条**：`why` 在带图 lock 上 `git.SpawnCount() == 0`；
- 旧 lock ⇒ 仍可用且报告写"重新解析上游清单"（**回退绝不静默**）；
- SBOM 两种格式的依赖图形**一致**（一份边、两种映射）；旧 lock ⇒ 两段都省略。
