# v0.54 计划 — **解析阶段的失败也是机器可读的**

> 范围来源：v0.52 登记表里那条"**中**"（v0.51 记下）——
> "错误信封扩到**解析更早的失败**"。
>
> 一句话目标：用户明明提了 `--json`，而这次失败发生在"命令还没认出它"之前——
> 那一次失败也要在机器那侧留下形态。

---

## 0. 起点：先量

v0.51 把错误信封做进了 `runErr`，而 `runErr` 只在**命令内部**被调用。
先量清"更早的失败"到底长什么样（六种变体 + 三条对照）：

| 变体 | 预期它属于哪一类 |
|------|-----------------|
| `verify --json --bogus` / `verify --bogus --json` | 解析失败（两种顺序） |
| `audit --json=1` / `verify --json --dir` | ？——**先量，别假设** |
| `nosuchcmd --json` | 分派失败 |
| `--json verify`（json 在命令之前） | ？ |
| `verify --bogus`（没提 json）/ `install --json` | **对照**：必须仍为空 |

## 1. 判据

1. **接受 `--json` 的命令**（从派生的 flag 表问）：未知 flag——**两种顺序**都要给信封；
2. **未知命令 / 缺子命令**：同样给信封；
3. 信封合格：恰好一份 · `code` = `Usage`（数值仍是 3）· `exitCode` == 进程码 ·
   `message` 说清是哪个 flag/命令 · `hint` 点名 `--help`；
4. **两条对照必须仍为空**：没提 `--json` 时、命令**不接受**它时（v0.51 规则④那句没变）。

另加一条：人读那侧**只说一次**（flag 包已经打印过 usage，`failEarly` 不再重复）。
