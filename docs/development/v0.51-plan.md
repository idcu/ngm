# v0.51 计划 — **失败路径上也要有机器可读的那一份**

> 范围来源：v0.50 量出的一条边界（也是它候选表的第 2 条）。
>
> 一句话目标：`--json` 的命令失败时，脚本不该只拿到"退出码 + 空 stdout + 一段人读文本"。
> v0.16 的规则④要求"输入错误时 stdout 必须为空"——那是为了**报告**不许半份，
> 而不是为了不让脚本知道发生了什么。这一版把规则改成：
> **要么为空、要么恰好一份错误信封**。

---

## 0. 起点：先量

v0.50 的读数已经在那儿了：7 个命令支持 `--json`，
其中失败路径上 stdout **为空**、错误只以人读文本落在 stderr。

## 1. 判据

1. **信封**：`{"version":1,"error":{code,exitCode,message,hint}}`——
   `code` 与人读那侧同一个显示名，`exitCode` **等于进程退出码**，`hint` 与人读那句**逐字相同**。
2. **规则④改写**：失败时 stdout 要么为空（命令不接受 `--json`）、
   要么是**恰好一份**报告或错误信封。
3. **归一化收成一处**（v0.43 的网被这一版带红后立的）：
   凡比较两次运行的输出，先过共享助手 `normalizeRunPaths`
   （原样 / JSON 转义 / 斜杠三种形态）。

## 2. 验收

```bash
gofmt -l . && go vet ./... && go build ./...
go test -count=1 -run 'TestV16|TestV51' -v ./cmd/ngm
go test -count=1 ./...          # 整套，不手挑
bash scripts/check-docs-links.sh
```

**牙齿**：让信封少一个字段、或让它的 `hint` 与人读那句不同 ⇒ 必须红。
