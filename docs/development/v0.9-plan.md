## A — `store usage`：共享 / 独占 / 孤儿

- [x] A1 **blob 池按引用数切开**：共享（≥2 棵树引用）、独占（=1）、孤儿（0）。
- [x] A2 **每棵树报"丢掉它能回收多少"**（`ExclusiveBytes`）——这是用户唯一能问的
      回收问题的答案。口径**只算 blob**：于是 `exclusive <= logical` 恒成立，
      且 `Σ exclusive` **恰好等于** `BlobExclusiveBytes`（两条紧的不变量，
      "把共享算进每一棵树"这种错法立刻可见——它会让数字超）。
- [x] A3 **孤儿单独报出来**，并写明 `prune` **不会**碰它（ADR-018 决策 5）。
      原因：否则"没有人回收"只剩一句印象，而 ADR-018 将来判 GC 需要的正是这个数字。
- [x] A4 清单读不出来时**标注**（`UnreadableManifests`）：坏清单的 blob 会**失去引用**，
      于是孤儿被多算、共享被少算——偏差方向相反，所以不能说"是下界"，要分别说。

**验收**：三条新用例（`TestContentStore_UsageSplitsSharedFromExclusive` /
`..._ReportsOrphanBlobs` / `..._FlagsUnreadableManifests`），断言的是**不变量**而不是固定数字。
**已验证有牙齿**：把"共享也算进独占"放回去，两条等式立刻红，
报出 `Σexclusive(1566) != BlobExclusiveBytes(1536)`（差值 30 = 2 × 15，共享文件被两棵树各算一次）。

## B — 锚点检查

- [x] B1 `docs/` 下 `[label](file.md#anchor)` 的锚点存在性。
- [x] B2 **载体不是 shell 而是 Go 测试**（`cmd/ngm/docs_anchors_test.go`）：锚点要按
      Unicode 类别处理中文，而 `grep -P` 的 Unicode 行为**依赖 locale**（换机器可能退回
      按字节匹配——本项目在编码上栽过，v0.8 复盘 §5.8）；放在 `go test ./...` 里则
      本机与 CI 一起跑，**不需要新的 CI job**（少一处会各自漂移的接线）。
- [x] B3 **不确定处放宽，而不是收紧**：规则不确定的字符（`≠`、箭头、emoji…）**两个变体
      都算存在**。放宽只可能漏报，不会误报——而误报会让门禁被忽略。因此它可以当**门禁**，
      而不是又一个"只报不判"的读数。

**验收**：`anchors checked: 46`（全量，0 跳过）。
**已验证有牙齿**：把那条真实死锚点放回去，用例立刻红，并直接给出正确答案
（`…不存在。该文件里形近的锚点：7-v06-候选按证据强度排序非路线图承诺`）。

**为什么值得做**：收尾时审计一次就查出 **2 条死锚点**（`#7-v06-候选项…`，标题里是"候选"），
而当时的检查器**完全不看锚点**——点进去只会静默跳到页首。

## C — blob 池的规模（**只测不做**）

- [x] C1 造一个 10 万 blob 的池（直接写文件，不经过 Git），量：`usage` 的耗时、
      两位 hex 分片下的单目录文件数、以及 `usage` 的内存足迹。
- [x] C2 只给数据与结论，**不改布局**——是否分片更细是一个需要数据的决策。

**实测量**（本机 Windows，10 万个 32 B blob + 1 份真实内容树）：

| 量 | 值 |
|----|----|
| 分片数 / 单目录文件数 | 256 / **341 ~ 437**（均衡） |
| 写入速率 | 3756 blob/s（26.6 s 写 10 万个） |
| `Usage()` 遍历整个池 + 清单 | **244 ms**，分配 28.7 MiB，堆峰值 13.3 MiB |

**结论：两位分片在 10 万级仍有余量，`usage` 也仍是毫秒级 —— 本版不改布局。**
数字进 [metrics · blob 池的规模](../internals/metrics.md#blob-池的规模v09-实测只测不做)。

- [x] C3 **测量本身要能被复核**：用例默认 `t.Skip`，靠 env 触发，避免几十秒的 IO 塞进日常测试。
      跑法写在 [metrics](../internals/metrics.md#blob-池的规模v09-实测只测不做) 里。

> **它顺手抓到一个夹具陷阱**：第一版夹具用计数器造名字，2 万个 blob 的前两位全是 `00`
> （全落进同一个分片），量到的是夹具的偏差。真实 blob 名是 `sha256(mode‖content)`、前两位均匀——
> **"测出来的分布"先要用"分布本身对不对"验一遍。**

## 本版明确不做

| 方向 | 为什么不是现在 |
|------|---------------|
| 任何按可达性删除 blob 的代码（GC） | [ADR-018](../adr/adr-018-store-reclaim.md) 的两个条件未变：没有项目注册表。本版补齐的是**数据**（孤儿字节、独占字节），不是删除 |
| v1 → v2 的就地迁移 | [ADR-019](../adr/adr-019-content-addressed-blobs.md) 已否（要遍历所有树、用文件权限反推 mode、中途失败会留下半转换的 store）；出路是"删掉整层再重装"，`usage` 会打印它 |
| `remote` adapter 门槛 b、3s 口径重定义 | 需要决策/真实项目/更多版本的数据，见 [v0.8 复盘 §7](./v0.8-retrospective.md#7-v09-候选按证据强度排序非路线图承诺) |
