# v0.95 复盘 — **fetch 那一半也搬到本地了**

> 计划：[v0.95 计划](./v0.95-plan.md)
>
> 一句话结论：v0.94 证明 `subPath` 的契约不需要远端；这一版证明**抓取那一半也不需要推送**——
> 本机 443 上的 https + **真正的 `git http-backend`**（smart HTTP）+ 现场自签证书。
> 于是"端到端只差一次人工推送"这句话，从现在起**对验证不再成立**（推送只剩发布与镜像覆盖的意义）。

---

## 1. 做了什么

`TestV95HTTPSFetchEndToEnd`：

```
本机 443 上：Go handler ⇒ 真正的 `git http-backend`（CGI 语义）+ 现场自签证书
init → add https://127.0.0.1/acme/lib.git@v1.0.0 → update --all → verify
```

四条断言，其中第 ① 条是这条判据的**骨头**：

| # | 断言 | 为什么重要 |
|---|------|-----------|
| ① | **服务端真的收到了请求**（计数器 > 0） | 否则这个"端到端"可能只是从某个热的本地镜像里读出来的——那样它什么都没证明（v0.94 的链路是 `--offline`，正是这个风险） |
| ② | `ngm.lock` 钉的 commit = 上游 HEAD | 证明 ref 真的在远端被解析，而不是照抄声明 |
| ③ | mappings 生成、指向包自己的 `exports` | 落盘那半条链路 |
| ④ | `verify` 通过 | 内容与 lock 一致 |

## 2. 一条边界：schannel 不读 `GIT_SSL_CAINFO`

第一次跑就是红的，报的是：

```
fatal: unable to access 'https://127.0.0.1/acme/lib.git/':
  schannel: SEC_E_UNTRUSTED_ROOT (0x80090325)
```

Git for Windows 默认走 **schannel**（Windows 证书库），而 `GIT_SSL_CAINFO` / `http.sslCAInfo`
是 **OpenSSL 构建**的开关——schannel 后端**不读它**。

对一条自签证书的本地端到端，剩下的路只有三条，而另外两条都不该走：

| 路 | 为什么不该走 |
|----|-------------|
| 往系统证书库装一张测试证书 | 一个测试**不该**动那台机器的信任根 |
| 为了测试切 TLS 后端（openssl） | 依赖构建里恰好带它，而且验的就不是默认后端了 |
| 关掉校验（`GIT_SSL_NO_VERIFY`） | 见下 |

于是选了第三条，并把边界写在注释里：这条端到端验的是
**"ngm 会构造 `https://host/org/repo.git`、smart HTTP 能谈、ref 能解析、内容能落盘"**，
**不是** "TLS 链校验"（那归 git 与操作系统，不该由本测试自证）。

> 这也是本项目一贯的分法：**把"这条判据到底证明了什么"写下来**，
> 而不是让"测试是绿的"承担它承担不了的结论。
