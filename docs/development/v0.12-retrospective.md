# v0.12 复盘 — 让读数说真话（第二轮：文档与静默失效）

> 体例与各版一致：逐组验收 → 未达成项 → 设计偏离登记 → 缺陷清单 → 过程洞察 →
> 指标 → 下一版候选。
>
> 范围来源：[v0.12 计划](./v0.12-plan.md)（它自己又来自 v0.11 复盘 §7 的候选 0/1/4
> 与 2026-10-04 的一次外部复核）。
>
> 一句话结论：**本版唯一的"新功能"是子命令帮助，其余全是把读数修准**——
> 六处文档与事实不符、六处静默失效缺陷、一条命令行 flag 的机械网。
> 其中**最有价值的一处不是修好的，而是被证伪的**：`v0.1.0` 在 Gitee 上根本没有发行版，
> 而四份文档都写着"两个源都可取到"。

## 0. 先说清楚这一轮是谁做的

本轮的"外部复核 + 修复"由**一个 AI 助手**在项目所有者授权下执行：读文档、扫代码、
跑全量测试、直接问两个发行源的 API，然后提交、推送、走完结项仪式。

记在这里不是为了标新立异，而是因为它与本项目的一个核心主张直接相关：
状态页写的动机是"**一个人（或一个 AI）接手时读不到它**"。
这一轮恰好是那个假设的第一次实测——**结果见 §5.1：读不到的不只是状态，还有状态里写错的地方。**

## 3. 设计偏离登记

| # | 计划写的 | 实际做的 | 为什么不是照做 |
|---|---------|---------|---------------|
| 1 | E1 的判据："flag 必须在用法文本里被写出来" | 实现时第一版**按行首匹配** FLAGS 条目 | **它立刻误报了一处**：`ngm integrations` 把三个 flag 写在 USAGE 行里（`[--dir=<dir>] [--dry-run] [--json]`），那是同一个事实的另一种排版。判据因此改为"在该文件的**原始字符串字面量**里出现过"——形状检查会误报，而**会误报的门禁会被忽略** |
| 2 | D1 的验收：冷 mirror 时应当失败 | 实测**退出码是 0**，不是 4 | `outdated` 是**报告**、不设门禁（它自己的 `EXIT CODES` 就这么写），而 `CheckOutdated` 把 `EnsureMirror` 的错误折成 `stale`。**是测试的预期写错了，不是实现**——修正的是断言，并把"原因必须被打印出来"补成新的一半 |
| 3 | D6：端口"如实拒绝" | 没有拒绝**默认**端口 | `:443` 在 https 下与不写端口是**同一件事**，拒绝它只会制造假失败。判据按 **scheme** 而非按端口号：`:443` 在 https 下接受、在 `git://` 下拒绝 |
| 4 | D5：两阶段写入 | 保留了一个**残余窗口**：改名阶段仍可能失败 | 已经写不了盘（内容与目录都就绪），但改名本身失败时无法回滚。处置：错误里**列出已经就位的文件**，而不是假装原子。**不把"接近原子"说成原子** |
| 5 | （未提）`cssUsage` 的文本 | 补了"每次一个输入"与对应退出码 | D3 新增了一条 exit 3 路径，用法文本不提它，就等于制造一个新的"文档与行为不符"——那正是本版要治的病 |

### 4.2 本轮自己制造、当场修掉的（**新的一类：工具链缺陷**）

这一版第一次出现"**修缺陷的过程中自己踩出缺陷**"，值得单独记：

| # | 现象 | 根因 | 处置 |
|---|------|------|------|
| T1 | 新建的 4 个 `.go` 与 1 个 `.md` 带 CRLF，`gofmt -l` 立刻变红 | 编辑器在 Windows 上按 CRLF 落盘。`.gitattributes` 保证**提交内容**是 LF，因此 CI 不会红——但**本地纪律会红**，而"本地红、CI 绿"会让纪律失去意义 | 全部转 LF；`.golden` 一字未动 |
| T2 | `gofmt` 把我的注释改成了一句带排版引号的话（`` \`...\` `` → `\`...\“`） | Go 1.19+ 的文档注释格式化会把**两个相邻反引号**折成弯引号 | 改写注释避开连续反引号。**这一条值得记**：工具会改文档注释的语义外观，而它是"格式检查"，看起来只动空白 |
| T3 | 本机**跑不了** `scripts/check-docs-links.ps1` | 它转调 `.sh`，而本机没有 bash/WSL（脚本这么做是为了"只保留一份实现"） | 用等价的内联检查替代：**结果只剩散文里的示例链接**（`x.md`/`file.md` 等），真脚本会先剥行内代码。**记为已知摩擦**：Windows 无 bash 时本地少一条检查，CI 侧不受影响 |
| T4 | 新写的 Gitee 读数脚本，`-Tags a,b` 被当成**一个**名叫 `a,b` 的 tag | `powershell -File` 不解析数组字面量，整个 `a,b` 作为单个字符串进来。后果是一个**看起来合理、实际错误**的读数："没有发行版" | 按逗号拆开。**记在这里是因为它又一次印证本版的判据**：这条路径是我特意去跑第二条参数路径才暴露的——**只测主路径的脚本等于没测参数** |
| T5 | 把成对的反引号写进了 raw string 里的 usage 常量，字面量当场被截断 | Go 的 raw string 用反引号界定，而**反引号在本项目的 usage 文本里是排版习惯**（`ngm build` 这类）。所以"把命令写成反引号"这个下意识动作，在这里恰好是语法错误 | 去掉反引号。**它与 T2 是同一类错误的两次**（T2 是注释里两个相邻反引号被 gofmt 折成排版引号）——**两次都在同一轮里**，而两次都是 `go build` 抓到的、不是 review 抓到的 |
| T6 | 一次提交失败：commit message 里的 **ASCII 双引号**被 PowerShell 5.1 拆成了多个参数，`git commit` 报出三个 `pathspec ... did not match` | 把含引号的文本传给原生 exe 时，PS 5.1 的引号处理与 POSIX shell 不同。而**本项目的发布路径整个跑在 PowerShell 上**（`upload-gitee-assets.ps1`、发布清单第 6 步、本轮的 Gitee 读数） | 改用中文引号（仓库既有提交信息本来就用中文引号）。**记它的理由**：它看起来像"git 不认我的文件"，实际是**参数在到达 git 之前就已经被拆开**——与本版治的那一族（"接受的输入被静默曲解"）是同一个形状，只不过这次受害者是我自己 |

## 5. 过程洞察

### 5.1 状态页的第一次真实读者测试：写错的东西比没写的东西更贵

本轮的起点是"读一遍状态页再核实"。三层的状态叙述分别停在 v0.8 / v0.10 / v0.11——
**这不是缺内容，是缺对账**。更要命的是其中**有一条是错的**：
`v0.1.0` 在 Gitee 上没有发行版，而四份文档（根 README、docs README、roadmap、project-state）
都写着"两个源都可取到"。补发记录里从来只有三条，**两处说法不一致时，这一轮选错了信哪一边**。

> **可复用的判据**：状态页说"已发布"时，**只有 API 能给它签字**。
> `check-release-status.sh --published` 早就在那里，它读的是 GitHub；
> **Gitee 侧没有对应的读数**。这条空白**在同一轮里补上了**（F 组）：
> `scripts/check-gitee-release-status.ps1` 现在能逐 tag 报"有没有发行版、7 个附件齐不齐"，
> 而它给出的第一个读数就是"缺 8 个"。

### 5.2 "会误报的门禁会被忽略"——本版第二次交学费

E1 的第一版判据（行首匹配 FLAGS 条目）立刻误报了一个**排版不同但事实正确**的文件。
这条纪律项目里已经写过（v0.6"指标页上的数字只有在它被门禁守着时才可信"），
但它的**反面**第一次被写下来：**判据过严 = 门禁被忽略 = 等于没有**。
最终判据取"原始字符串字面量里出现过"，并在测试注释里写明它**不**证明什么。

### 5.3 复用常量，而不是写第二份文本

子命令帮助没有新写任何帮助文本：它打印的就是每个命令参数错误时用的 `xxxUsage`。
这不是省事，是**把"两处说法不一致"这个缺陷类别从设计上删掉**。
同一条理由让 `testdata/help.golden` 的更新变成一次机械对账。

### 5.4 对照用例不是仪式

E3 的正反两条：一个"永远失败的实现"也能让"什么都没写"变绿，所以必须有"正常路径仍然成功"
在旁边。这与 v0.11 的 `waitdelay_test.go`、v0.6 的 spawn 预算同源——
**断言必须能区分"做对了"和"什么都没做"**。

### 5.5 内部一致性检查的边界，第二次被证明

D1~D5 五处缺陷，**在 build / vet / gofmt / 445 条测试 / 门禁全绿的状态下同时存在**。
发现它们的是一次"静默失效"专项审计（人/AI 主动去找"接受的输入被忽略"这类形状），
不是任何一条既有检查。这与 v0.11 C 组的结论完全一致，也是本版把 E 组（机械网）
放在同一版交付的原因：**找到一类形状之后，要立刻把它变成网，否则下一版会再找一遍。**

### 5.6 测试预期写错，是测试的功劳而不是耻辱

D1 的验收第一版断言 exit 4。实测 exit 0——**实现是对的（报告不设门禁），断言是错的**。
如果当时"为了让测试通过"去改实现，`outdated` 就会被改成一个会阻断 CI 的命令，
而那与它的文档、与它存在的理由都相反。**红的那一次，挡住的是一次错误的修改。**
