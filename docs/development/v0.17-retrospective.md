# v0.17 复盘 — 解释输出必须有界

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 范围来源：[v0.16 复盘](./v0.16-retrospective.md) §7 候选 1；实施计划：[v0.17 计划](./v0.17-plan.md)；
> 决策：[ADR-024](../adr/adr-024-bounded-explanations.md)。
>
> 一句话结论：**语义是对的，规模是失控的。** `why` 与 `tree` 的解释都正确（菱形、根+传递、环
> 全部实测通过），但它们随图"宽"**指数增长**——41 个节点就能产出 104 万条路径、626 MB，
> 而图的形状来自**上游清单**，不是本项目的输入。本版给两者加上**可见的上界**。

---

## 1. 逐组验收

### 1.1 语义审计（负面结果，如实记）

构造函数化夹具，覆盖既有测试没有的三类图形：

| 图形 | 期望 | 实测 |
|------|------|------|
| 菱形（两个 mid 都依赖同一个 leaf） | 两条路径都给出 | ✅ `paths=2` |
| 根声明 + 也被传递引入 | 直接路径与传递路径**同时**给出 | ✅ `paths=3`（1 条两元素 + 2 条传递），文字版分成"直接依赖/传递依赖" |
| 环（alpha ⇄ beta） | 不挂住、标出来、其余命令正常 | ✅ `add`/`install`/`verify` 退 0；`tree` 标 `↺ cycle (not expanded)`；`why beta` 给出路径 |

**没有发现语义缺陷。** 这条负面结果本身就是结论：这套工具的核心解释力是对的。

### 1.2 A 组 — 上界（[ADR-024](../adr/adr-024-bounded-explanations.md)）

| 判据 | 验收 |
|------|------|
| **输出有界** | ✅ `why` 默认最多 64 条路径（端到端：128 条路径的图 → 恰好 64 条）；`tree` 默认最多 4096 个条目（单元：8192 路径的格 → 恰好 4096 条目） |
| **工作量有界**（不是先算完再砍短） | ✅ 有界枚举 64 条用 **544 µs**；不限量时同一张图是 1 048 576 条 / 0.778s / 626 MB |
| **截断可见** | ✅ 文字写明"已列出 64 条（还有更多未列出；用 --all 展开全部）"/"树不完整"；`--json` 带 `pathsTruncated`+`pathsLimit` / `entriesTruncated`+`entriesLimit`；停止处条目带 `truncated` |
| **不许多报** | ✅ 恰好 64 条时 `truncated=false`（实现上用"多枚举一条"区分"正好"与"还有更多"） |
| **退出码不变** | ✅ 截断不是错误 |
| **`--all` 解除** | ✅ 128 条 / 8192 条目全给，且不标截断 |
| **正常图形不受影响** | ✅ 端到端那张 382 条目的树不被标记 |

### 1.3 B 组 — 输出示例必须与快照同形

审 A 组时顺手发现：`docs/architecture/observability.md` 的 **两段输出示例**
都在画渲染器**从不产生**的形状（树形方块 + `├──`；真实的 `tree` 只用缩进，
真实的 `why` 是扁平标签行），而该页自己声明"输出即当前真实行为"。

| 项 | 结果 |
|----|------|
| 文档 | 两段示例改成**快照本身**（占位符 `<sha>` / `<digest>` / `<time>`），并注明"这一段就是快照" |
| 网 | ✅ `TestV17DocOutputExamplesMatchTheGoldens`：从文档取块 → 归一化 → 与 `testdata/*.golden` **逐行比较** |
| 牙齿 | ✅ 把示例改回 `├──` 形状 ⇒ 网点名 `tree.golden` |

## 2. 未能达成的项

**本版范围内没有未达成项。** 范围外（已写进计划与 ADR 的"不做"）：
按**时间**截断（会破坏确定性）、给**深度**设上界（无真实案例）、统一 JSON 形状（破坏性变更）、
把 `tree` 改成"去重树"（**语义重设计**，会让条目数变线性，但改变形状与快照——记为候选）。

## 3. 设计偏离登记

| # | 计划写的 | 实际做的 | 为什么 |
|---|---------|---------|-------|
| 1 | 只审 `why`/`tree` 的 **`paths` 语义** | 语义审完**没有缺陷**，于是转向同一个问题域的**另一半：规模** | 本版最重要的一次转向。语义正确 ≠ 安全：**41 个节点就能让 CI 吃掉 626 MB**。审计的负面结果不是终点，它只是把问题推到了下一个维度 |
| 2 | 计划里没有"不许多报"这条判据 | 实现时补上：恰好等于上界时 `truncated` 必须是 `false` | "碰到了上界"**不构成**"还有更多"的证据。用"多枚举一条"区分两者——**报告不许把'列完了'说成'还有更多'**，两个方向的说谎一样糟 |
| 3 | 计划里没写 B 组 | 追加"输出示例必须与快照同形" | 审 A 组时**顺手看到的**：文档示例的形状与渲染器不符。看见了不记，正是本项目最反对的事 |
| 4 | `Truncated` 只作为报告级字段 | 条目级也要有，且**只在确有子节点未列出时**置位 | 报告说"不完整"是够的，但读者还需要知道**在哪儿断的**。而"预算恰好用尽在叶子上"不是截断——标记不许把"看完了"说成"没看完" |

## 4. 缺陷清单

| # | 缺陷 | 性质 | 状态 |
|---|------|------|------|
| D1 | `observability.md` 的 `ngm why` / `ngm tree` 输出示例与渲染器不符（方框形状；why 被画成树），而该页声明"输出即当前真实行为" | **文档缺陷**（与 v0.14 D4 同族：快照说了算，文档只是它的镜子） | ✅ 已修 + 被新网钉住 |
| — | **产品缺陷：0 处** | 语义三类图形全对；环不挂；上界之外没有别的问题 | — |

**自己制造、当场处置的**：

| # | 现象 | 处置 |
|---|------|------|
| P1 | 探针把 `resolve.Node.RequiredBy` **写反**（那是父节点，不是子节点），于是 `paths=0` | 修正构造并把这个坑写进 `lattice()` 的注释——**它下次还会有人踩** |
| P2 | 断言"展开条目数 = 2^depth"，实测 46 ≠ 16 | 树是**按路径展开**的：条目数是 `3·2^depth − 2`（共享节点随每条路径各出现一次）。**网的第一次失败抓的是我自己的算术**，算式连同推导写进了测试 |
| P3 | 探针改出**编译错误**（`truncated` 声明未使用），网根本没跑 | 差点读成"网没抓住"。**失败的探针什么也没证明**——"探针真的跑了吗"是验证的前提，不是细节 |
| P4 | **反引号陷阱第三次**：原始字符串里写 `` `--all` `` 把 usage 常量截断（v0.12 在 `help.go` 记过一次） | 立即修正。这条纪律已经写进过一份复盘，仍然复发——说明"写进复盘"不等于"形成肌肉"，**能机械化的只有网**（v0.15 的 flag 网确实会在改 usage 时跟着看） |

## 5. 过程洞察

### 5.1 审计的负面结果要接着问一句"下一个维度呢"

语义审计干净通过。如果就此收工，这一版会是一份"没发现问题"的报告——
而真正的问题就在隔壁：**同一份语义，规模上失控**。
`why` 枚举全部路径是**语义要求**（多父必须都给出），恰恰因此它是指数的。
**"正确"与"安全"是两个维度**，前者的通过不蕴含后者。

### 5.2 上界必须同时约束输出与工作量

只把结果砍短的上界是假的：最坏情况照样要算完 626 MB。实现里让"达到上界即停止遍历"
（`walker.stopped` / `treeBudget`），于是有界枚举用 **544 µs** 完成了不限量要 0.778s 的工作。
**上界要名副其实**——这条在本项目已经是第 N 次出现（`versionProbeTimeout`、3s 秒数门禁、
`WaitDelay`），这次出现在解释输出上。

### 5.3 判据要覆盖"两个方向的说谎"

"还有更多没列出来"与"已经列完了"都可能被说错。前者靠 `truncated=true`，
后者靠"恰好等于上界时 `truncated=false`"。**把两个方向都写进判据**，
是这一版最像本项目的一处细节——一个只在单向成立的不变量，等于半个承诺。

### 5.4 探针失败 ≠ 网有牙齿

P3 那次探针**编译失败**，网格线没跑过一次。如果我只看"报错了"就当验证完成，
这一版会带着"已验证"的标签把一张没被证明过会红的网交出去。
**验证的前提是"验证动作真的发生了"**——这与 v0.15 P3（机械改名漏了两处、靠补扫残留发现）
是同一种自觉：**别把"我做了动作"当成"动作产生了结果"**。

### 5.5 文档里的"命令示例"与"输出示例"是两类东西

v0.15 钉住了前者（示例命令必须成形）。这一版发现后者此前**完全没有网**，
而它更容易错——命令的错照抄会立刻报错，输出的错只会让人**以为工具会那样打印**。
两段示例现在都是快照的镜子：改渲染器 ⇒ golden 红 + 文档对照网红，两处一起提醒。
