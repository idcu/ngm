# v0.60 计划 — **两条通道对"写不出去"必须判法一致**

> 范围来源：v0.59 复盘候选 1（它自己的探针量到的新发现）。
>
> 一句话目标：人读路径在 stdout 写失败时**不再退 0**——
> "报告只写出去一半却报成功"要能被区分出来。

---

## 0. 起点：先量全貌

| 调用（stdout 永远写失败） | 今天 |
|--------------------------|------|
| `ngm verify` / `why` / `outdated` / `tree`（人读） | exit **0** · stderr 空 ✗ |
| `ngm engines list`（人读） | exit **6** · `write listing: …` ✓ |
| `ngm --help` | exit **0** ✗ |

**同一条通道里判法不一致** ✗：`engines` 检查了 `tw.Flush()`，其余把错误丢了；
而 JSON 路径**一律**检查 ✓。

## 1. 处置：在**唯一入口**包一层

不逐命令加检查（要改十几处调用点），而是在 `dispatch` 里包一个
**记账 writer**：写失败记下，命令返回后折算——命令**本来成功**（码 0）而写失败 ⇒ **码 6**
（ADR-026 的同一类：结论有了却送不出去）。业务失败优先（命令自己退了非 0 就按它的码走）。

`Write` 把**真实错误**返回给调用方：本来就检查错误的命令（如 `engines`）仍走自己的分支，行为不变。
