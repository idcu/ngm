# v0.77 复盘 — **标准覆盖第二种形态（CJS / 带构建 / monorepo）+ `ngm add` 实跑**

> 一句话结论：把标准套到**别的包形态**上，抓到两处**误伤**（显式 CJS 被判不合格 ·
> monorepo 根被当成包），两处都已修掉并各有判据守着；顺带在实现 monorepo 模式时
> 抓到一个**静默丢结果**的实现缺陷（Windows 版 node 读不到 MSYS 临时路径）。
> `ngm add` 用真实公网库走通（add → install → verify → why → mappings validate）。

---

## 1. 逐组验收（全部实测）

### 1.1 两处误伤与处置

| 形态 | 修前 | 修后 |
|------|------|------|
| A · CJS 优先 + 构建产物已提交（`"type": "commonjs"`） | `✖ esm-first 未声明 type=module（ESM 是现时默认；CJS 需显式说明）`——而它**已经显式说明**了 | `✔ esm-first type=commonjs（显式选择；ESM 是默认推荐，但写明的选择被尊重）`；`--strict` exit 0 |
| B · monorepo（`workspaces`，根不是包） | 根：`✖ entry-resolvable` + `✖ esm-first` + `✖ exports-conditions` + `✖ types-provided` + `✖ publish-scope`（五处误伤，必做红 ⇒ exit 1） | 根：六条包专属判据一律 `—`（不适用）+ 7 条 skip；**子包逐个按同一支脚本体检**（结论带 `packages/a/` 前缀）；`--strict` exit 0 |

### 1.2 monorepo 模式的读数

```
根        22 条：✔ 15 · — 7（6 条包专属 + semver-tag）
packages/a 22 条：全绿（— 1：semver-tag）
packages/b 22 条：全绿（— 1）
合并 --json  ok=true · mustFail=0 · shouldFail=0 · skipped=9 · checks=66（44 条带前缀）
```

**牙齿（4 条，全部实测）**：删掉 `packages/b` 的 `exports` ⇒ `✖ exports-conditions`
（推荐项）+ "子包里有未通过项 —— 合计不合格" + exit 1；
`workspaces` 匹配到的目录里没有 `package.json` ⇒ `✖ workspace-package-json`（必做）+ exit 1；
形态 A 的 `dist` 被 `.gitignore` 排除 ⇒ `✖ dist-committed` + exit 1；
`.gitattributes` 放在仓库根 ⇒ 子包记为 `✔ …（仓库根 monorepo/，子包不必自带）`。

```
$ ngm add gitee:idcu/canonical-json@v1.0.0 --ref-type=tag

next: run `ngm install` to resolve and lock

$ ngm install   → gitee:idcu/canonical-json@v1.0.0 (tag) → 9688ac0…（与库 HEAD 一致）
```

## 3. 设计偏离登记

| # | 计划写的 | 实际做的 | 为什么 |
|---|---------|---------|-------|
| 1 | 子包另写一套"轻量检查" | **用同一支脚本递归**（`NGM_LIB_STD_ROLE=package`） | 子包就是普通的包；两套规则必然漂移（"规则只允许有一种写法"） |
| 2 | 合并靠 bash 拼 JSON | 交给 **node 合并**（父进程只做归属） | bash 拼 JSON 容易产生"看起来对但类型不对"的输出；node 而已有硬依赖 |
| 3 | 临时文件直接传路径给 node | 传 `cygpath -w` 后的路径 | 见 §4.1：Windows 版 node 不认 MSYS 路径 |

## 4. 缺陷清单

| # | 缺陷 | 谁发现 | 处置 |
|---|------|-------|------|
| 1 | 显式 CJS 被判"未声明 type=module"（推荐项**不可满足**） | 造形态 A 的 fixture（"照着标准的字面做一遍"） | 显式 `commonjs` 记为合格；判据消息改成"未声明 type（module 或 commonjs）——模块形态不该靠猜" |
| 2 | monorepo 根被套上五条"包"的判据 | 造形态 B 的 fixture | 新角色 `mono-root`：六条包专属判据记 `—`；根另加"私有根可缺 version" |
| 3 | **子包结果被静默丢弃**：JSON 合并里 `catch { continue; }`，而 node 根本读不到 MSYS 临时路径（`/tmp/x` → `D:\tmp\x` ENOENT） | 自己验 `--json` 合并时（`checks=22`、0 条前缀 id ⇒ 与"子包没跑"长得一模一样） | ① 路径过 `cygpath -w`；② 读不出来 ⇒ 变成 `child-result-unreadable` 的**必做失败**（静默丢 = 把没查过的当成查过了） |
| 4 | 牙齿测试的预期写错：以为删掉子包目录会触发"缺 package.json" | 跑测试（exit 0 ≠ 1） | `packages/*` 只匹配**存在**的目录；改成"目录在、没有清单"——这本身就是需要写进测试注释的语义 |
| 5 | 标准页"相关文档"里两条重复的 `[依赖管理]` 链接 | 顺手扫到 | 合并成一条 |

## 5. 过程洞察

### 5.1 "标准只在它自己的样本上跑过"是这次的主线

v0.74 的标准、v0.75 的实现、v0.76 的端到端，用的都是同一种形态。
换两种形态立刻掉出两处误伤——而且**都不是判据没写，而是判据写死了**：
`esm-first` 把"推荐 ESM"写成了"必须 ESM"，monorepo 则被默认"每个目录都是一个包"。
**判据的错误分两种：漏判（该红不红）与误判（不该红却红）。后者更难发现**——
因为它看起来像"标准很严格"，而严格是讨人喜欢的。

### 5.2 两个工具链的路径不通，是这台机器上的一个反复出现的坑

`/tmp/x`（MSYS）与 `D:\tmp\x`（Windows node）不是同一条路径；
Go 测试里 WSL 的 `bash.exe` 与 Git 的 `bash.exe` 也不是同一个解释器。
两次的表现形式不同，**本质是同一条**：*两个都声称自己是 bash/node 的东西，
对同一个字符串的理解不一样*。这一版的处置是把它写进注释与函数名（`win_path`），
让下一个人不必再踩一次。

### 5.3 静默丢弃最会挑地方出现

第 4 条缺陷（子包结果读不出来 ⇒ `continue`）出现在"合并"这种**看起来只是搬运**的代码里。
它的输出（`checks=22`）与"子包本来就没跑"完全一样——**失败与正常长得一模一样**，
正是本项目反复要消灭的形态。修法也照例：把它变成一条**显式的必做失败**。
