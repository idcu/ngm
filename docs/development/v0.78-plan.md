# v0.78 计划 — **monorepo 的另外两个信号 + 自检器与产品读同一份事实 + 发布读数实测**

> 来源：[v0.77 复盘](./v0.77-retrospective.md) §7 候选 1（pnpm / lerna 变体）与候选 4（联网核对）。
>
> 一句话目标：把 v0.77 的"形态覆盖"做完（pnpm / lerna），并在做的时候盯住一条：
> **自检器比产品严就是误判**——标准推荐的事，产品必须真的读。

---

## 0. 三个起点

1. **pnpm / lerna 的 monorepo**：v0.77 只认 npm 的 `workspaces` 数组。另两种形态里，
   子包清单在 `pnpm-workspace.yaml` 或 `lerna.json`——而 pnpm 的根**可以没有** `package.json`。
2. **自检器与产品的入口推断**：标准第 1 条**推荐** `exports`；如果自检器不读 `exports`
   而产品（`internal/mappings.InferEntry`）读，那么一个"照着标准做"的库会被判红。
3. **发布读数**：GitHub / Gitee 两个源的历史读数（60 / 3）是 2026-10-05 的；
   本机虽然连不上 GitHub，但 API 可以通过联网工具**实测**——读数不该继续靠记忆。

## 1. 计划

| # | 项 | 验收 |
|---|----|------|
| 1 | monorepo 三个信号合并（npm `workspaces` · pnpm `pnpm-workspace.yaml` · lerna `lerna.json`） | pnpm（根无清单）与 lerna 两种 fixture 各 `--strict` exit 0 |
| 2 | 根"不是包"的判据补齐：`pkg-json-exists` / `pkg-name` / `pkg-version` / `license` / `engines` | 根上全部 `—`（不适用）并写明理由 |
| 3 | 子包清单的 glob：`dir/*` + 花括号 `{a,b}/*` | `{packages,apps}/*` 展开成两个子包 |
| 4 | 读不出的写法**不许猜** | `workspace-manifest-unreadable` 必做失败（含"有 N 条读不出"） |
| 5 | **自检器与 `InferEntry` 对齐**：候选层次读 `exports`（字符串 / `"."` 字符串 / 条件映射）+ 补 `index.cjs` | 只写 `exports` 的子包：`entry-resolvable` 与 `types-provided` 都 pass |
| 6 | 发布读数实测（GitHub tags / releases · Gitee releases）并修正文档 | 读数带**日期与方法**，与工具输出一致 |

## 2. 不做

- 嵌套 monorepo 的递归（仍是明确不做）；
- pnpm 的 `catalog:` / `workspace:` 协议读法（不是子包清单）；
- 把 tag **推**到 GitHub 镜像（那是仓库所有者的动作，不是代码改动）。
