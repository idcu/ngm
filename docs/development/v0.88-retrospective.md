# v0.88 复盘 — **把三处"说了但没人守"的地方补上网**

> 计划：[v0.88 计划](./v0.88-plan.md)
>
> 一句话结论：这一版没有新功能，三件都是**把已经说过的话变成有人守的东西**——
> 而其中两件当场抓到了真东西：**两个交付给 Windows 用户的入口脚本根本跑不了**，
> 以及自检器在**类型入口**上与产品长期各说各话。

---

## 1. A · 入口与类型：从"人工对齐"到"按声明判定"

### 1.1 四处分歧（都在 `Types` 与"存在性"这一带）

| # | v0.88 之前 | 后果 | 现在 |
|---|-----------|------|------|
| 1 | 自检器取**第一个存在的候选**；产品取**第一个声明的** | "声明了但文件不在"的包：产品用那个路径、自检器说"三层都没找到入口"——**两边都说了话，却说不清哪里不对** | 拆成两条：`entry-resolvable`（按声明，与产品同口径）+ 新增必做 `entry-file-exists`（点名缺的是哪个） |
| 2 | `types-provided` 认**任意根级 `*.d.ts`** | `foo.d.ts` 这种包：自检器说"有类型"，产品说"没有"（Go 的第 3 层只认 `index.d.ts\|d.mts\|d.cts`） | 口径与 `Entry.Types` 一致，并把路径**打印出来** |
| 3 | 路径不做规范化 | 声明 `src/x.js` 时两侧打印不同形（`src/x.js` vs `./src/x.js`）——"逐字对齐"只是话说得好听 | `rel_path` 逐字镜像 `mappings.relPath` |
| 4 | `Types` 侧**没有**机械对账（v0.87 亲手写下的已知缺口） | 下一个改 `Types` 推断的人走的是没有网的路 | 对齐网扩到 **15 种形态 ×（Main + Types）** |

### 1.2 牙齿

- **声明式 vs 存在式**：`TestV88DeclaredEntryMustExist` —— 声明 `./gone.js` ⇒ 入口判据过、存在性判据红（理由里点名路径）、exit 1；补上文件 ⇒ 两条都过、exit 0。
- **`foo.d.ts`**：把 `types-provided` 改回旧写法 ⇒ 对齐网立刻红，且报告里出现自相矛盾的一句
  `类型入口 （来自 index 约定…）`（**空路径 + "有类型"**）——正是这类分歧最难看的样子。

## 2. B · 交付物在坑里：两个 `.ps1` 根本**不能被解析**

新网 `TestV88PowerShellScriptsParse`（用 PowerShell 自己的 `[Parser]::ParseFile`）第一次跑就红：

```
--- FAIL: TestV88PowerShellScriptsParse/check-library-standard.ps1
--- FAIL: TestV88PowerShellScriptsParse/packagegate-demo.ps1
```

**根因**（实测确认，不是猜）：这批 `.ps1` 是 UTF-8，而 Windows PowerShell 5.1 在**没有 BOM** 时按 ANSI 解码；
中文在 GBK 下是双字节，**一个前导字节会把后面的换行一起吃掉**（成对消费）⇒ 代码被并进上一行 ⇒ 解析失败。

| 证据 | 结果 |
|------|------|
| 按 UTF-8 解码后解析 | **0 错** |
| 按 ANSI 解码后解析（PS 5.1 的默认） | **3 错**，第一处正是某行注释末尾 |

这两个脚本是**交付给 Windows 用户的入口**（标准页上写的就是"跑 `check-library-standard.ps1`"）——
而它们坏得很安静：Go 侧有个判据**只读它的文本**来对齐 Find-Bash 顺序，因此从没发现它跑不了。

**修**：给缺 BOM 的 5 个补 BOM。查下来 9 个 `.ps1` 里**本来就有 4 个带 BOM**——
约定其实一直是 BOM，是这 5 个漂移了。修完实跑：

```
check-library-standard.ps1 -Json  → 完整报告（ok:true，含新的 entry-file-exists）
packagegate-demo.ps1              → 5 passed, 0 failed（exit 0）
```

## 3. C · 读数要放在**会被看见**的地方

`scripts/write-readings-summary.sh`（+ `.ps1` 转调，同一条"唯一实现是 .sh"纪律）把两个源的
覆盖写成 markdown；`.github/workflows/ci.yml` 里一步 `if: always()` 贴到 job summary 页。

两条纪律各有一条牙：

- **读不出必须写"没读成"**：把 `--api-base` 指到没人听的地址 ⇒ 摘要里出现
  `⚠️ 这一段**没读成**`，而段落本身仍在（段落消失才是最坏的形态：看起来像"没问题"）；
- **`--out` 是追加**：`$GITHUB_STEP_SUMMARY` 本来就是追加写的地方，截断会抹掉同一 job 里
  别的步骤写的内容（判据先往文件里写一行"前一个步骤写的内容"再验它还在）。

脚本**永远 exit 0**（读数 ≠ 门禁，与 v0.86 一致）；只有用法错才 exit 2。
