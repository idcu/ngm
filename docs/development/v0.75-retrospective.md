> 一句话结论：写了一个**真实可用**的库 `canonical-json`（零依赖、免构建、25 个测试、

### 1.2 标准与自检器（两处修正 + 一条新判据）

| # | 修正 | 起因 |
|---|------|------|
| 1 | `ngm.json` 示例补 `schemaVersion` / `runtime`，并新增必做判据 **`ngm-json-valid`** | 我按标准写库时发现示例缺 `runtime`——而它是 ngm 清单的必填三件之一（`internal/config/validate.go`）；照抄示例的库，在 `ngm config validate` 下会直接报错 |
| 2 | LF 条款补边界："自检看**工作树字节**；Windows 上要保持 LF 检出" | 第一版文件写完是 CRLF（编辑器所致），自检当场红；而真正要保护的是**提交进仓库的字节**——这个区分必须写进标准 |
| 3 | 判据计数改为 **23 条**（12 必做常驻 + 2 条件触发 + 9 推荐） | 新增一条后，原来"22 项"的说法不再准确 |

**牙齿（实测）**：删掉库的 `ngm.json` 的 `runtime` ⇒ `✖ ngm-json-valid  ngm.json 过不了 ngm
自己的校验：runtime 必须是 node 或 deno（当前：undefined）` + **exit 1**；恢复 ⇒ exit 0。

## 3. 设计偏离登记

| # | 计划写的 | 实际做的 | 为什么 |
|---|---------|---------|-------|
| 1 | 一度想把实现放 `src/`、产物放 `dist/` | 最终**只有 `src/`**，`exports` 直接指 `./src/index.js` | 零构建 ⇒ 无需"产物目录"；多一个 `dist/` 只会制造"要同步两份代码"的假象，而标准要的恰恰是"提交什么就跑什么" |
| 2 | 类型面一度想用 TS 生成 | 手写 `.d.ts` + **机械对账测试** | 没有构建步骤，`.d.ts` 是唯一可接受的"第二处表达"；既然允许它存在，就必须有判据守着它不漂移 |
| 3 | hash 一度想支持多算法 | 只做 SHA-256 | 窄接口是刻意的：需要别的算法时应当显式引入别的库，而不是让本库变成一个"看起来能配"的面 |
| 4 | 库 README 里指向 ngm 标准页的相对路径 | 改成 gitee URL | 跨仓库的相对链接只在作者机器上成立；对任何克隆它的人都是死链 |

## 4. 缺陷清单

| # | 缺陷 | 谁发现 | 处置 |
|---|------|-------|------|
| 1 | 标准页 `ngm.json` 示例缺 `runtime`（照抄即错） | **写库时**（"照着做"是标准唯一诚实的检验方式） | 补示例 + 新增判据 `ngm-json-valid` |
| 2 | 库 README 的跨仓相对链接（`../../ngm/docs/…`） | 自查（写 README 时） | 改成 gitee URL；标准页里也据此不再用相对路径引外部仓库 |
| 3 | `assert.throws` 不返回错误（我在 4 处当它返回） | 库测试（4 个红） | 自写 `capture()` 再逐字段核对——错误对象本身也是契约 |
| 4 | 三处测试预期写错（`canonicalBytes('中')` 忘算 JSON 引号；两处 path 传了裸值） | 库测试（当场红） | 修正预期。注意 `canonicalBytes('中')` 含引号是**正确**行为——JSON 字符串的字节本来就带引号 |

## 5. 过程洞察

### 5.1 标准只有在被照着做一遍之后才算成立

v0.74 写得很"完整"，但两处关键缺陷（示例缺必填字段、LF 判定的边界）都是**照着它写库**时
才暴露的。这印证了项目里反复出现的那条：**判据的价值由它的失败证明**——
标准的价值也一样，由"第一次实现时它拦住了什么 / 漏放了什么"证明。

### 5.2 "免构建"把纪律挪到了字节层

ngm 不替依赖构建 ⇒ 仓库里提交的字节就是用户拿到的字节。于是：
- LF 不再是风格问题，而是**功能前提**（digest 对原始字节求哈希）；
- `dist/` 不存在反而是好事——没有"源码与产物可能不一致"的空间；
- CI 也不需要 install 步骤（零依赖 + 免构建，CI 跑的就是用户跑的那份文件）。

### 5.3 库自己的测试里，最值钱的是那两条"对账"

25 个测试里，真正防长期腐烂的是 `type-surface.test.js` 的两条：
**导出名双向对账**（实现 × `.d.ts`）与**入口指向真实文件**。
它们把 ngm 标准里的两条搬进了库自己的 CI——即使使用者从不知道 ngm 存在，这两条也在守着。
