# v0.88 计划 — **把三处"说了但没人守"的地方补上网**

> 来源：[v0.87 复盘](./v0.87-retrospective.md) §4 候选 2 / 3 与 v0.86 候选 3。
>
> 一句话目标：v0.87 写下的那处**已知缺口**（`Types` 没有机械对账）补上；
> 读数从"随时可再测"走到"**会被看见**"；顺带把交付给 Windows 的入口脚本纳入判据。

---

## 1. 三件（都本地可做）

| # | 项 | 验收 |
|---|----|------|
| A | **入口/类型对齐**：自检器按**声明**判定（与 `InferEntry` 同口径）、`rel_path` 逐字对齐、`types-provided` 不再接受任意根级 `.d.ts`；「有没有入口」与「入口文件在不在」拆成两条判据 | 对齐网扩到 **15 种形态 ×（Main + Types）**；牙齿：改回旧行为 ⇒ `foo.d.ts` 那条红 |
| B | **`.ps1` 必须能被 PowerShell 解析**（含非 ASCII 就必须带 UTF-8 BOM） | 网跑通；它当场抓到的两个坏脚本修好并**实跑**一次 |
| C | **读数进 CI job summary**（`$GITHUB_STEP_SUMMARY`） | 摘要两段都在；读不出必须写"没读成"；`--out` 是追加 |

## 2. 为什么是这三件

- A 是 v0.87 亲手写下的**已知缺口**：缺口不修就会变成"下一个人踩的坑"；
- B 是同一台机器上反复出现的一类坑（UTF-8/ANSI），而**交付物就在这个坑里**；
- C 是"读数 ≠ 门禁"之后的下半句：**读数还得有人看见**，否则等于没有。

## 3. 不做

- 不推 tag、不推 jsonkit（仓库所有者的动作）；
- 不动 `subPath` 端到端（等推送）；
- 不把自检器改成调用产品代码（v0.87 的判断继续成立：独立才有对账的价值）。
