# v0.55 计划 — **子命令之前的 flag 不许被静默丢弃**

> 范围来源：v0.54 探针的**新发现**（当时记进登记表的那条）。
>
> 一句话目标：`ngm --json verify` 这类写法今天**进得去、出不来**——
> token 被 `head` 吞掉，命令照常跑，用户拿到的是**人读文本**而退出码是 0。

---

## 0. 起点：先量（**必须是成功场景**）

| 调用 | 预期 |
|------|------|
| `verify --json`（对照） | exit 0 · JSON 报告 |
| `verify`（对照） | exit 0 · 人读文本 |
| `--json verify` | **关键**：它今天是静默成功、还是失败？ |
| `--bogus verify` | 未知根级 flag 的处置 |
| `-- verify` | 裸分隔符的处置 |

> 只在**有 lock 的项目**上量：空项目上 `verify` 自己也退 3，
> 那就分不出"被吞了"与"命令自己失败了"。

## 1. 判据

1. 根级未知 token 一律 `exit 3`（`--json` / 未知 flag / 带值 flag / 裸 `--` / 连子命令都没有）；
2. 用户提了 `--json` 的那个要给 **v0.54 的信封**，hint 点名"写在命令**之后**"并给例子；
3. **顺序无关**：`--version --bogus` 与 `--bogus --version` 结果一致；
4. **对照不许变**：白名单里的每个 token 仍被接受（列表**从运行时表取**）；
5. 拒绝一侧的**样本从派生 flag 表取**（`boolFlagsOfCommand`），不手写。

## 2. 验收

