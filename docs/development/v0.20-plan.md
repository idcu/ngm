# v0.20 计划 — 声明的退出码必须可核对

> 范围来源：[v0.19 复盘](./v0.19-retrospective.md) §7 候选 1 的延长线。
>
> 一句话目标：v0.19 在 9 个命令的用法文本里写下 `EXIT CODES` 段——
> 那是**声明**，不是证据。**声明会漂，而漂了不会让任何网变红。**
> 这一版把"每条声明都被一条命令盯着"变成门禁。

---

## 0. 为什么有这一版

v0.19 结束时出现了两个"看起来像待办、其实已经成立"的候选：

| 候选 | 我以为 | 实测 |
|------|--------|------|
| "缺引擎时报错要列出候选" | 报错没说有哪些可用引擎 | **它已经列了**：`(available: self, typescript)` / `(available: postcss, self)` |
| "配置错误要一致" | 各命令可能对坏目录/坏清单反应不一 | **已经一致**：21 个命令全部 exit 3 且点名路径 |

两次都是**先测量、再发现自己的候选是空的**——这本身值得记。
但它也说明：v0.19 留下的**新声明**（9 段 `EXIT CODES`）**没有任何东西核对**。
这一版就是补那个核对。

---

## 1. A 组 — 用法文本里的 `EXIT CODES` 段必须**格式正确**

每个命令的用法文本都必须有这一段，且：

- 至少声明一个码；
- 每个码都在 **0…5**（全局约定只定义这六个）；
- 同一个码不出现两次；
- 每个码都带一句说明（不是光秃秃一个数字）。

判据的**来源是运行时的命令表**（`root.go` 的 `commands`），不是另抄一份命令清单。

## 2. B 组 — 每条声明都必须有**触发命令**，且实测一致

光有段不够：段里的每个码，都要给出一条**能在离线环境里触发它**的命令，并断言实测退出码 == 声明的码。

覆盖范围（声明的码 ≥ 2 的那些）：

| 命令 | 触发的码 |
|------|---------|
| `init` / `add` / `remove` | `3`（用法错误 / 未声明） |
| `install` / `update` | `3`（`--frozen-lockfile` 且 lock 缺失或缺目标）、`4`（`--offline` 且资源不在本地） |
| `verify` / `audit` / `outdated` | `3`（lock 缺失）、`4`（`--offline` 且冷 mirror） |
| `why` | `3`（依赖不在图里） |
| `tree` | `3`（清单缺失） |
| `typecheck` / `typedecl` / `css` | `3`（没有引擎） |
| `cache` / `store` / `config` / `engines` / `mappings` / `integrations` | `3`（未知子命令） |

## 3. C 组 — 绊线：没有触发命令的声明**直接红**

```go
if !ok {
    t.Errorf("`ngm %s` declares exit code %d, but nothing triggers it — " +
        "either add the trigger or drop the claim")
}
```

这条是**本网唯一的牙齿**：它逼着"声明"要么给出可跑的触发命令，要么被删掉。
否则 `EXIT CODES` 段会变成又一处"没人看着的承诺"。

---

## 4. 明确不做

| 不做的 | 理由 |
|--------|------|
| 穷举每个命令的**全部**状态去证明"这些码只在这些状态下出现" | 那是数据流分析，不是一张网能做的事；本网只守"声明的码确实会被退出" |
| 给 `cache` / `store` 加 `--dir` | 它们操作的是**全局**层（`NGM_HOME`），与项目目录无关 |
| 改引擎默认选择 | ADR-025 已定：不设默认。报错已经可行动（列出候选） |
