# v0.50 复盘 — **"下一步"这条契约要跨通道成立**

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：从 v0.28 到 v0.49 这一系列**全部**盯着人读的输出，
> 而 `--json` 是给脚本读的。这一版把"每一条失败都要说得出下一步"这条契约
> **扩到机器那一侧**，并钉住"两个通道说同一句话"。
> 过程中最有价值的读数不是三处缺口，而是：**第一版判据的牙齿没能咬住**。

---

## 1. 逐组验收

### 1.1 先问对了问题：哪些命令有 `--json` ✅

从**派生的 flag 表**里问（`boolFlagsOfCommand`），不靠我记。

第一版探针假设"每张报告都能加 `--json`"，于是在 `install --json` 上撞到
`flag provided but not defined: -json` 与 exit 3（而人读那侧是漂移的 exit 1）——
**我差点把它当成"`--json` 改变了判定"这个缺陷**。真相是那个命令根本没有这个 flag。

### 1.2 三处真实缺口 ✅

| 报告 | 人读那侧的下一步 | 机器那侧（改前） |
|------|-----------------|-----------------|
| `audit`（公告**没有**修复版本） | `→ no fixed version is recorded …`（v0.32 加） | **没有** |
| `tree --osv`（查到漏洞） | `→ N known vulnerability(ies); run ngm audit …`（v0.32 加） | **没有** |
| `engines validate`（7 条问题） | 每条问题一行 `→ …` | **没有** |

### 1.3 一处**不是**缺口，而是刻意设计 ✅

`install`（`verifyOnLock` 撞上漂移）带 `--json` 时 **stdout 为空**、错误走人读通道——
这是 **v0.16 规则④** 写明的：*输入错误时 stdout 必须为空——"我没有报告可给"
不能用半份 JSON 表达*。

处置：改成**具名登记**（`jsonNotApplicable`，写清为什么），而不是"顺手让它也产出 JSON"。
登记与机械闸门分工明确：**命令没有 `--json`** 由源码派生的事实拦下；
**有 `--json` 却没产出**必须具名登记（否则缺口与设计分不开）。

### 1.4 处置：四个字段 + 同一条句子同源 ✅

| 报告 | 新字段 | 句子从哪来 |
|------|-------|-----------|
| `audit` | `findings[].vulnerabilities[].remediation` | `supplychain.NoFixAdvice` |
| `tree` | `remediation`（顶层） | `observability.VulnRemediation` |
| `engines validate` | `issues[].remediation` | `cmd/ngm.issueAdvice` |
| `verify` | （v0.32 起就有 `remediation`） | — |

**同一条句子、两处同源**是刻意的：同一条报告不该在两个通道里说不同的话。

### 1.5 牙齿：**第一版没能咬住** ✅（这一版最值钱的读数）

- 第一版判据是"body 里含 `"remediation"` 或 `"fixedIn"` 即可"。
- 牙齿（抽掉 `tree` 报告的顶层 `remediation`）——**没有咬住** ✗：
  因为条目级的 vuln 字段还在，粗判据照样绿。

> 这正是 v0.47 那条教训的复现：**绿不等于它在盯着什么。**

改成**内容级**判据：人读的每一条行动行，剥掉 `→` / `driftKind: …;` / `Fixed in: `
前后缀之后，那句话**必须逐字出现在 JSON 里**。改完之后牙齿咬住了。

而内容级判据又带出**两处我的问题**（都不是产品）：

1. **两次 run 各自 isolate 到不同的 home**——建议里印着那个绝对路径，
   于是两边对不上（同族第三次：v0.45 印绝对路径 · v0.47 hint 里的 home · 这一版）。
   处置：**两边都归一化**，且 JSON 那侧要按**转义后**的形态替换。
2. **`json.Marshal` 会转义 HTML**（`\u003c`），而产品的编码器不转义——
   针与正文对不上。处置：用 `Encoder.SetEscapeHTML(false)` 与产品对齐。

### 1.6 一处红是**好的红** ✅

`TestV26EveryFieldOfTheReportIsDocumented`（v0.26：报告里每个字段都必须有文档）
抓到 `TreeReport.remediation` 没进 `docs/guides/cli.md` 的形状表 ⇒ 补文档
（并顺手把三个新字段的说明写成一节）。

**这正是那张网存在的理由**：新字段不会悄悄溜进 JSON。

## 5. 过程洞察

### 5.1 牙齿咬不住时，先怀疑判据

"抽掉一处实现 ⇒ 判据必须红"是这一系列每版都做的一步。
这一版它给出的答案不是"产品没问题"，而是**"这条判据有问题"**：

- 判据问的是"有没有某个字段" ✗ 太粗（条目级字段会替报告级字段交差）
- 改成"那句话在不在" ✗✓ 才对得上契约本身（**两个通道说同一句话**）

> 判据的**形式**要贴着契约的**句子**写，而不是贴着实现的**字段名**写。

### 5.2 "跨通道一致"是这一系列一直缺的那一维

前 22 版（v0.28 ~ v0.49）都在打磨人读输出；机器那一侧只有一个 v0.16 的
"报告不能说谎"契约（退出码、恰好一份 JSON）。这一版补上的是
**"两个通道说同一件事、同一句话"**——它比"JSON 合法"强，也比"字段存在"强。

### 5.3 第三次同一个形状：隔离出来的路径跑进输出

v0.45（`store prune` 印绝对路径）· v0.47（hint 里的 home）· v0.50（两通道各一次 run）。
每次都是"两次运行各有各的 temp 目录，而输出里印了它"。

**纪律（已经在候选里挂着，这一版又踩了一次）**：
归一化清单要从"**输出里出现过什么**"反推，而不是从"我以为会变什么"正推。
