# v0.65 复盘 — **矩阵的每一列都要有自己的证据**

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：这条守卫**当场抓到两处夹具**——它们**没有测到名字里写的那个缺陷** ✗：
> 两条清单都停在更早的 `version is required` 上，于是两列的输出**逐格完全相同**。

---

## 1. 逐组验收

### 1.1 V37：命名的轴 + 每列的证据

`configErrorShapes`（8 列）从测试函数里提出来 ✓，每一列被要求：

| # | 断言 | 说明 |
|---|------|------|
| ① | 至少有一格**走到配置层**（不是全退 0 / 全用法 / 全静默） | 防止"新增一列而它什么都没测到" |
| ② | 签名（每格"通道 + 整份**归一化**输出"）**不与其他列相同** | 等价只能在 `shapeEquivalents` 里具名说明 |

签名的两个设计细节都是被实测逼出来的：

- **不能用首行** ✗：五种"清单有问题"的形状首行**完全一样**（`ConfigInvalid: invalid <path>\ngm.json`），
  区分点在后面的行 ⇒ 改成**整份输出**；
- **必须归一化**：签名里不能留有这一轮自己造的临时路径（v0.43 那课，v0.51 已收成 `normalizeRunPaths`）。

### 1.2 **本版的主要发现**：两列其实什么都没测到 ✗

第一次运行，守卫报出的不是"新增的噪声"，而是**既有的两列**：

```
形状 "manifest-with-a-dependency-without-a-name" 与 "manifest-with-an-unknown-runtime"
的**每一格**输出都完全相同
```

查下去，真相是**夹具缺必填字段**：`validate.go` 要求 `name` **且** `version`，
而这两条夹具都没写 `version` ⇒ 它们都停在更早的 `version is required` 上 ✗
⇒ **谁都没有测到名字里写的那个缺陷**（未知 runtime / 无名依赖）。

处置：**修夹具**（补上 `version` 与 `name`）✓ —— 再跑，8 列各有各的证据 ✓。

> 这正是"新增即红"想要的东西：它不只拦新来的噪声，还能**把已有的噪声照出来**；
> 而噪声的表现就是"覆盖数字很好看、实际上什么都没测到"。

### 1.3 V39：命名的维度 + 自带契约

`argumentDimensions` 从循环里的字面量提成命名变量 ✓，每个维度带一句 `wants`
（`-v` 时打印出来："这一轴现在主张什么" ✓）。另有计数下限守卫（`< 2` ⇒ Fatal ✓）。

### 1.4 牙齿 ✅（如实记两道的强弱）

| 探针 | 判据说了什么 | 评价 |
|------|------------|------|
| 把 `no-manifest` 的夹具换成**合法项目** | 红在**exit-0 登记**那条（`` `ngm install` exited 0 in 1 run(s) and nothing here says why ``） | ⚠️ 我的"至少一格走到配置层"那一半**没响**——因为该列仍有命令走到配置层。**这一半很弱**（对"半坏"的夹具恒真），它的价值只在"整列全 OK/全用法"时发出声音 |
| 两列逐格相同 | 红：`形状 … 与 … 的**每一格**输出都完全相同` | ✅ **真的抓到了东西**（见 §1.2）——这是本版的主力 |

## 5. 过程洞察

### 5.1 "覆盖数字"与"覆盖证据"是两件事

V37 从前能报出"21 × 8 = 168 格"这样的数字 ✓，而**两列是空的** ✗。
这一版把"每一列要有自己的证据"变成断言之后，数字没变、**内容变了** ✓。

> 与 v0.53（"逐条计数"）、v0.63（"登记要落地"）、v0.64（"清单要有来源"）同族：
> **形状好看 ≠ 真的在查**。

### 5.2 守卫的第一批猎物通常不是新来的

这条守卫是为"新增一列"写的，而它第一次跑就抓到了**两列旧的** ✗——
修好之后它才是"网的网"。**先拿它照一遍现状**，比等它拦新东西更值。

### 5.3 知道自己哪一半弱

两道断言里，"不等价"那一半硬、"至少一格走到配置层"那一半软 ✗——
软的那一半留在代码里，但**注释与复盘都写明它软在哪、什么时候才会有声音** ✓。
不做"两条并排写、看起来一样强"的假对称 ✓。
