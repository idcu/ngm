## A — 四项决策

| # | 决策 | 结论 | 文档 |
|---|------|------|------|
| 1 | `remote` adapter 是否投入 | **搁置**（触发条件：真实需求 / 本地算力证据 / 跨生态标准） | [ADR-020](../../docs/adr/adr-020-remote-adapter-shelved.md) |
| 2 | `symlink` 落地模式是否恢复 | **保留降级**（触发条件：具体的工具要求 + 实测数字） | [ADR-021](../../docs/adr/adr-021-symlink-link-mode.md) |
| 3 | verify 的性能目标 | **次数门禁 + 秒数观测**（3s 不再是验收目标） | [ADR-022](../../docs/adr/adr-022-verify-performance-target.md) |
| 4 | blob 回收是否做 | **做**，但只做"无人引用的字节"：`store prune --orphans` | [ADR-023](../../docs/adr/adr-023-orphan-reclaim.md) |

**决策 1 的关键新事实**（它改变了判断的性质）：`remote` adapter 在代码里**不存在**
（`AdapterRemote` 只产出"按决定排除 → exit 5"）。因此"发布它"= **从零写一套远端执行协议**，
不是打开开关——比 ADR-013/017 写作时的假设贵一个量级。

**决策 4 的关键洞察**：ADR-018 卡住的原因是"按**可达性**删除需要一个项目注册表"，
而**孤儿不需要**——"本 store 里没有任何清单引用它"是由构造可判定的事实。

### A4 的实现要点（`ngm store prune --orphans`）

- [x] 判据单点：`scanManifests` 汇总引用关系，`usage` 与回收**共用**（两处各写一份判断，
      后果不是数字对不上，而是**删掉还有人要的字节**）。
- [x] 年龄门槛（默认 24h）：`Put` 先写 blob、后发布清单 → 刚写下的东西一律不动。
- [x] **有清单读不出来时拒绝删除**（含 `--dry-run`）：那时"无人引用"只是下界。
- [x] 默认行为一字不变：不带 `--orphans` 时 `prune` 与 v0.7 完全一致。
- [x] 输出含安全声明：删了几个、释放多少、留下多少（年轻）、多少被引用的没动。
- [x] 验收：`internal/vendor` 四条（含安全阀与 dry-run）+ `cmd/ngm` 五条（含"默认一个字节都不动"）。

## B — workflow 的 YAML 门禁

**缺口**：`.github/workflows/*.yml` 没有任何检查。改坏一个文件（缩进、重复键）的后果是
**GitHub 不创建 run**——没有红、没有日志，只有"以后再也不跑"。这在 v0.8 收尾改过
`release.yml` 之后不是假想风险。

- [x] B1 判据用**真实解析器**（`npx js-yaml`），不自己写近似校验器——
      会误报的门禁会被忽略，会漏报的门禁等于没有（v0.8 复盘 §5.8）。
- [x] B2 三个 workflow 文件全部解析（本地已验证）；CI 里作为独立 job。
- [x] B3 写明这条门禁的**代价**：它依赖 npm registry（首次 `npx` 要下载）。
      网络失败会表现为一个带 npm 报错的红色 job——**与"YAML 坏了"可区分**。

## C — 端到端可用性复核

在一个干净目录里当一次用户：`init` → `add`（真实 Git 依赖）→ `install` → `verify` →
`build`（真实 esbuild）→ `store usage`。**记录摩擦点**（不是找 bug 的替代品，是补充）。

- [x] C1 跑通最小闭环，记录每步耗时与输出 → 6 步全通：`install` 2.32s / `verify` 0.81s /
      `build` 0.66s（真实 esbuild 0.28.2），另加验了 `--frozen-lockfile --offline`
- [x] C2 记录**摩擦点** → **3 个**（见复盘 §4）：D1 非默认端口被丢弃（已知限制）·
      D2 `store usage` 孤儿提示与本版自相矛盾（已修）· D3 状态页的 `add --ref=` 写法从来跑不通（已修）
- [x] C3 结论进复盘：哪些该改、哪些是有意的 → 复盘 §4.1（权限门禁四次是**有意**的）·
      §4.2（D1 为何"已知限制"优于"悄悄支持一半"）· §5.1（内部一致性检查证明不了"对外能用"）

> **本组的最大产出不是"跑通了"，而是抓到了三个问题**——
> 而它们在锚点检查、链接检查、单测、门禁**全部通过**时依然存在。
