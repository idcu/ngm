# v0.34 复盘 — 建议要**承认失败的形状**

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：v0.33 的判据是"行动行必须点名一个**真能执行**的东西"，
> 而这一版把**失败的性质**也写进判据。立判据的过程中实测到一处**真实产品缺陷**：
> `verify` 的"检查未能完成"那一支**算好了建议又把它丢掉**——
> 用户看到 `✗ … — check incomplete`（exit 4），看不到任何下一步。

---

## 1. 逐组验收

### 1.1 形状 ↔ 解法（8 条用例，全部命中）✅

| 失败形状 | 用例 | 命中的解法 |
|---------|------|-----------|
| 落地完整性失败（critical） | `verify` / 树被删 · 字节被改 | `ngm install` ×2 |
| 漂移（unexpected） | `verify` / tag 被挪走 · `install` / verifyOnLock | `ngm update` ×2 |
| **检查未能完成** | **`verify --offline` / mirror 不在（本版新增）** | `ngm install` |
| 漏洞（无修复版本） | `audit` | `supplyChain.osvIgnoreSeverities` |
| 漏洞（有修复版本） | `audit` | `Fixed in:` |
| `tree --osv` 看到漏洞 | `tree` | `ngm audit` |

读数：**8 条用例 · 8 行动行 · 5 种不同解法**。

### 1.2 牙齿 ✅

| 探针 | 结果 |
|------|------|
| **把 critical 的建议改指向 `ngm audit`**（一个**真实存在**但文不对题的命令） | **v0.33 放行**（它确实是真命令）、**v0.34 红**：`this next-step line does not match **this** failure's shape (expected one of [`ngm install`])` |
| 把渲染门退回旧形状 | v0.32 精确报出那一条：`this report has 1 failing item(s) but only 0 next-step line(s)` |

第一行**正是这一版存在的理由**：两张网的差别就落在这一个格子上。

## 5. 过程洞察

### 5.1 "算好了又丢掉"是这一族的通名

v0.28 修的是**包装时丢掉建议**；这一版修的是**渲染的门把它拦住**。两次的产品代码都是"一行条件写窄了"：

```go
if d.DriftKind != verify.DriftNone && d.Remediation != "" {   // ← 门太窄
```

而两次能发现，都不是因为有人重读那行代码，是因为**有一条判据在问"用户到底看到了什么"**。

这一族的其它名字：v0.29 的"用户层 11 处没有下一步"、v0.32 的"audit 无修复版本时不说话"。
**共同点：产品里有信息，用户手里没有。**

### 5.2 一条建议，两种成因

`res.Err != ""` 覆盖了实测到的两种成因（mirror 不在 / 网络被权限拒），
而它们**真正该做的事不同**：

- mirror 不在 ⇒ `ngm install` 会把它取下来（这条建议对）；
- 网络被**策略**拒 ⇒ `ngm install` 也会被拒——真正的下一步是改策略里的 `net:<host>`。

我给的是一套覆盖两者的话（两条命令都真实存在）。这是**取舍**，不是缺陷：
按成因分派需要把错误码穿到 `remediationFor`（它现在只拿到 `DepResult` 的字符串 `Err`）。
**记成候选**：若某天它变成高频路径，就该按成因分派。

### 5.3 又一次"我的工具在骗我"：`echo` 掩盖了 gofmt 的红

`gofmt -l .` 报了 `cmd/ngm/failure_shape_test.go` 未格式化，而我在同一条命令里紧跟着
`echo "gofmt-clean"`——**输出里那一行红被固定的那句绿盖住了**，
我差点按"格式化干净"继续往下走。

同一条命令里还有一次：牙齿 A 第一次跑时**没有任何输出**，因为我的 `Select-String`
把**编译错误**一起滤掉了——而那次替换确实把文件改坏了。
"过滤成功不等于构建成功"这条我在整套测试上一直守着，却在**牙齿脚本**上犯了两次。

处置：格式化检查改成**看结果再决定打印什么**（`if ([string]::IsNullOrWhiteSpace($out))`），
牙齿脚本改成先看 `exit` 与原始输出，再谈滤出的那一行。

### 5.4 判据能"承认形状"之后，弱的那一半反而更清楚了

v0.33 能说"这句话点名了一个真东西"，v0.34 能说"这句话点的是**这一类**该指的方向"。
但两张网合起来仍然判不出：**建议的措辞对人是否清楚**、**是否遗漏了更重要的下一步**。

这不是自我否定——把边界写在明处，下一版才知道往哪儿推：
**能被机械化的部分，已经被推到了"形状"这一层**；再往前（因果、优先级）目前没有判据。
