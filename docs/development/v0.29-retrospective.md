# v0.29 复盘 — 第一次上手的错误必须有下一步

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：v0.28 把用户层的空 hint 钉成棘轮（11/47）时判断"有些错误没法更好"。
> 这一版**逐条看过那 11 处**——每一处都能写出真实的下一步，
> 于是棘轮收紧成**硬门禁（0/47）**，并加一张端到端的网证明建议真的到得了用户眼前。

## 1. 逐组验收

### 1.1 判断的翻案 ✅

v0.28 的理由是"有些错误确实没有比'它不存在'更有用的下一步"。
**这句话没有被验证过**。逐条打开后，11 处的真身全部是**可归因的失败**：

| 位置 | 能写的下一步 |
|------|------------|
| `--dir` 解析失败 ×5 | 传绝对 `--dir`，或从目标目录运行 |
| `init` 建目录 / 建 `src` / 写清单 / 写入口 ×4 | 检查可写性；**并说清"已经写了什么、没写什么"** |
| `add` 依赖定义非法 | 给出 slug 形状与 `--help` |
| `transform` 建输出目录失败 | 指向可写的 `--outdir` |

### 1.2 A 组 — 两条写法纪律 ✅

- `init` 的失败**说清已经发生了什么**：写 `ngm.json` 失败时提示
  "目录已建、`ngm.json` 没写成"；写入口文件失败时提示
  "`ngm.json` 写了、入口文件没写"。用户下一步的动作取决于这个事实，
  一句泛泛的"检查权限"给不出来。
- 不写"请检查日志"这类**没有动作**的建议。

### 1.3 B 组 — 棘轮 → 硬门禁 ✅

```
user-facing error sites: 47, empty hint: 0 (ceiling 0)
```

### 1.4 C 组 — 端到端对照 ✅

静态网只证明"源码里写了 hint"。端到端那张让 `ngm init` **真撞一次建不出来的路径**
（父路径是**文件**，`MkdirAll` 必失败）：

- 退出码 **3** ✓
- 输出里有 `hint:` ✓
- 提示指向可归因的线索（可写性）✓
- **没有谎报 `created`** ✓（入口都没建出来，就不许说建了）

### 1.5 读数 ✅

## 5. 过程洞察

### 5.1 "没法更好"这种结论，也得逐条看过才能下

v0.28 的棘轮值 11 是**一次判断**，它写下来时带着一个理由。
这一版把那个理由**验证了一遍**：11 处全是可归因的失败，全部能写建议。

**"有些情况没法更好"最容易变成省事的挡箭牌**——它听上去总是对的，
因为它不需要证据。逐条看一遍的成本并不高（11 处），却能把它变成 0。

### 5.2 网在看着网的文档

D2 很有意思：**v0.27 立的那张散文网，抓到了 v0.28 自己写的登记文本。**
这不是误报——那行确实把 `--json`（机器接口）与 `errors.As`（Go API）混在一起写。
判据的假设是"提到 `--json` 的行里，反引号驼峰标识符是字段名"，
而修法是**改措辞**，不是放宽判据。

**项目的文档已经密到"新写的登记文本会被老网看着"**——这是意外收获，也是提醒：
写登记时同样要遵守文档自己的写法纪律。

### 5.3 棘轮与硬门禁是两种不同的表达

| 形态 | 它说的是 |
|------|---------|
| **棘轮**（上限 = 当前读数） | "**这里有已知的洞**，但不许变大" |
| **硬门禁**（上限 = 0） | "**这件事做完了**" |

从棘轮到硬门禁不是调个数字，而是**一次判断的翻案**。所以这次改动同时改了注释，
把翻案的理由留在原地——下一个看到 `const emptyHintCeiling = 0` 的人，
应该能读到"为什么曾经是 11、又为什么变成 0"。
