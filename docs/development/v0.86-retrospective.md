# v0.86 复盘 — **镜像覆盖：从写死的快照到按需实测**

> 计划：[v0.86 计划](./v0.86-plan.md)
>
> 一句话结论：文档里的"GitHub 有 65 个 tag"这一类数字**仍是快照**，
> 但现在多了一条随时可再测的路：两次请求得到镜像的真实覆盖与"未推送"。
> 它是**读数不是门禁**——这是 v0.85 那条教训（软硬由语境决定）的第二处应用。

---

## 1. 交付

### 1.1 `scripts/check-mirror-coverage.sh`（+ `.ps1` 转调同一实现）

```
mirror coverage (live reading — the written-down numbers in docs/ are snapshots of this):
  local: delivered 86 version(s), newest v0.86
  mirror (GitHub idcu/ngm): 65 tag(s), 60 release(s), newest release v0.64.0
  UNPUSHED: 21 tag(s)  (= delivered 86 − mirror 65)
  note: 推送是仓库所有者的动作；这条命令只报数，不判失败（读数 ≠ 门禁）
  hint: git push origin main --tags
```

两次请求：`/git/refs/tags`（一次给全，不翻页）与 `/releases?per_page=100`。
**退出码语义**：0 = 读到了（哪怕有缺口）· 3 = 问不到（HTTP 非 200 / 连不上 / 仓库不明），
且 3 的路径上**明说"不下结论"**——"读数"也不许在读不到时装作读到了。

### 1.2 接入 CI（`release-state` job）

`continue-on-error: true`，与 §1.1 同一条理由：缺口不该让流水线变红，
"问不到"也不该把一条与本次改动无关的流水线拖红（它的输出里写着拒绝下结论）。
**放 CI 页面上**的收益是：两个源的覆盖不再是"某次会话里读过一次"。

### 1.3 判据抓到的一处实现缺陷（本版最值得记的一条）

第一版脚本按**行数**数 JSON（`awk '/"ref"/ {n++}'`）——真实 API 是美化输出，
所以本机试跑完全正确。判据里的**假 API** 回的是**紧凑 JSON**（合法响应 ✗ 不是"格式不符"），
于是 65 个 tag 被数成 **1** ✗，判据当场红。

处置：改按**出现次数**数（`gsub`），两种形态都对；并在脚本注释里写明这次教训。

> 一般的话：**"本机跑通"常常等于"只跑过一种形态"。**
> 判据给一个**自己造的**输入（而不是真实服务的默认输出），才发现脚本依赖了一个**从未声明的契约**。
