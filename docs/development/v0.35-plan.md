# v0.35 计划 — 建议要承认**成因**

> 范围来源：[v0.34 复盘](./v0.34-retrospective.md) §5.2 与 §7 候选 1。
>
> 一句话目标：`remediationFor` 里 `res.Err != ""` 是**一支**，但它覆盖了**成因完全不同**的失败。
> v0.34 给它们同一句话——而对"网络被策略拒"，那句话是**错的**。
> 这一版让**最贴近成因的那一层**写下的话送到用户眼前。

---

## 0. 实测到的两种成因（同一个分支）

| 成因 | 报错 | v0.34 给的建议 | 正确的是什么 |
|------|------|--------------|------------|
| mirror 不在（`--offline` 冷启动） | `GitFetch: --offline: no local mirror for github:x/dep` | `run \`ngm install\` …` | ✅ 对（`ngm install` 会把 mirror 取下来） |
| 网络被**策略**拒 | `ConfigInvalid: permission denied: net:github.com` | 同上 | ❌ **错**——`ngm install` 也会被拒；真正的一步是往 `permissions.allow` 里加 `net:github.com` |

第二行的那句话，**产品早在构造错误时就写好了**（权限层）：

```
add "net:github.com" to `permissions.allow` in ~/.ngm/config.json
```

而 `res.Err = merr.Error()` **只留 message**，把它丢了。

## 1. 判据

**同一个分支覆盖的不同成因，必须拿到各自承认成因的建议，且两句话不相同。**

依据与 v0.28 同源：**建议沿包装链找第一句非空的**——最贴近成因的那一层最知道该怎么办，
`remediationFor` **猜不出来**。

## 2. 要修的两处（都已取证）

1. **建议被字符串化丢掉**：`res.Err = merr.Error()` / `res.Err = derr.Error()` 只留 message；
2. **死赋值**：`internal/verify/verify.go` 的 Offline 分支里
   `derr = errs.New(…, "the local mirror is cold; run once without --offline …")`
   —— 下一句就离开这个分支，**写了却没人读**。`go vet` 不看这种（`ineffassign` 会）。

修法：`errs.Hint(err)` 导出（与 `FormatHuman` 共用 `inheritedHint`）+ `DepResult.ErrHint` +
`remediationFor` 优先用它。
