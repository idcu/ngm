# v0.14 计划 — 把"文档承诺"与实测行为对账

> 范围来源：[v0.13 复盘](./v0.13-retrospective.md) §7 候选 #4（"继续找没人检查的角落"，
> 但它自己提醒：下一轮应当先问**"还有哪一类形状没有网"**，而不是再扫一遍代码）。
>
> 一句话目标：**给"文档说的默认行为"与"实现真的会做的事"对一次账**，
> 并把由此暴露的最后两类形状变成网。
>
> 本版**不改产品行为**（非测试代码 0 行改动）：改的是**文档**与**网**。

---

## 0. 为什么有这一版

v0.13 的结论是"边际递减的信号已经出现：一轮扫描没找到新的产品缺陷"。
于是本版换了个方向——不问"代码里还有什么错"，而问
**"文档承诺了什么，而实现做的是另一件事"**。一次就抓到一处**成片**的不一致：
三份文档加一份指南的示例，都建立在"`ngm typecheck` / `ngm css` 内置、装了就能用"
这个**不成立**的前提上。

---

## 1. A 组 — 文档与实测行为对账

| # | 文档说的 | 实测（可复跑） | 处置 |
|---|---------|---------------|------|
| A1 | `docs/README`："`ngm typecheck` 内置 `typescript`（tsc，装了就能用）；`ngm css` 内置 `esbuild` 与 `postcss`" | `typecheck` / `css` **未声明**时都是 `exit 3`（`no engine configured for …`）；而内置的**默认选择**只覆盖 `bundle` / `transform` | 改为实测表：哪些 kind 有内置默认、哪些必须声明；并点明它是"**在清单里** ≠ **会被自动选中**"的混淆 |
| A2 | `cli.md` 的 css 行：`v0.1（esbuild）` | `ngm css --engine=esbuild` → **no css engine named esbuild**（可用：postcss、self）——esbuild **从来不是** css 引擎 | 改为 `postcss` + 写明"需要声明" |
| A3 | `capability-matrix.md`：CSS/SCSS 一栏 `postcss / esbuild` | 同上 | 改为 `postcss` |
| A4 | `build.md`「esbuild 不做类型检查」的示例给的是 `EngineNotFound`（`exit 5`） | **未声明时是 `exit 3`**（`--engine` 的名字是**按 kind 查**的）；**声明为 typeCheck 条目之后**才是 `exit 5` | 补上前提，两段都给，并说明两个退出码的**修法不同**（改名字 vs 换引擎） |

**为什么这是缺陷而不是措辞**：按 A1 照做的用户会直接跑 `ngm typecheck`，拿到 `exit 3`，
然后去 `npm i -g typescript`——那不会解决问题。文档把他送向了错误的修复方向，
与 v0.11 D1（"报错指向网络连通性"）同族。

## 2. B 组 — 三张网（把形状钉住）

| # | 形状 | 网 | 陪衬（缺了网就不成立） |
|---|------|----|----------------------|
| B1 | **dry-run / 只读命令偷偷写盘** | `TestV14DryRunAndReadOnlyCommandsWriteNothing`：项目目录 + ngm home 的**快照比对**，覆盖 8 条带 `--dry-run` 的命令与 4 条只读命令 | ①每条都要"走到了那条分支"（输出里有 `would bundle` 这类措辞）；②`store prune` 的残骸**先造出来、再证明真能清掉**；③**对照**：一条不带 `--dry-run` 的 `add` 必须改变快照 |
| B2 | **"在清单里"被读成"会被自动选中"** | `TestV14EngineKindsWithoutBuiltinDefaultNeedDeclaration`：bundle 有默认；typeCheck / typeDecl / css 未声明 = `exit 3`；`--engine=esbuild` 做 css = `exit 3`；**声明之后**用 esbuild 做 typeCheck = `exit 5` | 同一命令在"未声明 / 已声明"两种清单下的**两个不同退出码**互为对照 |
| B3 | **flag 注册了却没人读**（v0.5 的 `--concurrency` 就是这个形状） | `TestV14EveryFlagBindingIsDereferenced`：注册时丢弃（`_ = fs.String(...)`）与绑定后从不解引用，两条规则都报 | 已用两个探针证明会红；判据的代价（**会漏报**：指针整体传出去时看不见）写在注释里 |

**三张网的共同点**：判据都取自**运行结果或可枚举的源码事实**，没有一条依赖"看起来对"。

---

## 3. 明确不做（本版范围外）

| 不做的 | 理由 |
|--------|------|
| 给 `typeCheck` / `typeDecl` / `css` 加"内置默认选择" | 那是**行为变更**：会把"未声明"从 `exit 3`（缺配置，提示写哪个键）变成 `exit 5`（引擎没装）。文档写得含糊，但不能靠改行为去迁就它——**要改先立 ADR**，并说清哪个退出码对用户更有用 |
| 补发历史版本 | ⏸️ 已暂缓（见[发布清单](./README.md#发布清单每个版本)） |
| Gitee 读数进 CI | 已记为不做并写明触发条件（发布清单第 6 步） |
| 非默认端口的真正支持 | 等真实需求（schema 级变更） |

## 4. 验收

```bash
go build ./... && go vet ./... && gofmt -l .
go test -count=1 -run 'TestV14' ./cmd/ngm
bash scripts/check-docs-links.sh      # 本机可跑（Git for Windows 自带 bash）
go test -count=1 -run 'TestDocsAnchorsResolve' -v ./cmd/ngm
```

- 三张网都要**证明过会红**（探针 / 对照），不是"跑起来是绿的"
- A 组的每一句更正都要能由一条命令复现（`ngm engines list` 与 `ngm <cmd> --engine=…`）
