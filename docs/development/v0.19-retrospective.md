# v0.19 复盘 — 用户看到的文本也是接口

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 范围来源：[v0.18 复盘](./v0.18-retrospective.md) §7 候选 1（联网复核）——
> 本版不是复核本身，而是**复核时顺手抓到的那条**：
> `ngm config validate` 在没有 `ngm.json` 的目录里**照样打印 `ngm.json OK`**。
>
> 一句话结论：**退出码与措辞，是脚本与人分别读到的那一份契约。**
> 这一版把它补齐、说准，并配上机械网。

## 1. 逐组验收

### 1.1 A 组 — 每个命令都写出自己的退出码（8 个新增 + 1 个修正）

| 命令 | 之前 | 现在 |
|------|------|------|
| `init` | 无 | `0` / `3` |
| `add` | 无 | `0` / `3` |
| `update` | 无 | `0` / `1` / `2` / `3` / `4` / `5` |
| `remove` | 无 | `0` / `3` |
| `mappings` | 无 | `0` / `3` |
| `cache` | 无 | `0` / `3` |
| `store` | 无 | `0` / `3` |
| `config` | 无 | `0` / `3` |
| **`install`** | **`0` / `3` / `4`（漏了 2 与 5）** | `0` / `1` / `2` / `3` / `4` / `5` |

`install` 那一段漏掉的两个码都有据，不是"感觉应该有"：
- **2**：`postinstall.go:217,221` —— 依赖自检钩子失败/超时即 exit 2（与 digest 不匹配同级，ADR-012 决策）；`links.go:132` / `content.go:220` 是落地侧的同级护栏。
- **5**：`security.FindDeno()` 失败即 exit 5 —— 有钩子而没有 Deno 时属"引擎不可用"。

配套的机械网 `TestV19EveryCommandDocumentsItsExitCodes`
现在对 **21 个命令**全部断言"有 `EXIT CODES` 段且段内有至少一行 `<0-5> <说明>` —— **一次性覆盖**（v0.19 之前是 13/21）。

### 1.2 B 组 — `ngm config` 的三处缺陷

| # | 缺陷 | 处置 |
|---|------|------|
| ① | `--dir` 不存在：只认进程 CWD | 加上 `--dir`（默认 `.`，与其余命令一致） |
| ② | 多余位置参数被静默丢弃 | 改为 `NArg() != 1` → 用法 + exit 3 |
| ③ | 没有 `ngm.json` 时照样打印 `ngm.json OK` | 改为 exit 3 并点名是哪个目录 |

**修复前的实测**（探针输出，见 §4）：

```
config validate --dir=<有坏 ngm.json 的目录>   exit=0   ngm.json OK
```

这一行意味着：**在 CI 里最常见的误用——在错的目录里跑 `ngm config validate`——会拿到绿色**。
三处都不是"功能缺失"，合起来却是一次**假通过**；而假通过比直接报错更糟：
它让做错的人以为自己做对了。
这正是本项目存在要防的那类东西。

### 1.3 C 组 — 内部阶段标签（`M\d`）

`M0…M7` 是项目**内部**的里程碑编号，用户从没听说过。此前它泄漏到**两处**用户可见的字符串：

| 位置 | 内容 | 处置 |
|---|---|---|
| `cmd/ngm/add.go:137` | `next: run \`ngm install\` to resolve and lock (M3)` | 去掉 `(M3)` |
| `cmd/ngm/update.go:34-35` | `M1 阶段本命令完成…；ngm.lock 的写入属于 M3` | 重写为今天的实际行为 |

其中 `update` 那句**还是错的**：它宣称 lock 写入属于别的阶段，而 update 今天就写 lock。
**"过时"比"缺失"更危险**——缺失只是没说，过时是**说错了一条事实**，
读它的人会据此做出错误判断。

### 1.4 D 组 — 引擎默认：从"待决"变成"决定"

| 问题 | 决定 |
|---|---|
| `typecheck` / `typedecl` / `css` 缺声明时，要不要"目录里恰好只有一个可用引擎就默认选它"？ | **不设内置默认**（[ADR-025](../adr/adr-025-no-builtin-engine-defaults.md)） |

一句话理由：**默认一旦由"机器上装了什么"决定，就会在没有人改任何文件的情况下改变行为**——
这与 [ADR-018](../adr/adr-018-store-reclaim.md) 拒掉可达性删除是同一个形状。

## 3. 设计偏离登记

| # | 计划写的 | 实际做的 | 为什么 |
|---|---------|---------|-------|
| 1 | D 组：解决"要不要内置默认引擎" | 写成 ADR，并**不改行为** | **"挂着的待决项"本身就是缺陷**：没决定 = 没人负责。把它写成带重开条件的决定，等于把它从"没人管"变成"有据可依" |
| 2 | B 组只打算修措辞 | 结果补了一个**新增能力**（`--dir`） | "测试只能靠 `chdir` 绕过"不是措辞问题，是**能力缺失的信号**；看到绕绕就绕过去的那一刻就该补 |
| 3 | C 组的网扫全仓库 | 只扫**非测试**文件的**字符串字面量**（`go/scanner`） | **判据取窄是刻意的**：注释里合法出现 `M\d`（设计记录），但若把禁区扩到注释就会误报——**会误报的门禁会被忽略** |
| 4 | 统一 JSON 形状（v0.16 记过） | 不动 | 破坏性变更，要另立决定；本版只补"退出码与措辞" |

## 5. 过程洞察

### 5.1 待决项不决定，本身就是缺陷

"引擎要不要内置默认"挂了两版，每版复盘都写"待决"。**写"待决"不等于处理了它**：
它还在那里，而且没人负责。本版把它写成 ADR。意义不在"解决了"，
而在**它现在是一个有据可依的结论，而不是一个没人管的问题**。

### 5.2 绕过去的那一刻，就该补上

`config` 缺 `--dir`，于是测试只能 `chdir`；v0.15 的探针也照绕；
一整条绕过链就此悄悄成立，直到有人**不绕**（联网复核）才发现：
**绕过去的动作本身就是问题**。

### 5.3 内部标签泄漏 = 两个世界没隔开

`M\d` 只在项目内部有意义。它出现在打印给用户看的字符串里，
说明"内部标记"与"对外措辞"被当成了同一件事。
**同一份东西不该有第二个读者理解不了的记号。**

### 5.4 过时比缺失更危险

`update` 那句"lock 写入属于 M3"不仅过时，而且**错**。
缺失只是没说，过时是**说错了一条事实**。

### 5.5 先测量，再决定要不要动手（第三次）

v0.18 的复核本不打算找缺陷，只想量一条路径；结果测量本身成了发现。
本版动手前也先量了：`2` 与 `5` 都有代码路径与既有测试支撑。
**没有测量就动手，就是把想象写成契约**——这条纪律在本项目已第三次起作用。
