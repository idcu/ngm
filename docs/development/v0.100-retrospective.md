# v0.100 复盘 — **层 1 的两笔看不见的账**

> 计划：[v0.100 计划](./v0.100-plan.md)
> 一句话结论：**"提交多"几乎不是成本来源**——实测一个真实 JS 库（6181 个提交 / 3982 个 ref）
> 的全量 mirror 是 18.41 MiB，而它最新一版的源码是 694 KiB，两者相差约 26 倍；
> 但真正白占磁盘的是两笔**此前谁也看不见**的账：**非默认分支的 ref 所带的对象（约 40%）**
> 与**被中断的克隆留下的临时包**（本机实测到一个 66.82 MiB 的，一个字节都不是历史）。
> 后者这一版收掉了，前者是一个**写在 ADR 里的拒绝**。

---

## 1. 取证

三个读数（本机实测，2026-10-15），细节见 [ADR-030](../adr/adr-030-mirror-reclaim.md)：

| 量 | 值 |
|----|----|
| `express` 的 mirror（全部 refs） | **18.41 MiB**（in-pack 54155 个对象 / 3982 个 ref / 默认分支 6181 个提交） |
| 它最新一版的源码 | **694.33 KiB** |
| 其中一个提交一份完整快照的朴素开销 | 6181 × 694 KiB ≈ **4.1 GiB** ⇒ 实际与它差 **约 228 倍** |
| 其中**不在**默认分支历史上的对象 | **21610 / 54155（约 40%）** |
| `lodash` 的 `--depth=1` 克隆 | 共 5.36 MiB，其中 `.git` 只占 **0.82 MiB**，工作区 4.54 MiB |
| 被中断的克隆留下的残骸 | **66.82 MiB**（`objects/pack/tmp_pack_*`，in-pack **0**，`packed-refs` 不存在） |
| `git gc` 清 `tmp_*` 的门槛 | **14 天**（实测 13 天存活、15 天被清；即 `gc.pruneExpire` 默认的 `2.weeks`） |

最后一行是这一版**为什么需要存在**的直接依据：git 自己会收这个残骸，但要等**两周**。

## 2. 交付

- `internal/git/gc.go`（新）：`GC` —— 把 `git gc` 收进唯一的 spawn 出口。它**不触网**
  （因此不做 `net:` 判定）、**不传 `--prune=now`**（两周的不可达对象窗口是 git 的安全期）。
- `internal/vendor/mirror_maintain.go`（新，353 行）：层 1 的**读数 / 残骸 / 整理**——
  `(*Mirror).Usage`、`PruneResidue`、`GC`，与 `content_maintain.go` 对层 2 做的事同形。
  `MirrorResidueGrace` = **1 小时**（常量，不是旋钮：`--older-than` 的既有语义一个字节没动）。
- `cmd/ngm/store.go`：`store usage` 增报层 1（含 `NO REFS` 点名）、`store prune` 追加层 1 残骸段、
  新增 `store gc [--dry-run]`；usage 与退出码补码 4。
- `docs/adr/adr-030-mirror-reclaim.md`（新）：把"镜子仍是全量"写成**决定**，
  并给出拒绝 `--single-branch` / 部分克隆的理由（ADR-004 的 refType、ADR-008/010 的离线重放）。

### 2.1 顺手修掉的一处**既有缺陷**

`store usage` 此前在"content store 不存在"时**提前返回**并打印 `nothing to report`。
在只有层 1 的机器上（clone 过、还没 install）这句话是错的：用户打开这个命令
正是想看那些 mirror 占了多大。现在两层都读，只有两层都不存在才说那句话。

### 2.2 一处**认知被实测纠正**

`PackBytes` 一开始被我当成"必然大于 0"。实测打脸：**本地克隆落的是松散对象，没有 packfile**，
于是一个刚建的 mirror 就是 `PackBytes=0` 而 `Bytes>0`。这不是"没有历史"，是"历史还没被收成包"。
断言、措辞（`packed history`）与代码注释都按这个事实改了——顺便它让 `store gc` 有了一个
**可被观察的效果**（整理后同一个读数会变），测试里也钉住了这一点。

### 3.1 牙齿（都**验证过**：改一下确实红）

| 牙齿 | 怎么改一下 | 结果 |
|------|-----------|------|
| **年龄门槛** | `PruneResidue` 里把 `if f.modTime.After(cutoff)` 改成恒假 | 4 条断言同时红，包括"比门槛新的残骸必须活下来"与 `KeptYoung` 的两个数 |
| **跳过没有 ref 的目录** | `GC` 里把 `case hasNoRefs(dir)` 改成恒假 | `SkippedNoRefs` 变空 ⇒ 跳过断言红，且 `Collected` 从 1 变 2 |
| **小计 = 逐行之和** | `Usage` 里把 `out.ResidueBytes += e.ResidueBytes` 改成 `=` | 小计对账红（`total ResidueBytes=0 want 4096`） |

`dry-run` 那条不是牙齿而是**仪器断言**：它直接断 `git.SpawnCount() == 0`——
不是"应该没跑"，而是"一个子进程都没起"。

## 4. 这一版**做错了什么**（比做了的更容易被忘）

**我覆盖了一个既有测试文件。** `cmd/ngm/store_gc_acceptance_test.go` 里已经装着
v0.11 的 `TestV11StorePruneOrphansAcceptance`（251 行），而我把它当成了新文件写下去。
它被从 HEAD 逐字节恢复了（`git diff` 为**空**，可核），新增的两个验收测试改放
`cmd/ngm/v100_mirror_layer_test.go`。

教训不是"小心点"，而是流程的：**这个仓库里"看起来像新文件"的名字，恰恰因为命名约定太整齐
而更容易撞上**。在覆盖任何文件之前先问一次"它是不是已经在仓库里"，
成本是一次 `git ls-files`，收益是一份 250 行的既有判据。

## 5. v0.101 候选

| # | 候选 | 理由 | 谁做 |
|---|------|------|------|
| 1 | mirror 的**跨进程锁** | 现在只有年龄门槛**缓解**并发（1 小时），没有防护——两个 `ngm install` 同时 fetch 同一个 mirror 时的行为仍是"没定义"（v0.66 就写在 `Mirror` 的文档里） | 需要一轮设计 |
| 2 | `store usage` 报**"只属于非默认分支的 ref"的对象数** | 这一版量到了它约占 40%（21610 / 54155），但它需要 spawn git（`rev-list`）才能算——而 `store usage` 现在是**纯文件系统、0 spawn** 的只读命令，加它要先把这条纪律摆到台面上 | 需要 ADR |
| 3 | `store gc` 的 `--json` | 输出形状还没被要求成机器可读；加它要连着 JSON 契约网一起动 | 等到有消费方 |
| 4 | `objects/<shard>/tmp_obj_*` 纳入残骸口径 | 这一版**明确**只认 `objects/pack/tmp_*`（实测到的那一类，MB/GB 级）；单对象的临时文件是 KB 级 | 低优先 |
| 5 | `store prune` 的层 1 段加门槛旋钮 | 现在门槛是常量（1 小时）。要给用户旋钮就得先回答"为什么 1 小时不对" | 等到有人真的遇到 |
