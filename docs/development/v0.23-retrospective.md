# v0.23 复盘 — 名字必须说发生了什么

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：把"**显示名**"从"**数值**"里拆出来，
> 让 `ngm typecheck` 失败时说的是 `EngineFailed:` 而不是 `RefDrift:`——
> 退出码、`--json`、`errors.Is/As` 一字未动。
> 顺带在**规范**里抓到一处同类漏写（`p0-core.md` 说码 1 是"非预期漂移"）。

---

## 1. 逐组验收

### 1.1 A 组 — 机制 ✅

`NgmError` 加 `Label` 字段（空则退回 `Code.String()`），配 `Labeled()`——
它返回**浅副本**，因此 `errors.Is/As` 仍然穿透到 `Cause`。
`Error()` 与 `FormatHuman()` 都改走 `label()`。

**为什么是"拆"而不是"改名"**：换成任何**单一**名字，另外三种用途照样读到自己不相关的词。
问题不在名字取得不好，而在**一个数字被迫只有一个名字**。

### 1.2 B 组 — 四处误标点 ✅

| 位置 | 之前 | 现在 |
|------|------|------|
| `internal/adapter/runner.go`（引擎跑过但失败） | `RefDrift` | **`EngineFailed`** |
| `internal/adapter/engine.go`（同上，另一条构造路径） | `RefDrift` | **`EngineFailed`** |
| `cmd/ngm/audit_hook.go`（钩子超时 / 钩子否决） | `RefDrift` | **`AuditHook`** |

改前的实际输出（牙齿验证时重现过）：

```
RefDrift: typeCheck: fake: fake/typeCheck: …\fake-engine.exe failed
  cause: … failed (engine exit 1)
  hint:  fix the reported problem; `--dry-run` prints the exact command ngm resolved
```

跑 `typecheck` 的人会去找"漂移"，而实际发生的是引擎退出非零。

### 1.3 C 组 — 两张网 ✅

- `internal/errs`：`Labeled` **只**改显示名（码、退出码、`errors.Is/As`、原错误都验了）；
- `cmd/ngm`：端到端断言 stderr **含 `EngineFailed`、不含 `RefDrift`**、**仍然退 1**，
  外加对照"新标签不许泄漏到 verify 的报告里"。

### 1.4 D 组 — 规范与声明同步 ✅

- `docs/modules/p0-core.md`：`ErrRefDrift` 的注释补上四个来源 + 结构体补 `Label` 字段；
- `cmd/ngm/update.go`：码 2 的声明补一句**实测的澄清**（见 §2）。

## 5. 过程洞察

### 5.1 一个数字一个名字 ⇒ 名字必然在某些命令里说谎

退出码是契约，必须有唯一的数字；名字是给人读的，**它天然是"某一个用途"的名字**。
只要一个数字被多种情形共用，这个名字就会在其余情形里**指错方向**。
治法是**把两者拆开**，而不是在两者之间反复挑一个更好的折中。

### 5.2 改名要三处同时落地，否则规范会变成新的错误源

这次改动落在**实现**（errs / adapter / audit_hook）、**规范**（p0-core）、
**命令用法**（update 的声明）三处。少任何一处，下一个人照着那处写就会把错的东西再抄一遍——
D1 就是这么来的：架构文档改了，规范没跟着改。

### 5.3 对照用例写错了，也要当成缺陷修

第一版对照断言是"真正的漂移必须仍然打印 `RefDrift`"。
实测发现 **`verify` 的漂移根本不走错误前缀**——它是 stdout 里的一行 ✗ 加退出码 1。
于是断言换成"新标签不许泄漏到 verify 的报告里"。
**预期落空时先量一遍再改断言**：这次落空暴露的是我又一次"凭印象写断言"。
