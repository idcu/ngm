### 1.3 P2#17：默认 verify 的边界**说出来**

浅校验（默认）只比结构与大小——hardlink 下 vendor 与 blob 是同一 inode，
**等长字节篡改检不出来**，而 CI 默认跑 `ngm verify` 会把"全部 ✓"读成字节级证明。

处置**不是**把默认改成 `--deep`（那会改掉已发布的成本模型：浅校验的代价与树规模无关），
而是把边界立成可见事实：

- 汇总行加一条 note（`structure-only (no byte hashes): same-length byte edits are detectable only with ngm verify --deep`）；
- `cli.md` 的 verify 行写明"要字节级保证请加 `--deep`"。

形式与 OSV 的 `CoverageNote` 同源：**不写这句，"通过"就会被读成比实际更强的东西。**

### 1.5 探针自查抓到的一处**既有缺口**（不在评估报告的清单里）

`--dir=` 空值的拒绝发生在**命令行分流层**（`dispatch`，早于命令自己的 flag 解析），
而 v0.54 的错误信封只覆盖了"7 个命令的解析失败 + 缺子命令 + 未知命令"。
实测（v0.66 探针）：

```
$ ngm verify --json --dir=
exit 3 · stdout **0 字节**   ← 用户提了 --json，失败却在机器那侧什么也没留下
```

修复：该分支加 `failEarly`（用户提了 `--json` 就给信封；没提时 stdout 仍为空）。
牙齿：`TestV66EmptyDirFlagCarriesAnEnvelope`（含"没提 --json ⇒ stdout 为空"的对照）。

> 这与 v0.31/v0.36/v0.56 那几课同族：**覆盖集的边界要按真实入口数，不能按"我以为的入口"数**。

### 1.6 fsync（评估报告 P1#5）

此前全链路**无一次 fsync**：`清单存在 ⇒ blob 在池里` 这个核心不变式只在**顺序**层成立，
持久性层不成立（断电可产生"清单在、blob 空"）。处置（仍是 best-effort 与硬保证分开写）：

- `writeBlob`：内容 `Sync()`（rename 之前）→ rename → `fsyncDir`（目录项，POSIX 有效、Windows 忽略错误）；
- `publishManifest`：`writeJSON` 内部 `Sync()`（清单文件本身）→ rename → `fsyncDir(treesRoot)`。

**未做**：每个 blob 的目录 fsync 是逐文件开销（1000 文件 = 1000 次），已用"发布清单后一次目录 fsync"覆盖主要窗口；剩余边界如实记在 §2。

## 5. 过程洞察

### 5.1 外部评估的价值不在"新能力"，在"**代码里的错**"

项目自己的状态页写的是"未完成任务"（尚缺什么），评估报告写的是"**已经在错**"
（门禁绕过、逃逸、往返不一致、装饰性配置）。两者不是同一张清单：
前者驱动"再加一层"，后者驱动"把洞补上"。这一版全部来自后者——
83 个版本以来第一次，范围的**事实源不是候选表，而是一份逐行复核**。

### 5.2 加一个 flag 会触发四张既有网（这是设计，不是噪声）

install / update 加 `--json` 时，v0.25（形状表正向）、v0.26（反向：**每个顶层字段都要在文档里**）、
v0.50（失败路径的 next-step 必须跨通道同源）、v0.57（**新出口要登记**）四张网依次亮起。
其中 v0.50 的红才是真正有价值的那条：`verifyOnLock` 撞漂移时人读有一行行动行，
而机器那侧此前**什么都没有**——`verification` 字段（含 `drifts[].remediation`）
就是被这条网逼出来的，`remediation` 与人读那句**同源**。

> **"加一个 flag"的真实成本不在 flag 本身，而在它把所有既有契约都问了一遍。**

### 5.3 "该不该修"与"哪里修"是两个问题

`--dir=` 空值那条：v0.41 修了"静默当 CWD"（危险的那半），v0.54 给解析失败加信封时
**没有覆盖它**——因为它不在"命令的 flag 解析"这条通道上，而在更早的**分流层**。
两个版本各自都对，缺口在**交界处**。这类交界（分流层 ⇄ 命令层、人读 ⇄ 机器）
是本项目缺陷最密集的地方。

### 5.4 探针的代价是一行命令，收益是一处真缺陷

`--dir=` 缺口不是读代码发现的（读代码时那一段看起来完全正确：它明确拒绝了、
打印了 usage、退 3）。它是**跑了一次探针**发现的：
`ngm verify --json --dir=` 之后盯着 stdout 看——空。这与 v0.9~v0.12 的历史一致：
真缺陷是"跑出来的"，不是"想出来的"。
