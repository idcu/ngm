# v0.19 计划 — 用户看到的文本也是接口

> 范围来源：v0.18 的"第一次真实联网复核"顺手暴露的一条——
> `ngm config validate` 在**没有 ngm.json 的目录里照样打印 `ngm.json OK`**。
>
> 一句话目标：退出码与措辞是脚本与人分别读到的那一份契约。
> 这一版把它**补齐、说准、并配上机械网**。

---

## 0. 为什么有这一版

v0.18 的联网复核里，我拿"目录里没有清单"当错误路径去测，结果拿到的是：

```
config validate --dir=<没有 ngm.json 的目录>   exit=0   ngm.json OK
```

三个缺陷叠在一起才出现这一行：
① `--dir` 根本没注册（本命令是唯一只认进程 CWD 的项目命令，测试只能用 `chdir` 绕）；
② 多余位置参数被静默丢弃（只检查了 `NArg()==0`）；
③ 目标目录没有清单时**照样报 OK**——于是 CI 在错的目录里跑 `ngm config validate` 会拿到绿色。

**假通过比报错更糟**：它让做错的人以为自己做对了。这正是本项目存在要防的东西。

---

## 1. A 组 — 每个命令都写出自己的退出码

新增 8 个 `EXIT CODES` 段（init / add / update / remove / mappings / cache / store / config），
并**修正 `install` 不完整的一段**：它写着 `0/3/4`，但实测还能退 **2**（postinstall 钩子失败/超时、落地字节校验不过）与 **5**（需要 Deno 而缺失/不可用）。

配一张机械网：`TestV19EveryCommandDocumentsItsExitCodes`——
每个命令的用法文本必须有 `EXIT CODES` 段，且段内至少有一行 `<0-5> <说明>`。
（它**不**证明"列全了"——那需要数据流分析；本网的判据取窄是刻意的：**会误报的门禁会被忽略**。）

## 2. B 组 — `config` 的三处缺陷

| # | 缺陷 | 处置 |
|---|------|------|
| ① | `--dir` 不存在：只认进程 CWD，想校验别的目录只能 `chdir`（本项目自己的测试就这么绕） | 加上 `--dir`（默认 `.`，与其余命令一致） |
| ② | 多余位置参数被静默丢弃 | 改为 `NArg() != 1` → 打印用法 + exit 3 |
| ③ | 目录里没有 `ngm.json` 时照样打印 `ngm.json OK` | 改为 exit 3 并点名是哪个目录；`config show` 保持"查看"语义，但**写明项目层缺席` |

## 3. C 组 — 用户可见文本里的内部阶段标签

`M0…M7` 是项目**内部**的里程碑编号，用户从没听说过；此前它泄漏到两处用户可见的位置：
- `ngm add` 成功后打印的 `next: run \`ngm install\` to resolve and lock (M3)`
- `ngm update` 用法里的 `M1 阶段本命令完成…；ngm.lock 的写入属于 M3`（**而且这句话是错的**：update 今天就写 lock）

配一张机械网：`TestV19NoInternalStageLabelsInUserFacingText`——用 `go/scanner` 取**字符串字面量**（不看注释），
断言其中不含 `\bM\d\b`。判据说得明白：**注释里可以出现（那是设计记录），字符串里不行（那会打印给人看）**。
并且大小写敏感——否则 `sha256.Sum256` 里的 `m2` 会被当成阶段标签（第一版扫描就踩了这个）。

## 4. D 组 — 一个待决项：引擎要不要有内置默认？

决定见 [ADR-025](../adr/adr-025-no-builtin-engine-defaults.md)：**不设**。
一句话理由：默认一旦由"机器上装了什么"决定，就会**在没有人改任何文件的情况下改变行为**——
这与 ADR-018 拒掉可达性删除是同一个形状。`typecheck` / `typedecl` / `css` 缺声明时退 **3**
（配置/策略错误），声明了但引擎未装才是 **5**（引擎不可用）。
