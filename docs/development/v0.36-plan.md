# v0.36 计划 — **扫描，而不是挑选**

> 范围来源：[v0.35 复盘](./v0.35-retrospective.md) §7 候选 1 与 3。
>
> 一句话目标：报告契约（v0.32 ~ v0.35）现在只覆盖我**手工挑的 9 条**用例——
> 挑的依据是"我知道这几个命令会出报告"。这一版换一种做法：
> **把全部非零用例都跑一遍，凡输出里出现 `✗` 的，都必须带下一步。**

---

## 0. 为什么值得换

**扫描比挑选更接近全称，而且不需要我猜哪里会有报告。**

v0.32 挑那 9 条时的依据是我的记忆；这一版把判断权交给"输出里有没有 `✗`"这个客观事实。

## 1. 范围

| 来源 | 非零用例数 |
|------|-----------|
| 退出码对账表（v0.22） | 43 |
| 错误面表（v0.31） | 14 |
| **合计** | **57** |

判据：凡 `reportBody` 里出现 `✗` 的，都必须至少有一行行动行（`→ …` / `Fixed in: …`）。

## 2. 一处必须做的处理：去掉**用法文本**

用法文本里有一段 `MARKERS:` 就是在**解释记号本身**：

```
MARKERS:
  ⚠  the ref no longer points at the commit pinned in ngm.lock
  ✗  known vulnerabilities (only with --osv; without it nothing is claimed)
```

不截掉它，扫描会把 `tree` 的一条**用法错误**（"flag provided but not defined"）
误报成"有失败项却没有下一步"——**判据自己造一个假缺陷**。

## 3. 与 v0.32 的关系

| | v0.32（深度） | v0.36（广度） |
|---|---|---|
| 输入 | 手工挑的用例 | **全部**非零用例 |
| 断言 | 行动行数 **≥ 失败项数**（逐条对齐） | 至少**一行** |
| 挡住什么 | "有"不等于"够" | "我没想到的地方" |

两者都要。
