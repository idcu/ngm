# v0.101 复盘：三个承诺、五条说谎的读数、三个真仓库

> 本版最贵的读数不是"修好了什么"，而是**三条对外承诺实测都不成立**，
> 而在这之前**没有任何判据会因此变红**——判据检查的是实现内部一致，
> 不是实现与承诺一致。

## 一、三条承诺的实测证据

| 承诺 | 复现方式 | 结果 |
|---|---|---|
| 沙箱无网络 | `deno run --deny-net --no-remote --deny-write --deny-run --deny-env --deny-read` 里 `import "npm:is-number@7.0.0"` | **成功**，包被下载进 `DENO_DIR/npm/registry.npmjs.org/` |
| 依赖不能改沙箱行为 | 同一命令，工作目录放一份依赖自带的 `deno.json` | **被自动加载**，`imports` 生效 |
| `install` 不静默丢文件 | 同时含 `Foo.txt` 与 `foo.txt`，在 Windows 上 `install` | 打印成功；vendor 只有一个；随后 `verify` 判 `critical exit 2` |

第三条最值得记：**工具造出了一个自己拒绝的世界**，而两步各自都"按设计工作"。
发现它的方式不是读代码，是把两件事按用户的顺序跑了一遍。

## 二、五条"输出正常、结论错"

| 缺陷 | 为什么它能活下来 |
|---|---|
| `attest` 签名时读两次 `ngm.json` | 两次读之间没有判据；签名之后也没有东西能发现 |
| `TagSignature` 把"git 没跑起来"说成 `SigUntrusted` | `vres, _ :=` 吞掉执行错误，两种情形落进同一个结论 |
| `mappings` 的 `main`/`types` 可 `../` 逃出 vendor | 存在性检查会**放行**（目标文件真的存在），而它先跑 |
| `why` 只约束命中、不约束搜索 | 条数上界看着像上界；不可达时一条也不命中 ⇒ `truncated=false` |
| `atomicfile` 不同步目录项 | `tmp.Sync()` 看起来像"已经落盘" |

再加两条同族：`verify` 把 `permission denied` 报成 `driftKind: unexpected`（把"没问到"
说成"上游漂了"）；模块重放信任 content store 自述的清单（带 NUL 的 `Path` 能把一条记录变成两条）。

**一条一般的话**：当结论写得比实现强时，没有任何判据会变红。本版所有修法共同的形状，
是把"我们没能判断"变成一个**独立可表达的状态**（`operational`、`IsRefNotFound`、
`EscapesVendor`、`Skipped`），而不是让它落进最近的那个结论里。

## 三、三个真仓库（以及它们不证明什么）

`gitee.com/idcu/ngm-fixture-{basic,monorepo,content}`：只覆盖本地 mirror 假不出来的三件事。
**它们不证明产品被采用**——那是作者自己的夹具。这一点写在文档第一段，
因为本项目已经在这两件事上混淆过一次（100 个版本、0 个外部用户）。

夹具的坑记两条：`git push --mirror` **不带 HEAD 符号引用**（远端非空时它不在 refspec 里），
于是 `basic` 的默认分支落在 `legacy` 上，仓库首页只显示两个文件而所有判据都是绿的；
生成器现在显式 `symbolic-ref HEAD refs/heads/main`，并有一条判据盯着。

## 四、我自己的三次误判（记下来，因为它们是同一类）

1. **pnpm 越界**：把"解析 pnpm lock"排进下一步，与同一篇 ADR 里"不碰 registry 一侧"矛盾。
   已收回，并在 ADR-040 写成**明确非目标**。
2. **"mint 版本会让读数变成假话"**——**算错了**。读数的分母是**已交付版本数**，
   不是已推送数；`60 of 100` 改成 `60 of 101` 依然为真（GitHub 仍是 60 个 release、65 个 tag）。
   这个误判让版本仪式白白推迟了几轮。后来用公开 API 复量才纠正：
   GitHub 60 releases / 65 tags（`v0.1.0`…`v0.65.0` 无缺口）、Gitee 3 releases。
3. **"sbom 两次运行逐字节相同"**——两次跑在**同一秒**里，而时间戳是秒级。
   按 3 秒间隔重测：两种格式都不同。实现其实早写在注释里（"时间戳是唯一非确定字段"），
   错的是我的测量方法。

三次的共同点：**我用一个看起来通过的观测代替了真正的测量**——与本版修的五处缺陷同一个病。

## 五、判据的增量

先红后绿的：沙箱模块加载（argv + 真 Deno，**禁止 `t.Skip`**）、大小写冲突（跟随磁盘而非 GOOS）、
`run:git` 全称判据（牙齿实测）、引擎侧 env 剔除（含对照）、产物存在性、BOM、
`refType` 窄默认、`attest` 单次读（源码级）、签名判定（纯函数 5 格）、`mappings` 包含性、
`why` 预算（实测 14 ms vs 无预算的 626 MB）、`atomicfile` 目录同步、`checks[]` 留痕、
锁重复条目、清单字段校验、`BlobPath`、`adopt` 的证据语义与 `--check` 三形态、
`verify` 的"结论 / 没查成"分类、夹具的确定性与形状、默认分支。

**顺带发现仓库自己有三张网在本版开工前就是红的**（`doctor` 从未登记进形状表、
从未登记参数维度的退 0、`--json` 解析失败时 stdout 0 字节）——新增命令不会被旧网自动接管，
而漏接管的表现与"全都对得上"一模一样。

## 六、外部校验（证据，不是判据）

用发布方 schema 验了三份产物：SARIF 2.1.0、CycloneDX 1.5（含它引用的两个子 schema）、
SPDX 2.3 —— **都 VALID**（2026-10-30）。`attest` 的 SLSA v1 谓词**没验**：
那份 schema 在它文档给出的路径上 404（两个仓库都挪过目录），而凭记忆写一份 schema
去校验自己的产物等于自证。
