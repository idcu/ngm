## 1. 漏检是什么

`[x](./b(c).md)` 这种链接**完全合法**（CommonMark 允许 destination 里有配平的括号）。
旧实现的匹配 `\[[^]]+\]\([^)]+\)` **到第一个 `)` 就停**，于是：

| 步骤 | 旧实现的结果 |
|------|-------------|
| 匹配 | `[x](./b(c)` |
| 取"最后一个 `(` 之后" | `c` |
| 剥 `)` 与锚点 | `c` |
| 是否 `.md`/`.txt` | 否 ⇒ **静默跳过** |

也就是说：这条链接**既不会被报坏、也不会被算好**——它从检查里**消失**了。
一个会漏检的检查比没有检查更坏：它给人"查过了"的感觉。

## 2. 先量，再改

| 问 | 答 |
|----|----|
| 全仓（253 个 `.md`）destination 里含 `(` 的链接 | **0 处** |
| destination 里含 `)` 的链接 | **0 处** |

⇒ 变强不会引入新红。**这一步必须先做**，否则"改进"会变成"突然红一片"，
而那种红很容易被当成"检查坏了"而被关掉。

## 3. 改法与前后对照

destination 改为**平衡括号**扫描（从 `](` 之后数括号，深度回到 0 的那个 `)` 才是结尾）；
括号**不配平**时退回旧语义（取最后一个 `(` 之后）——不把畸形写法顺手变哑。

同一份夹具（4 条链接：带括号且存在 / 带括号且缺失 / 普通的坏 / 普通的好）：

| | 旧实现 | 新实现 |
|---|--------|--------|
| 报出的坏链接 | 1 条（只有"普通的坏"） | **2 条**（多的是"缺失（带括号）"） |
| 带括号且**存在**的那条 | 不报（看不见） | 不报（**正确解析后确实存在**） |

第二条尤其重要：它证明新解析不是"见括号就报"——那只是把漏报换成误报。

**黄金用例**同步补了这两侧（`cmd/ngm/v091_docs_links_golden_test.go`），
于是"漏检关上"这件事第一次有了**常驻**的凭据，而不是一句复盘里的话。
真实仓库（253 个 `.md`）仍然 `all docs links OK` ✓。
