# v0.42 复盘 — **取值 flag 的空值**

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：把 v0.41 的教训**推广到全部取值 flag**——
> **15 个 (命令, flag) 组合里，14 个明确拒绝空值、1 个与"不给"等价，没有一处再碰 CWD**。
> **产品代码 0 行改动**；这一版的产出是一条**长得像缺陷本身**的判据。

1. **显式空值要么与"没给这个 flag"完全等价，要么失败**——没有出现"两个都成功、结果却不同"；
2. **任何一次运行都不许在 CWD 里留下东西**——判据把 CWD 换成空目录，跑完它还是空的。

## 5. 过程洞察

### 5.1 一条判据长得像它要抓的东西

这一版的核心句是：**"两个都成功、结果却不同"**。

它不是一个抽象的"要正确"，而是**那个缺陷的形状本身**——v0.41 的 `--dir=`：
用户以为自己在设一个值，实际触发了另一条路（CWD），而两边都"成功"。

**判据应该长得像它要抓的东西**：这样它就不需要解释（读的人看到红就知道是什么事），
也不容易写偏（写偏了就不再像那个形状）。

### 5.2 把一次修复**推广**成一族判据，是对修复最好的收尾

v0.41 修的是**一个 flag**。若不推广，下一个 `--outdir=` 的同类问题要等到有人再撞一次才被发现。

这一版做了两件事：把"空值"这个**输入形状**枚举到全部取值 flag；
并把"静默改变行为"抽象成一条可判定的不变量。

> 顺带一个诚实的结果：**其余 14 个 flag 本来就没这个毛病**（它们要么拒绝、要么无害）。
> 这不妨碍推广的价值——**判据的价值在于它会继续看着**，而不在于它今天抓到了什么。

### 5.3 一条纪律真的挡住了一次复发

v0.41 的探针把**仓库**写脏了（`cmd/ngm/ngm.json` + `src/`），处置是：
"跑可能写文件的探针前，先把 CWD 换到临时目录"。

这一版的探针与网**每一步都先 chdir**，于是：

- 探针跑完，仓库 `git status` 干净 ✅
- 而"那个目录是不是还是空的"直接成了**判据的第二条不变量** ✅

**一次事故的正确收尾不是"下次小心"，而是把那条小心写成代码。**

### 5.4 又一次引号事故（Go 版）

写判据时我在 Go 字符串里嵌了 ASCII 双引号（`"这正是"静默改变行为"的定义"`），
编译直接报 `missing ',' in argument list` ✗。

与 v0.41 那次（PowerShell 的 `git tag -m` 被双引号拆参）是同一族的**另一个面**：
**同一句话在两层工具里都要过——先过 shell，再过语言**。
处置固定成一条：**跨层传文本时，一律用中文引号或转义**。
