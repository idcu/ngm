# v0.13 计划 — 把"缺陷形状"固化成网

> 范围来源：[v0.12 复盘](./v0.12-retrospective.md) §7 候选 #5（"继续找没人检查的角落"）
> 与 §5.5 的结论（**"找到一类形状之后，要立刻把它变成网，否则下一版会再找一遍"**）。
>
> 一句话目标：**把 v0.12 抓到的那几类形状，从"这一轮查过"变成"以后自动会红"。**
>
> 本版**不加能力、不改行为**：产出是机械网与文档纠偏。它是 v0.10 那种"实现 0 行改动"的
> 版本的同族——把一个已经知道的事实钉进检查里。

---

## 0. 为什么有这一版

v0.9 ~ v0.12 的真缺陷**全部**是主动去找才找到的（v0.12 一次性抓到五处"静默失效"），
**没有一个是既有检查发现的**。每找到一类形状，正确处置不是"写进复盘"，
而是**让它变成下一次会自动变红的东西**——否则同一个形状会在下个版本被重新发现一遍。

v0.12 已经这样做了三张网（flag 必须有文档 ⋯ 帮助文本必须与常量逐字一致 ⋯ 脚手架必须全有或全无），
本版补上剩下的两类，并**记录一张故意不做的网**（下面 §1.3）。

---

## 1. A 组 — 两张新网 + 一张不做的

### 1.1 A1 — "接受的输入被静默忽略"

| 项 | 内容 |
|----|------|
| 形状 | v0.12 **D3**：`ngm css a.css b.css` 只编译第一个、exit 0、一句话不说（shell glob 是最常见的触发方式） |
| 网 | `TestV13PositionalArgsAreBounded`（扫源码）：读了 `fs.Arg` 的**文件**必须校验 `fs.NArg()` |
| 判据的代价 | 文件级。已逐个核对在当前代码上等价（22 个 flagset、11 个读位置参数的文件）；**它可能漏报**——若某命令把解析搬到别的文件就看不见了。这一句写在测试注释里：**漏报比误报更需要被知道** |
| 牙齿 | 已用一次性探针验证：注册一个"读 `fs.Arg` 但不校验个数"的函数 → 网变红并**点名文件**；删探针后恢复绿 |

### 1.2 A2 — "`--offline` 被绕过"

| 项 | 内容 |
|----|------|
| 形状 | v0.12 **D1**：`ngm outdated --offline` 实际仍会把在线版 `EnsureMirror` 交给检查器（mirror 在则 `fetch`、不在则 `clone`），而检查器只在 branch 分支读 `Offline` |
| 网 | **行为级**：冷 mirror + `--offline` ⇒ **0 次 git 子进程**（`git.SpawnCount()`），并断言报告说出真正的原因（`no local mirror`） |
| 为什么用次数而不是文本 | clone / fetch / ls-remote 都要起 git，因此"零次 spawn"拦的是**行为**而不是措辞；与 v0.6 的 spawn 预算同源（**次数优先于秒数**） |
| **对照**（必须有） | 同一命令 + 暖 mirror ⇒ **必须起 git**（列 tag 要读本地 mirror）。没有这一条，"零次"也可能只是计数器坏了——**一个恒为零的仪器能让那条断言永远变绿**。实测：冷 mirror 0 次、暖 mirror > 0 次 |

### 1.3 A3 — **故意不做的一张网**（记在这里，免得下一版再想一遍）

一张"注册了 `--offline` 的命令文件必须把它交出去"的源码网（判据：文件里出现
`offlineEnsureMirror` 或 `Offline:`）。它在当前代码上是**绿的**（6 个文件全过），
但——**D1 也会通过它**：当时的 `outdated` 确实把 `Offline:` 交给了检查器，
只是检查器自己只在 branch 分支读它。

按项目自己的话：**会漏报的门禁等于没有**。所以那一类改用 A2 的行为网。
这条记下来的价值是：下次有人想加这张网时，能先看到它为什么不够。

## 2. B 组 — 状态声明一致性扫描

v0.12 的病灶是"状态页与事实不符"，而扫过一遍不等于以后不会再有。
本组做一次**机械扫描 + 修**：在全部文档里找"过期读数"（已被证伪的版本号、
已被推翻的计数、已失效的"待办"措辞），逐条对账。

| 判据 | 说明 |
|------|------|
| 只改**会被当作现状读**的地方 | 各版复盘是**快照**，按项目纪律**不修改**（v0.11 复盘里那句"暂缓已取消"就留在那里） |
| 计数必须能被一条命令复读 | 例如"缺 9 个"要能由 `scripts/check-gitee-release-status.ps1` 复现 |

---

## 3. 明确不做（本版范围外）

| 不做的 | 理由 |
|--------|------|
| 补发 4 个 GitHub release + 9 个 Gitee 发行版 | **已暂缓**（2026-10-04，项目所有者决定），判据与恢复信号见[发布清单](./README.md#发布清单每个版本)开头 |
| 非默认端口的**真正支持** | 需要给 `Canonical` 加字段（lock / mirror / slug 的共同基础）= schema 级变更，**先有真实需求** |
| 仓库的 description 与 topics | 只能网页操作 |
| Gitee 读音进 CI | CI 是 ubuntu、没有 PowerShell；要么改写实现语言，要么接受它是本地读数——**先不做，但记着** |

## 4. 验收

```bash
go build ./... && go vet ./... && gofmt -l .
go test -count=1 -run 'TestV13' ./cmd/ngm
go test -count=1 -run 'TestV02ObservabilityAcceptance' ./cmd/ngm   # A2 的对照在这一组里
```

- 两张网都必须**证明过会红**（探针 / 对照），而不是"跑起来是绿的"
- 文档扫描的结论要能列出"改了什么、为什么其余不动"
