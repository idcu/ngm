# v0.64 计划 — **`schemaFiles` 不再是一份要人记着的清单**

> 范围来源：v0.63 复盘候选 1（v0.56 普查留到现在的那条）。
>
> 一句话目标：把"漏加一份配置 schema"从**静默变松** ✗ 变成**判据红** ✓。

---

## 0. 起点：那张清单自己的注释

```go
// 新增一个用户可编辑的 schema（新的配置文件）时，把它加进这里——这是本检查
// 唯一需要人工维护的地方，而漏加的表现是"检查少了几个键"，不是误报。
var schemaFiles = []string{ … }   // 3 条
```

⇒ 也就是说：**检查可以静默变松** ✗——正是本项目一直在杀的那类缺陷
（v0.45「按文件名找源码」· v0.46「覆盖集从哪来」· v0.57「来源按行为派生」）。

## 1. 计划：三处闸门，两条反例定形状

| 闸门 | 信号 |
|------|------|
| ① 文档侧 | `docs/guides/configuration.md` 开头的**配置文件表**（首格是反引号包着的 `.json` 名）——文档自己说"这些是配置文件" |
| ② 代码侧 | 名字出现在**代码行**（跳过纯注释行）里，且是"赋给标识符"或"作为 `filepath.Join(` 的参数"——**定义方要解析路径** |
| ③ 形状侧 | 该文件**至少有一个带 json tag 的字段**——它确实在定义 schema |

三条缺一不可，两条反例把形状钉死：

- `internal/verify/graph.go`：`const UpstreamFile = "ngm.json"`——名字一样，但那处是**读上游清单**（没有任何 json tag 字段）⇒ 不进来 ✓；
- `internal/lock/schema.go`：有 11 个 json tag 字段，但它命名的是 `ngm.lock`（不是 `.json`、也没在配置表里）⇒ 不进来 ✓。

## 2. 验收

```bash
go test -count=1 -run 'TestV64|TestV53|TestConfigKeys' -v ./cmd/ngm
go test -count=1 ./...          # 整套，不手挑
gofmt -l . && go vet ./... && bash scripts/check-docs-links.sh
```

**牙齿**：清单**少一条** ⇒ 红（`却不在 schemaFiles 里：…`）· 清单**多一条** ⇒ 红（`派生不出来：…`）。
