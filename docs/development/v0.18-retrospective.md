> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 范围来源：v0.11 C 组留下的"端到端可用性复核（可按季度重跑）"；实施计划：[v0.18 计划](./v0.18-plan.md)。
>

> 完整首次上手路径**未能在本环境端到端验证**。同时，**一条我原本准备动手修的假设被测量否掉了**。

## 2. 未能达成的项

**完整首次上手路径未能在本环境端到端验证。** 原因不在本项目：本机对 `github.com:443`
的 git-https 三次尝试只成功一次（另两次是 RST 与连接超时）。

如实记法：**这一版不能声称"首次上手已验证"**。能做到的是：
- 工具留在仓库里（一条命令就能在任何有正常网络的机器上补上）；
- 把已发生的事实逐条写下来（哪一步成功、哪一步被什么挡住、耗时多少）；
- 把"未证明"这件事写进[指标](../internals/metrics.md)与本文，而不是含糊过去。

## 3. 设计偏离登记

| # | 计划写的 | 实际做的 | 为什么 |
|---|---------|---------|-------|
| 1 | 探针用**断言式**（网络失败也算失败） | 改成**记录式**：联网部分只打日志；远端不可达（exit 4）判为"未证明"并 skip | 网络不是本项目的可控输入。把不可控的部分写成断言，等于给项目装一个**随时会因别人而红**的门禁——那种红训练人忽略红色 |
| 2 | 原本准备**给网络操作加超时**（怀疑等待无界） | **没做**。先测量：三次失败由 RST(~20s) 与 TCP 连接超时(~21s) 终止，都是 git 自己的界 | 假设没有测量支持。**不去修一个没测到的问题**——v0.14 D6 的纪律，这次挡住了一次"看起来很像缺陷"的改动 |
| 3 | 计划里"验四类东西" | 保留，但明确标注**它们只在网络可达时才有意义** | 让复核的**结论强度**与它的**前提**写在同一个地方 |

## 5. 过程洞察

### 5.1 没做到的事要写在最前面

这一版最容易写成"我们做了真实联网复核"——而事实是：**工具有了，路径没跑通**（网络）。
复盘的顺序因此刻意调整：§2"未能达成的项"紧跟验收，而不是藏在结尾。
**把"未证明"标清楚，与把"已证明"标清楚同样重要**——这个项目的全部价值都建立在这一点上。

### 5.2 被否掉的假设也是交付物

我原本要做的是"给网络操作加上界"（听起来完全符合本项目"上界要名副其实"的性格）。
先测量之后：三次失败分别由 RST（~20s）与 TCP 连接超时（~21s）终止——**界一直都在，只是不在我们手里**。
把它记下来，比加一个用不上的超时更有价值：**下一个人会同样怀疑它**。

### 5.3 把不确定性关在门禁之外，而不是把它写成断言

联网复核的形状因此是：**默认跳过 · 不可达即"未证明" · 联网部分只记录**。
这与 v0.15 拒绝一张"会因别人而红"的网是同一条纪律的正面应用：
**门禁只断言本项目能控制的事**。

### 5.4 真实失败的压力验证，价值高于构造的失败

此前"诚实读数"（§v0.12/v0.16）的验证都是**构造的**：写坏一个文件、注入一个常量。
这一次是真实的 `Connection reset` 与 `Could not connect to server`——
ngm 的说法（`check incomplete`、exit 4、点名 URL 与操作、给出 hint）**经得起**。
**构造的失败证明机制存在，真实的失败证明它扛得住。**

### 5.5 一条顺手得到的正面证据

`ngm add` 在真实环境里 **2–4 ms、零网络**，与 `runAdd` 的注释（"ref 解析与 lock 写入属于 install"）
以及文档里的分工完全一致——设计意图与真实行为对上了。这种"顺手的对照"是联网复核的额外收益：
它同时在检查**文档说的分工**是否真的成立。
