# v0.50 计划 — **"下一步"这条契约要跨通道成立**

> 范围来源：v0.49 候选之外的一次普查——从 v0.28 到 v0.49，这一系列**全部**盯着
> **人读**的输出（hint 行 · cause 行 · 行动行），而 `--json` 是给脚本读的。
>
> 一句话目标：**人读那侧有行动行 ⇒ 机器那侧必须有对应的结构化字段**，
> 而且两个通道说的是**同一句话**。

---

## 0. 起点：先量

先问一个问题：**哪些命令有 `--json`**——从**派生的 flag 表**里问，不靠我记
（第一版探针假设"每张报告都能加 `--json`"，于是在 `install --json` 上撞到
"flag provided but not defined"，差点把它当成缺陷）。

然后对每一条报告式失败，各跑两次（不带 / 带 `--json`），看三件事：
退出码是否一致 · 机器那侧有没有"下一步" · 那句话与**人读那句**是不是同一句。

## 1. 判据

1. **机械闸门**：命令没有 `--json` ⇒ 这条不在契约范围里（从源码派生，不靠登记）。
2. **具名登记**：有 `--json` 却没产出 JSON 的路径必须**登记并写清为什么**
   （v0.16 的规则④：输入错误时 stdout 必须为空——"我没有报告可给"不能用半份 JSON 表达）。
3. **内容级跨通道一致**：人读那侧的每一条行动行，剥掉 `→` / `driftKind: …;` /
   `Fixed in: ` 前后缀之后，那句话**必须逐字出现在 JSON 里**。

## 2. 验收

```bash
gofmt -l . && go vet ./... && go build ./...
go test -count=1 -run 'TestV50|TestV26' -v ./cmd/ngm
go test -count=1 ./...          # 整套，不手挑
bash scripts/check-docs-links.sh
```

**牙齿**：抽掉某一处的机器侧"下一步" ⇒ 该条必须红
（第一版判据**没咬住**，那次失败是这一版最值钱的读数）。
