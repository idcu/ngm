# v0.15 计划 — 把两条对外契约钉成网

> 范围来源：[v0.14 复盘](./v0.14-retrospective.md) §7 候选 #2（"示例命令是否真的能跑"
> 是那条线的第一次命中）与 §5.2（"照文档写断言，会把文档的错误复制进测试"）。
>
> 一句话目标：**文档里的示例命令必须真的成形；CLI 的错误路径必须可判别**——
> 两条都是"用户照着做就会撞上"的契约，而此前**没有任何机械网**看着它们。

---

## 0. 为什么有这一版

v0.14 找到的四处文档缺陷里，`build.md` 的 D4 属于一类**没人检查**的形状：
文档的示例命令是否**成形**（子命令真的存在、flag 真的属于那个命令）。
更早一次同类事故是文档里的 `ngm add --ref=…`——**那个 flag 从来不存在**
（真名是 `--ref-type`），照着抄直接 `flag provided but not defined`。
这两件事都不会让任何测试变红，**因为测试从不读文档**。

第二条来自写第一张网时的实测发现：参数错误时，那句
`flag provided but not defined: …` **绕过调用方注入的 writer**，
直接写到**进程的 `os.Stderr`**（21 个命令都如此，`fs.SetOutput` 从未被调用过）。
终端里两者是同一个地方，所以手测完全正常；而退出码与流向正是脚本唯一能看的东西。

## 1. A 组 — 文档示例命令必须成形

| 项 | 内容 |
|----|------|
| 网 | `TestV15DocExamplesAreRealInvocations`（`cmd/ngm`） |
| 判据 | 每条以 `ngm` 开头的示例命令：① 子命令必须在**运行时的命令表**里；② 它带的每个 `--flag` 必须出现在**该命令自己的 usage 文本**里（那份文本已被 `TestV12EveryRegisteredFlagIsDocumented` 证明"会写下自己的全部 flag"），或属于两个根级 flag（`--help` / `--version`） |
| 只取代码 | 只扫**围栏代码块与行内代码跨度**，不扫整行文本。实测理由：整行扫描会把 `node --test`、`git merge-base --is-ancestor`、esbuild 的 `--alias:…`、catalog 的 `--kind=` 全算进来——**会误报的门禁会被忽略** |
| 范围 | **只含活文档**（根 README、docs/README、guides、internals、architecture）。`docs/development` 与 `docs/adr` 是**快照**：按项目纪律不随之后的删改修订，让一张会红的网去要求改写历史等于拆掉那条纪律 |
| 负例 | 有 3 处示例是**故意的"这个命令不存在"**（`ngm test`、`ngm lock migrate` ×2），用一份**会自己过期的名单**登记：每条若在文档里匹配不到就会红，要求一并删掉 |
| 不做 | 不检查示例"能否跑通"（需要 fixture、引擎与网络）——那是另一张网，**这一张挡"照着抄直接报错"，挡不了"抄了能跑但结果不是你看到的"** |
| 牙齿 | 一次性探针文档（`ngm verify --strict` 是真 flag 不报 / `ngm lok migrate` 报 / `ngm build --bundle` 报）+ 名单过期绊线 |

## 2. B 组 — 用法错误的退出码与流向

| 项 | 内容 |
|----|------|
| 网 | `TestV15UsageErrorsPrintOwnUsage`（`cmd/ngm`，覆盖全部 21 个命令） |
| 契约① | 错的 flag ⇒ **exit 3**（`CodeConfigInvalid`）——用法错误必须能与"检查没通过"（1/2）区分开 |
| 契约② | 该命令**自己的用法**必须出现在 **stderr**（不是根帮助、不是 stdout） |
| 契约③ | 用法错误时 **stdout 必须为空**（否则 `ngm … --json > out.json` 会污染报告） |
| 契约④ | **没有任何字节绕过注入的 writer**：把进程 `os.Stderr` 收进管道，跑完断言它是空的 |
| 对照 | 同一命令的 `--help`：exit 0、用法在 stdout、stderr 为空。同一份文本、两个流、两个退出码——少了任何一半，"参数错误时打印用法"都能靠"永远打印用法"满足 |
| 顺带的修复 | `newFlagSet(name, stderr)` 并 `fs.SetOutput(stderr)`（22 个调用点）；删掉**从未被引用**的 `errSilent`——它的注释写着"让 ContinueOnError 静默"，而那个机制**不存在** |

## 3. 明确不做（本版范围外）

| 不做的 | 理由 |
|--------|------|
| 给 8 个命令补 `EXIT CODES` 段（`init`/`add`/`update`/`remove`/`mappings`/`cache`/`store`/`config`） | 这是**新增约定**，不是修缺陷。先记录，等有人真正需要时再决定是否让 21 个命令的用法格式统一 |
| 检查示例命令"能否跑通" | 见 §1 |
| 把 `docs/development`、`docs/adr` 纳入扫描 | 快照纪律 |
| 补发历史版本 · Gitee 读数进 CI · 非默认端口的真正支持 | 见[发布清单](./README.md#发布清单每个版本)与前两版复盘 |

## 4. 验收

```bash
go build ./... && go vet ./... && gofmt -l .
go test -count=1 -run 'TestV15' ./cmd/ngm
go test -count=1 ./internal/... && go test -count=1 -timeout 40m ./cmd/ngm
bash scripts/check-docs-links.sh
go test -count=1 -run 'TestDocsAnchorsResolve' -v ./cmd/ngm
```

两张网都必须**证明过会红**：A 组用探针文档 + 名单绊线，B 组用"摘掉 `SetOutput`"对照。
