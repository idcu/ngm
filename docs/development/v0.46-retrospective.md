# v0.46 复盘 — **同一种错法，另一张网还在用**

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：v0.42 那张取值 flag 的网用的是**手抄**的 14 条表，
> 而源码里派生得出 **37 条**——**23 条从来没被这张网看过**，
> 其中一条又是 `css`（**同一个命令连着两版在漏**，病根还是"按文件名找源码"）。
> **产品代码 0 行改动。**

## 1. 逐组验收

### 1.1 先量再改 ✅

| 项 | 数 |
|----|----|
| v0.42 手写 map | **14** 条 |
| 源码派生 | **37** 条 |
| **从未被看过** | **23** 条 |

漏掉的里面，最有代表性的几条：

| flag | 为什么之前没人看 |
|------|-----------------|
| **`css --outfile=`** | `css` 住在 `typecheck.go` 里；**v0.45 漏的是它的布尔 flag，这一版漏的是它的取值 flag** |
| `typecheck --tsconfig=` | 手抄表只写了 `--engine` |
| `transform --dir=` · `build --dir=` · `init --dir=` … | `--dir` 归 v0.41 管，v0.42 的表里索性没写 |
| **`store prune --older-than=`** | 子命令层，v0.42 的表**结构上**够不到它 |

### 1.2 处置 ✅

1. v0.42 的表换成**按块派生**（`flagsetBlocksOf`，**跨文件**、带**声明种类**）——手抄表删掉；
   取值 flag = `String / Duration / Int`，于是 `--older-than` 这类也自动进来了。
2. 子命令层的参数底子用**块名本身**（`store prune`），不拼 `matrixArgs`
   ——否则会拼出 `store usage prune`（v0.42 那套只对命令层成立）。
3. 覆盖守卫扩到**全部种类**，且覆盖集由**三张网各自的选择函数**拼出来：

```
v0.43  命令层布尔   → boolFlagsOfCommand(t, cmd)
v0.45  子命令层布尔 → subcommandBoolPairs(t)
v0.42  取值（两层） → valueFlagPairs(t)
```

### 1.3 读数 ✅

| 网 | 读数 |
|----|------|
| v0.42 取值 flag | **37 条（源码派生）→ 36 拒绝 · 1 等价 · 0 次碰 CWD**，1.2 秒 |
| v0.43 命令层布尔 | 40 对 × 4 断言 · 跳过 0 |
| v0.45 子命令层布尔 | 2 对 × 4 断言 |
| 覆盖并集守卫 | **unowned flagsets: 0**（现在管**两种种类 · 两层**） |

### 1.4 守卫被拔掉一处**硬编码捷径** ✅

v0.45 的守卫里有一句：

```go
if len(parts) >= 2 && known[parts[0]] {
    continue        // "名字带空格 ⇒ 子命令层已被覆盖"
}
```

**那正是 v0.45 自己批评过的错法又一次出现**（按名字判断覆盖）。
这一版去掉它：一个 flag 只要被**任一条路**覆盖就算数，
而"路"只有上面那三个**选择函数**给出的集合说话。

### 1.5 牙齿 ✅

| 探针 | 结果 |
|------|------|
| 把取值的选择函数**收窄到命令层** | 红：`the flagset "store prune" (store.go) contributes --older-than, which no net reaches` |
| 让取值的选择函数**返回空** | 红，并**逐条**点名全部取值 flag（`add --ref-type` · `add --path` · …） |

第一道牙证明守卫真的在看**取值**这一侧；第二道证明它看的是**全部**，而不只是新增那一条。

## 5. 过程洞察

### 5.1 "手抄表"是这一族的通病，而且**换着地方长**

| 版本 | 形态 | 后果 |
|------|------|------|
| v0.43 | 手抄的 (命令, flag) map | 里面有几条**根本不存在的组合** |
| v0.45 | 按**文件名**派生 | 一个文件里住两个命令 ⇒ 算错对象 + 遮蔽整个 `css` |
| **v0.46** | **手抄的取值 flag map** | **23 条从未被看过** |

三次的红都不在产品上。判断标准不是"我这版有没有抄"，而是——
**覆盖集是从哪来的**：

- 从**源码/运行时**取 ⇒ 源码变了它跟着变；
- 从**我的记忆**取 ⇒ 它只反映我写表那天的认识，而**没人会去核对一张"看起来对"的表**。

### 5.2 上一版的教训，要同一晚就去找**同族**

v0.45 刚发现"按文件名派生"的洞，这一版就去找"还有谁在按文件名/手抄"——
结果：**又一处，而且在同一个命令上**（`css` 的取值 flag）。

> 一个洞被找到时，值得立刻问的不是"还有别的洞吗"，
> 而是 **"发现它的那条判据，别处也适用吗"**。
> v0.45 的判据是"覆盖集必须从源码派生"，而它对**取值 flag** 同样适用——
> 只是当时没人去问。

### 5.3 守卫里的"捷径"要一条条拔掉

v0.45 的守卫写着"名字带空格 ⇒ 已被覆盖"。它是**正确**的（当时子命令层确实被两张网分掉了），
但它是一条**断言式的捷径**：它把"覆盖"这件事的判断，从"查集合"换成了"看名字"——
而这正是它上一版刚刚栽过的错法。

> 守卫的强度不在它挡了多少次，而在**它下次还会不会说话**。
