# v0.74 计划 — **JS Git 库的标准（梳理 + 可执行自检）**

> 来源：用户提出——"对于真实的 js git 库，梳理其标准，以后用户自己的库文件都按照这个标准统一"。
>
> 一句话目标：把"一个能被当作 Git 依赖消费的 JS/TS 库该长什么样"写成**一页标准 + 一个判据**，
> 让自家库文件从此有唯一的对齐对象。

---

## 0. 起点：标准不能凭印象写

先取证，再动笔。三条事实源（都在代码里，可核对）：

| # | 事实 | 出处 |
|---|------|------|
| 1 | 入口推断是**三层**：`ngm.json` → `package.json`（exports → main/types）→ `./index.ts|js` | `internal/mappings/generate.go` 的 `InferEntry` |
| 2 | 传递依赖**只有一个来源**：上游根目录 `ngm.json`；写在 `package.json` 里的 Git 依赖只提示、不纳入 | `internal/resolve/graph.go`（`UpstreamFile`） |
| 3 | 依赖的安装钩子**默认不执行**（`postInstallPolicy` 默认 `deny`） | `internal/supplychain/policy.go` · ADR-009/012 |

由此推出的最硬的一条：**ngm 不替依赖构建** ⇒ 入口指向的产物必须已经提交在仓库里。

## 1. 处置

| 项 | 决定 |
|----|------|
| 标准页 | `docs/guides/js-git-library-standard.md`：必做 10 · 推荐 9 · 禁止 5，每条带"为什么"与"怎么验" |
| 判据 | `scripts/check-library-standard.sh`（22 项：13 必做 + 9 推荐），`.ps1` 转调同一实现 |
| 诚实边界 | 生态现状类条目标 🌐 并写明"本机离线未联网核对"；"ngm 会因此报错"的标 🔒 并给代码位置 |
| 例外 | 标准页末尾有"例外"小节：不遵守必须写下理由，不默不作声 |

## 2. 验收

```bash
bash scripts/check-library-standard.sh /path/to/lib            # 符合标准 ⇒ exit 0
bash scripts/check-library-standard.sh /path/to/lib --strict   # 推荐项也计入
bash scripts/check-library-standard.sh /path/to/lib --json     # 机器读（同一套事实）
```

**牙齿**（实测，四条）：加 `postinstall` / 放 `.npmrc` / 入口指向被 `.gitignore` 排除的 `dist` /
删掉 `version` ⇒ 各自红并点名；`--strict` 下"package.json 有 git 依赖而 ngm.json 没声明"也红。
