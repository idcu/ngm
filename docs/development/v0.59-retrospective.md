# v0.59 复盘 — **给"内部失败"一个自己的码（6）**

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：这一系列**第一次动退出码契约**（`0..5` → `0..6`）。
> 按纪律先立 [ADR-026](../adr/adr-026-exit-code-6-internal-failure.md)，
> 再把 v0.57 量出的那 16 处"算出来了却说不出去"从码 1 搬到码 **6**。
> 判据侧做了两件事：**码 6 可测量**（一个永远写失败的 writer），
> 以及——**逐处对账"退的是哪个码"**（只数处数抓不到"换了码"）。

## 1. 逐组验收

### 1.1 契约（ADR-026）

| 决定 | 内容 |
|------|------|
| 新码 | `CodeInternal = 6`，显示名 `InternalFailure` |
| 语义 | **内部失败**：ngm 自己没走完（panic）· 结论有了却送不出去（IO/编码/读取）· 错误**没走错误模型**（`errs.ExitCode` 兜底） |
| 不搬 | 码 1 的四类策略来源（漂移 · 引擎 · 漏洞 · 钩子）一个不动 |
| 传播 | 11 个命令的 usage 各加一行 `6  internal failure: …`；根帮助的全局约定加一行 |

取代的方案（都写进 ADR）：只改文档（v0.57 做过，解决不了"CI 分不清"）·
映射到 3（磁盘满不是配置问题）· 映射到 2（与完整性无关）· 留一个区间（ADR-025 的同一课：不留没人负责的空位）。

### 1.2 实现：16 处站点

| 站点 | 数量 |
|------|------|
| IO / 编码 / 读取失败（`write report` / `write json` / `marshal json` / `read stdin` / `write output` / `write bundle` / `write css` / `write listing` / `encode report`） | **14** |
| panic（`runWithRecovery`） | 1 |
| `errs.ExitCode` 的兜底（非 `NgmError`） | 1 |

它们从前各自写着**字面量 `1`** ✗；现在统一是 `errs.CodeInternal.ExitCode()` ✓
（数值收在一处 ✓）。

### 1.3 可测量 ✅（V22 的规矩）

`dispatch` 接受任意 `io.Writer`，于是**不必真去弄坏磁盘**：传一个永远写失败的 writer ✓。

读数：**5 个命令测到 6**（verify · why · outdated · tree · engines ✓），
**6 个记进缺口表并写明原因**（audit 需要 OSV 结果 ✓；build/typecheck/css/transform 需要配好的引擎 ✓；
integrations 需要真实的工具名 ✓）——**测不到也具名** ✓。

### 1.4 判据侧的两处改动

| # | 改动 | 为什么 |
|---|------|-------|
| 1 | V21 的上界不再硬编码 `5`，改成**读全局契约表** | 契约扩展时判据不该落后一版（它当时报了 11 次"declares exit code 6; the contract defines 0..5"） |
| 2 | V57 扩成**管两个码**，并**逐处对账"退的是哪个码"** | 见 §2 |

### 1.5 牙齿 ✅

| 探针 | 结果 |
|------|------|
| 把 `verify.go` 的 `return errs.CodeInternal.ExitCode()` 改回字面量 `return 1` | 红：`` `cmd/ngm/verify.go :: runVerify` 的站点**退的码对不上**：源码里是 [1]，登记说 [6] `` |
| 从文档那一行里撤掉类别 | 红（上一版已有同形牙齿） |
| 子测试名来自变量（表驱动） | 红：V56 从源码找不到 `t.Run("verify"` ⇒ **判据要求字面名字**（本版实测，已改成 5 个字面 `t.Run`） |

## 2. 判据的**洞**：只数处数，抓不到"换了码"

v0.57 那条判据数的是"每个函数里有**几处**站点" ✓。这一版改码时会发现：
把某处的 `errs.CodeInternal.ExitCode()` 换回字面量 `return 1`，**处数一样** ✗——
判据照样绿 ✗，而那一处的语义从"内部失败"变回了"策略失败" ✗✗。

**补法**：扫描时记下**每一处提的是哪个码**（`CodeInternal` ⇒ 6，其余 ⇒ 1 ✓），
登记侧的条目也说自己解释的是哪个码（source 由 `categoryCodes` 决定 ✓、
definition/helper 由 `tokenCode` 说明 ✓），然后**两个已排序的码表对账** ✓。

> 与 v0.57 那道牙齿（"同函数里多一处"）是同一族：**判据的粒度不够时，
> 它看不见的那一类改动正是最该被看见的**。

## 4. 设计偏离登记

| # | 计划写的 | 实际做的 | 为什么 |
|---|---------|---------|-------|
| 1 | 只改那 12–14 处 IO 站点 | 还改了 `errs.ExitCode` 的**兜底** | 它是"错误没走错误模型"——与"说不出去"同一类，而从前它退 1 会让 CI 把"有错误逃过模型"读成"上游漂移" |
| 2 | 以为 11 个命令都能测到 6 | 实测只有 5 个能（4 个要引擎、1 个要 OSV、1 个要真实工具名） | 先量再写：把能测的测掉，把不能测的**具名记进缺口表** |
| 3 | 子测试用表驱动（`t.Run(c.label, …)`） | 改成 5 个字面 `t.Run("verify", …)` | V56 从**源码**核对指针，表驱动的名字它看不见 |

## 5. 过程洞察

### 5.1 契约扩展要按"契约"的规矩办

这一次动的不是一个测试，而是**可观测契约**（脚本据它分支 ✓）。所以：
**先立 ADR**（写清决定、代价、替代方案）✓ → 再改实现 ✓ → 再让四条判据同步 ✓ →
最后文档（唯一事实源 `observability.md` ✓ + 用户侧 `cli.md` ✓ + 规格 `p0-core.md` ✓）。

顺带修掉一处**陈旧读数**：`p0-core.md` 的 `iota` 块注释还写着码 1 "**四种来源**"✗
（它没有出现在 v0.57 的判据范围内 ✓——那条判据只看 `observability.md` ✓）⇒ 已改并写明第五类去了哪 ✓。

### 5.2 "测不到"也要具名

V22 的规矩（声明了就要能测）在这一版第一次遇到"**一次要测 11 个**"✗。
处置不是把测不到的删掉声明 ✗（那是假话：它们**真的**会退 6 ✓），
也不是默默略过 ✗，而是：**能测的测掉、测不到的逐条写清为什么** ✓。

> 与 v0.44 那句"未证明要写下来"、v0.52 的登记表同源：**缺口本身要可见**。
