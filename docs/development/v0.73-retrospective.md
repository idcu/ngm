# v0.73 复盘 — **实现 ADR-028：依赖图形进 lock**

> 一句话结论：`ngm why` 从此读 lock 回答（**0 次 git 子进程、离线可用**，实测断言），
> SBOM 有真正的依赖关系段（CycloneDX `dependencies` / SPDX `DEPENDS_ON`，两种格式
> 同一份边）。**用户可见增量**：一个命令从"要触网"变成"不触网"。
> 另：实现时推翻了 ADR 的一处裁决（根边要一起存），已就地修订 ADR。

## 1. 逐组验收（ADR §5 五条）

| # | 验收项 | 结果 |
|---|--------|------|
| 1 | lock 字段 `requiredBy` 恒在 + 排序去重 | ✅ Marshal 归一（调用方可以把解析器给的顺序原样写进来）；nil 也写成 `[]`，输出里永不出现 `null` |
| 2 | 幽灵边被拒 | ✅ Validate 在**读取时**红，消息点名那个不存在的引用者并给下一步 |
| 3 | install / update 写入 | ✅ 直接把 `Node.RequiredBy` 交给 lock（序列化时归一） |
| 4 | `why` 离线 | ✅ **实测 `git.SpawnCount() == 0`**；来源写进报告（人读末行 + `--json` 的 `source`），旧 lock 退回并说明 |
| 5 | SBOM 依赖段 | ✅ CycloneDX `dependencies`（根 `ngm:root` + 各组件）、SPDX `DEPENDS_ON`；旧 lock 两段**整段省略** |

**读数**：

```
why（lock 带图）        0 次 git 子进程 · 来源 "lock"
why（旧 lock）          退回重新解析 · 来源 "resolved" · 报告明说
install 写出的 lock     直接依赖 requiredBy=[(root)]，HasGraph=true
sbom                    dependencies 1 条（根 → 直接依赖）；spdx DEPENDS_ON 1 条
sbom（旧 lock）         dependencies 段缺失、无 DEPENDS_ON（不编图）
```

## 3. 设计偏离登记

| # | 裁决写的 | 实现做的 | 为什么 |
|---|---------|---------|-------|
| 1 | 直接依赖 = `[]`，根边不存 | **根边一起存**（`(root)` 进 `requiredBy`），ADR 已就地修订（§2.1b） | 一个依赖可以同时是"根声明"与"被上游引用"（root wins）。只存依赖引用者会丢掉 `RootDeclared`，`FindPaths` 就不再从它出发 ⇒ `why` **少列一条路径**。这是实现时才暴露的缺陷——裁决时没有想到 root wins 与来源记录的交叉 |
| 2 | — | CycloneDX 根用文档内 ref `ngm:root`；SPDX 根边从 `SPDXRef-DOCUMENT` 出发 | 根不是任何 purl 能表达的 Git 包；两处都写清了理由 |
| 3 | — | 边表存**条目 Key**，两种格式各映射到自己的 ref | 一份边、两种映射，才不会出现两棵树 |

## 4. 缺陷清单

| # | 缺陷 | 谁发现 | 处置 |
|---|------|-------|------|
| 1 | 裁决时漏掉 root wins 与来源记录的交叉（见 §3.1） | 实现时（写 `GraphFromLock` 需要 `RootDeclared`，而它无处可来） | 就地修订 ADR + 把根标记同值钉成判据（`TestRootRequirerMatchesResolve`） |

| 4 | 初版 `idOfPurl` 用线性反查把 purl 换回 SPDXID（笨且可能返回空） | 自查 | 边表改存 Key，各格式自己映射（§3.3） |

## 5. 过程洞察

### 5.1 一份边、两个出口——"同一事实两个表达"的代价是可以消灭的

SBOM 的两种格式都要依赖图形。第一版让 CycloneDX 存 purl、SPDX 再反查回 ID，
立刻出现了"两个表达可能不一致"的缝。把边表统一到**条目 Key**（与 lock/resolve
同口径），两种格式各自做一次映射，缝就消失了。教训与 v0.70 的 `FromLock`/`Sort`
同一门：**规则只写一处，出口各自翻译成自己的语言**。

### 5.2 判据先写，才知道实现哪里站不住

`GraphFromLock` 需要 `RootDeclared`，而裁决的形状里没有它——这个洞是**写实现时**
才被踩到的，不是设计评审能看出来的（它藏在 root wins 那条分支里）。
这与 v0.72 的"格式契约先立 ADR"不矛盾：ADR 把 90% 的临场发明提前消灭了，
剩下 10% 由实现时的判据逼出来，并**立刻回写 ADR**——这才是完整的循环。

### 5.3 用户可见的增量可以是"少做一件事"

本版没有新命令、没有新字段给用户读（除了 lock 里那一行），但它把一个每天都会被问的
问题（`why`）从"要触网、离线不可用"变成"0 次子进程"。**省掉的工作量也是增量**，
前提是它被量出来（`git.SpawnCount`）并被用户看见（报告末行那句来源）。
