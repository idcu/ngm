# v0.86 计划 — **镜像覆盖：从写死的快照到按需实测**

> 来源：[v0.85 复盘](./v0.85-retrospective.md) §3 候选 4（把发布读数做成 CI 可见摘要）。
>
> 一句话目标：文档里那几处"GitHub 有 65 个 tag / 60 个 release"是 **2026-10-10 的快照**。
> 让同一件事**随时可再测**——一条只读命令，两次请求。

---

## 1. 计划

| # | 项 | 落位 | 验收 |
|---|----|------|------|
| 1 | `scripts/check-mirror-coverage.sh`：读镜像 tag 数 / release 数 / 最新 release，算 `未推送 = 已交付 − 镜像 tag` | 新脚本 + `.ps1` 转调同一实现 | 判据三侧：读得到 · HTTP 500 ⇒ 3 · 连不上 ⇒ 3 |
| 2 | 它是**读数不是门禁**：缺口不判失败；只有"问不到"才 exit 3 并明说"不下结论" | 脚本 + CI | v0.85 那条教训的第二处应用 |
| 3 | 接进 CI 的 `release-state` job | `ci.yml` | `continue-on-error`（理由同上） |
| 4 | 判据用**本地假 API**（httptest）喂它，不碰网络 | `cmd/ngm/v086_mirror_coverage_test.go` | 三侧 |

## 2. 不做

- 不让"缺口"让 CI 变红（推送是仓库所有者的动作）；
- 不改文档里那些快照数字的**性质**（它们仍是快照），只加一条"随时可再测"的路；
- 不把两条源的读数合并成一个"总覆盖率"分数（两源的语义不同：release 与 tag 不是一回事）。
