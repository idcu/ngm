# v0.41 复盘 — **`--dir` 的四种拼法 · 空值必须被拒绝**

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：这一版枚举 `--dir` 的**拼法**，并**抓到一处危险的产品缺陷**：
> `--dir=`（显式空值）被**静默当成当前目录**——`ngm add … --dir=` 改的是 CWD 的 `ngm.json`，
> `ngm init … --dir=` 在 CWD 里**建出项目**。
> 这条判据的现场证据是它**自己造出来的**：探针跑过之后，仓库的 `cmd/ngm/` 里多了 `ngm.json` 与 `src/`。

---

## 1. 逐组验收

### 1.1 两族 ✅

| 族 | 读数 |
|----|------|
| **四种拼法**（`--dir=X` / `-dir=X` / `--dir X` / `-dir X`） | **19/19 输出逐字节相同** ✅ |
| **显式空值**（`--dir=` / `-dir=` / `--dir ""`） | **19/19 被拒绝**，且**CWD 原封不动** ✅ |

覆盖 **19 个命令**（21 减去 2 个不接受 `--dir` 的全局命令），耗时 **1.5 秒**。

### 1.2 产品缺陷（本版修掉）✅

```
修复前：$ ngm add github:x/dep@v1 --dir=      → exit 0，added … in <当前目录>/ngm.json
修复后：$ ngm add github:x/dep@v1 --dir=      → exit 3
        ngm: `--dir=` was given an empty value — that is almost always an unset variable
        (`--dir="$PROJ"`); pass a real path, or drop the flag to use the current directory
        + 该命令的用法文本
```

**根因**：Go 的 flag 把 `--dir=` 解析成空串，而**空串与"没给这个 flag"在后续代码里无法区分**——
于是命令把空值当成 CWD。

**修法**：在 `dispatch` 里、命令 Run **之前**拒绝（`emptyDirFlag`：三种写法都挡），
exit 3 + 一句点名成因的话 + 用法文本。

> 只挡"**显式**给了空值"这一种；不给这个 flag 仍然合法（默认 `.`）。

### 1.3 牙齿 ✅

| 探针 | 结果 |
|------|------|
| 回退修复 | **4 个失败**，报的是副作用证据：`` `--dir=` 静默退化成了 CWD：命令在**当前目录**里留下了 [ngm.json src] `` |

**为什么只有 4 个**：只有**会写东西**的命令（`init` / `add` / …）既退 0 又在 CWD 留下文件；
只读命令在空目录下本来就非零（找不到 `ngm.json`）——那类行为**没有危害**，网正确地放行。
判据抓的是**危险的那一半**。

## 5. 过程洞察

### 5.1 "没给"与"给了空值"必须能区分

Go 的 flag **不区分**这两件事：`fs.String("dir", ".", …)` 在 `--dir=` 时给出 `""`，
在没给时给出 `"."`——但**用户的意思完全不同**：

| 输入 | 用户想说什么 | 实际含义 |
|------|------------|---------|
| 不给 `--dir` | 用当前目录 | 当前目录 ✅ 一致 |
| `--dir=.` | 显式说当前目录 | 当前目录 ✅ 一致 |
| `--dir=` | **`$PROJ` 是空的**（九成是变量没展开） | 当前目录 ❌ **不一致** |

第三行是这一类缺陷的通名：**一个"空"被当成了"默认"**，而它在用户那里的意思是"我传了个值，但它是空的"。

### 5.2 探针把**仓库**写脏了——而那是缺陷的现场

跑那族探针时，`ngm add … --dir=` 真的在 `D:\repos\mine\ngm\cmd\ngm\` 里建出了 `ngm.json` 和 `src/`。
我是在看输出里的路径时发现的（`added … in D:\repos\mine\ngm\cmd\ngm\ngm.json`）。

这一族（**夹具会改掉状态**）在本项目里已经出现过六次：

| 版本 | 形态 |
|------|------|
| v0.16 | 篡改掩盖了漂移 |
| v0.21 | 夹具被前面的命令改掉 |
| v0.31 | 删了个不存在的路径 |
| v0.39 | 坏目录让配置错误掩盖参数处理 |
| v0.40 | `init` 建出目录、`add` 加进依赖（两次） |
| **v0.41** | **把仓库本身写脏** |

处置这一版多了一条：**跑可能写文件的探针前，先把 CWD 换到临时目录**——
这也直接成了新网的判据设计（§3 偏离 1）。

### 5.3 判据的第三次演进：从"文本"到"副作用"

| 版本 | 判据看什么 |
|------|-----------|
| v0.33 | 文本里点名了一个**真实存在**的东西 |
| v0.40 | 文本会**回显** token，所以不能用"出现过什么字符串" |
| **v0.41** | **干脆不看文本**：只看"那个目录跑完之后是不是还是空的" |

副作用不会说谎——因为它**就是危害本身**。这条经验值得推广：
**凡是"某个东西被改变了"能表达成副作用时，就别用文本表达。**

### 5.4 只抓到了 4 个，而这是对的

牙齿跑出来只有 4 个失败（19 命令 × 3 写法 = 57 个格子）。
原因是判据**只在有危害的地方响**：只读命令在空目录下本来就退非零，不会写任何东西。

这提醒一件事：**"红了几条"不是判据好坏的指标**——
一个只抓危险格子的判据，比一个把 57 个格子全报红的判据更有用（后者会被忽略）。
