# v0.90 计划 — **登记表是待办清单，不是永久豁免**

> 来源：[v0.89 复盘](./v0.89-retrospective.md) §4 候选 3。
>
> 一句话目标：把 v0.89 那张"跑不了的东西"的登记表**变短**——能跑的就去跑；
> 顺手发现的两类真缺陷（入口吞参数 · 一个检查慢 4 倍）一并处置。

---

## 1. 计划

| # | 项 | 验收 |
|---|----|------|
| 1 | **五个 `.ps1` 入口真的跑一次**，每个都用**必然失败的输入**验退出码与点名传了回来 | 登记表 5 → 2 条 |
| 2 | **入口不许吞参数**：`.ps1` 必须转发同名 `.sh` 接受的每个长选项（没有入口的要写明原因） | 牙齿：拿掉 mirror 入口的 `--api-base` ⇒ 红 |
| 3 | **`check-docs-links.sh` 的性能**：路径规范化从"每条链接一次子进程"改成纯 bash | 实测数字（改前 133.72s）+ 负例网 |
| 4 | 为 `check-release-status.sh` 补 Windows 入口（它是"开工先对状态"那条读数） | 实跑 + `-Published` 转发 |

## 2. 为什么这三件是一件事

它们是同一个病的三个面：**交接处没有判据**。

- 入口与实现交接 ⇒ 参数被吞（#2）；
- 判据与入口交接 ⇒ "只被解析过，从没被跑过"（#1）；
- 实现与自己交接 ⇒ 每条链接起一个进程，谁也没量过（#3）。

## 3. 不做

- 不推 tag / jsonkit（仓库所有者的动作）；
- 不动 `subPath` 端到端（等推送）；
- 不把 `check-docs-links.sh` 重写成"一个进程搞定"（能到秒级，但那是**重构**，
  这一版只要"去掉每条链接的子进程"这个低风险的大头；候选留给 v0.91）。
