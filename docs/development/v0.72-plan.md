# v0.72 计划 — **裁决：依赖图形进 lock（ADR-028）+ 停止清单对账**

> 范围来源：[v0.71 复盘](./v0.71-retrospective.md) §7 候选 1/3，
> 与 [评估报告 2026-10-09](../internals/assessment-2026-10-09.md) 第 4 层（明确停止）。
>
> 一句话目标：**把最后一个大产品候选的形状定死（ADR-028，v0.73 实现），
> 并把"明确不做"的三条停止项逐条对账落账。**

---

## 0. 起点

评估的第 0–3 层已经交付（v0.66–v0.70）；第 3 层第三条（`verify --json` 证据化）
按评估原话"等消费方"；第 4 层是三张停止项；第 5 层（找真实用户）是人的动作。
产品侧剩下的最后一个大项是**传递依赖图形进 lock**——它有三处现成的需求
（`why` 离线、SBOM 依赖段、attest 的未来形态），而图在解析时本来就是现成的。

按本项目的纪律：**格式契约的变更先立 ADR**——lock 是对外承诺（"一旦发布不可随意变更"），
形状错了的代价是迁移与信任。

## 1. 处置

| 项 | 决定 |
|----|------|
| **ADR-028** | 每依赖新增**恒在**的 `requiredBy`（直接引用者，排序去重，直接依赖为 `[]`）；lockfileVersion **不动**（新增可选字段 + 解码器忽略未知字段是既有契约，`subPath` 有先例）；只存**直接边**（全路径是指数的，ADR-024）；`Validate` 拒绝幽灵边 |
| 消费端裁决 | `why` 有图 ⇒ **离线 0 spawn**，无图 ⇒ 现行为 + 注明来源；SBOM 增 CycloneDX `dependencies` / SPDX `RELATIONSHIPS`；`verify` / `tree` / `attest` **明确不变** |
| 停止清单对账 | roadmap 新增"明确不做"小节：三条停止项逐条对账，全部维持；同时说清 **v0.71 的判据为何不违约**（回应已发生的缺陷 ≠ 对假想缺陷造网） |
| 勘误 | v0.71 复盘把评估第 4 层误写为"协议级差距"——修正，并把真正候选指向 ADR-028 |

## 3. 流程
