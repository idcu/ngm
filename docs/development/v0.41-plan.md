# v0.41 计划 — **`--dir` 的四种拼法 · 空值必须被拒绝**

> 范围来源：[v0.40 复盘](./v0.40-retrospective.md) §7 候选 1。
>
> 一句话目标：v0.40 枚举了参数的**位置**（顺序 / 重复 / `--`）。这一版枚举 `--dir` 的**拼法**：
> `--dir=X` / `-dir=X` / `--dir X` / `-dir X`，以及**显式空值**。

---

## 0. 两件事

| 族 | 判据 |
|----|------|
| **四种拼法** | 必须**输出逐字节相同**（依据：`flagSpec` 同时登记长短前缀，Go 标准库把 `-`/`--` 当同义） |
| **显式空值** | `--dir=` / `-dir=` / `--dir ""` 必须**被拒绝**，且**绝不能在当前目录里留下东西** |

## 1. 第二族是实测出来的

Go 的 flag 把 `--dir=` 解析成空串，而空串与"没给这个 flag"在后续代码里**无法区分**——
于是命令**静默地把空值当成 CWD**。实测后果：

```
$ ngm add github:x/dep@v1 --dir=      → 改的是**当前目录**的 ngm.json
$ ngm init github.com:x/app --dir=    → 在**当前目录**建出项目
```

最可能的来源是**变量展开失败**（`--dir="$PROJ"` 而 `$PROJ` 未设），而用户看到的是"成功了"。

> 这条判据的现场证据是它自己造出来的：探针跑过之后，仓库的 `cmd/ngm/` 里多了 `ngm.json` 与 `src/`。
> 已清理；而它也正好说明为什么"空值必须被拒绝"。

## 2. 判据只看**副作用**

把 CWD 换成**一个空目录**，跑完之后**它必须还是空的**——

比读输出可靠得多（v0.40 已经吃过"输出会回显"的亏）。
