# v0.77 计划 — **标准覆盖第二种形态（CJS / 带构建 / monorepo）+ `ngm add` 实跑**

> 来源：[v0.76 复盘](./v0.76-retrospective.md) §7 候选 1 与 2。
>
> 一句话目标：把标准套在**别的包形态**上，看它是不是只会认"第一种库"；
> 顺带把 `ngm add` 这条入口用真实公网库走一遍。

---

## 0. 起点：一条标准只在自己写的那一个样本上跑过，等于没验证

v0.74 定的标准、v0.75 的第一个实现（`canonical-json`）与 v0.76 的端到端，
全都围绕**同一种形态**：单包 · ESM · 零构建 · 仓库即产物。真正的问题是：
**换一种形态，它是误伤还是真抓？**

因此本版造两个 fixture（先取证，再改代码）：

| 形态 | 关键差异 |
|------|---------|
| A · CJS 优先 + 有构建步骤 | `"type": "commonjs"`（**显式**）+ `main`/`exports.require` 指向 `dist/`（产物已提交）+ `scripts.build`/`prepublishOnly` |
| B · monorepo | 根带 `workspaces` + `private`，根**不是包**；子包各自带 `package.json`/`ngm.json` |

## 1. 取证的结论（先跑，后改）

- A：唯一红的是推荐项 `esm-first`——而它**显式写了** `type: commonjs`。
  判据自己的措辞是"CJS 需显式说明"，却仍然要求 `type=module` ⇒ **推荐项不可满足**。
- B：根的 `entry-resolvable`（必做）+ 四条推荐项全红，而"根不是包"⇒ 五处**误伤**。

## 2. 处置

| # | 修正 | 落点 |
|---|------|------|
| 1 | 显式 `type: commonjs` 记为**合格**（写明的选择被尊重；"别让形态靠猜"才是要求） | 自检器 `esm-first` |
| 2 | **monorepo 模式**：根声明非空 `workspaces` ⇒ 根不是包，六条包专属判据记为**不适用**；子包**用同一支脚本**逐个体检，结论带路径前缀；`workspaces` 里没有 `package.json` 的目录**显式失败**；私有根可缺 `version` | 自检器（新角色 `mono-root` + 子包递归 + JSON 合并） |
| 3 | `.gitattributes` / `.gitignore` 看**仓库根**（LF 声明与"产物是否被忽略"都是仓库级事实） | 自检器 |
| 4 | 子包结果读不出来时**不许静默丢**：变成一条 `child-result-unreadable` 的必做失败 | 自检器合并步骤 |

## 3. 验收

```bash
bash scripts/check-library-standard.sh <形态 A>  --strict   # exit 0
bash scripts/check-library-standard.sh <形态 B>  --strict   # exit 0，根 6 条不适用 + 子包逐个
bash scripts/check-library-standard.sh <形态 B>  --json     # 合并后子包 id 带 packages/*/ 前缀
# 回归：canonical-json / vendored 副本 / 形态 A 全绿
# 牙齿：删子包的 exports ⇒ 红；workspaces 目录缺 package.json ⇒ 红
```

`ngm add` 实跑（候选 2）：

```bash
ngm add gitee:idcu/canonical-json@v1.0.0 --ref-type=tag   # 写回声明
ngm install && ngm verify && ngm why && ngm mappings validate
```

## 4. 流程

交付即提交、提交即打 tag。
