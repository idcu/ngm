# v0.98 计划 — **对账用在另一对：入口路径规范化**

> 来源：[v0.97 复盘](./v0.97-retrospective.md) §6 候选 1 / 4。
>
> 一句话目标：v0.97 把「两条实现必须一致」做成了判据（用在链接检查上）。
> 这一版把它用在**另一对**——入口路径规范化（产品 `relPath` / 自检器 `rel_path`），
> 并专门喂**边缘形态**，看它们会不会分家。

---

## 1. 先看有哪些成对实现（不要瞎挑）

| 候选 | 结论 |
|------|------|
| `subPath` 校验 | **不是成对**：v0.82 已统一（`config.validateDepPath` 转调 `resolve.ValidateSubPath`），无需对账 |
| `exports` 解析 | 成对（Go `parseExports` / shell 里那段 Node 内联脚本）——**逐字读下来是一致的**，但只被 11 种形态对过 |
| **路径规范化** | 成对（Go `relPath` / shell `rel_path`）——**读下来就有两处分家** |

## 2. 读出来的两处分家（都在 Windows 上看不出来）

| 形态 | 产品旧行为 | 自检器 | 为什么看不出 |
|------|-----------|--------|-------------|
| `main: "src\\x.js"` | `filepath.ToSlash` 转换——**Windows 上转、Linux 上不转** | 一律 `tr '\\' '/'` | 本平台正好会转 |
| `main: "//src/x.js"` | 只剥一个前导 `/` ⇒ `.//src/x.js` | 剥到不剩 ⇒ `./src/x.js` | 两个字符串指向同一文件，但**打印出来不一样** |

## 3. 计划

| # | 项 | 验收 |
|---|----|------|
| 1 | 修产品侧（产品是契约）：反斜杠无条件转 `/`；前导斜杠剥到不剩 | 单元判据 12 格；牙齿：改回 `TrimPrefix` ⇒ 红 |
| 2 | 对齐网语料 11 → 22 种形态（`exports` 数组/null/嵌套/空白串/`*` 模式；`main` 的反斜杠/多斜杠/空白/裸文件名） | 27 个子测试全绿（实测 66.8s） |
| 3 | 诚实边界写进注释：反斜杠那格在本机**无法用行为分辨**，价值在 Linux CI | 不假装本机验证过 |

## 4. 不做

- 不推 tag / jsonkit（只为发布与镜像覆盖）；
- 不改 `exports` 解析（读下来两侧一致，且新形态证明它扛得住边缘）；
- 不为"边缘形态"造产品行为（例如给 `*` 模式做展开）——那是**特性**，不是对账。
