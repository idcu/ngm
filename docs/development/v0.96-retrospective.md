# v0.96 复盘 — **判据不该是平台相关的**

> 计划：[v0.96 计划](./v0.96-plan.md)
>
> 一句话结论：链接的存在性判据在 Windows 与 Linux 上给出不同结论（同一份仓库、同一份判据）。
> 这一版把"大小写"接进判据——放在 Go 侧（逐段 `ReadDir`），而不是塞回刚提速 100× 的 shell 检查。

---

## 1. 病是什么

| 平台 | `[x](./Guides/a.md)`（磁盘上是 `guides/`） |
|------|------------------------------------------|
| Windows | **通过** |
| Linux CI | **失败** |

一台机器说"没问题"、另一台说"红了"，而两份报告的**判据是同一份**——
这正是"仪器说谎"的一种：不是判据错了，是它**依赖了平台**。

## 2. 先量再改（与 v0.92 / v0.93 同一纪律）

| 问 | 答 |
|----|----|
| 全仓仓库内链接 | **2127 处** |
| 大小写不一致 | **0 处** |

⇒ 加这条判据不引入任何新红，守的是下一次。

> 顺带核了一件事：这条判据数出 **261 个文件**，而 v0.93 的扫描数出 253。
> `find docs -name '*.md' | wc -l` = **260**（+ 根 README = 261）⇒ 差值来自**期间新增的文档**
> （v0.92 ~ v0.95 各两份计划/复盘），不是漂移。差一点就把它当成"两个检查数不一致"来查——
> 值得记下来：**读数不一致时，先看事实源会不会自己长大了**。

## 3. 分工，而不是叠加

shell 检查刚（v0.91）才从"每条链接一个子进程"降到"一个 awk 进程"（1.33s）。
逐段核对大小写要**读目录**，在 awk 里做不到；放回 shell 就又是一次 per-link 开销。

于是分工写下来：

| 检查 | 负责 | 实现 |
|------|------|------|
| 存在性 | shell（快、跨平台不敏感） | `check-docs-links.sh` |
| **大小写** | Go 判据（逐段 `ReadDir` + 目录缓存） | `TestV96DocLinkCaseIsExact` |

两者覆盖同一批文件与链接（`docs/**/*.md` + 根 `README.md`；行内代码剥掉；跨仓 / 锚点 /
被忽略目录跳过；destination 按平衡括号解析——与 v0.92 同口径）——
**同一批输入、两种判据**，而不是两条各自走样的实现。

## 4. 牙齿

真仓库里没有不一致的链接可试 ⇒ 核心函数收 `root` 参数，用**临时树**上牙：

```
docs/x.md:  [对](./guides/a.md)                     → 不报
            [错](./Guides/a.md)                     → **报**（要求两边写法都出现在理由里）
            [也对](../docs/guides/a.md)              → 不报
            `[行内代码里的不算](./Guides/a.md)`        → 不报（行内代码先剥掉）
```

断言里还有一条"应当恰好扫到 3 处"——防的是"把行内代码也算进来"这类范围漂移。

## 4.5 顺带：围栏代码块整块跳过（自己的复盘把这条检查打脸了）

写这份复盘时，我在上面那个"牙齿"小节里用围栏代码块演示了**一条大小写错误的链接**——
于是 `check-docs-links.sh` 当场报了 **3 条坏链接**，全是**示例**。

这正是文件头里写着的那个已知边界（"只剥行内反引号；跨行的代码块由下面的事实兜住：
代码块里的路径通常不是真实相对路径"）——而**那个"事实"当场不成立**。

处置：`link_scan` 加一个两行状态机（``` 开、``` 关，每文件重置）⇒ 围栏块**整块跳过**，
并补了黄金用例（块里的链接不报 + **块之后**的链接仍然报——后者证明状态机真的关掉了）。

> **一个会误报的门禁会被忽略，比漏报更糟**——这条检查自己写着这句话，
> 而这次是它自己的复盘给它提供的第一手反例。
