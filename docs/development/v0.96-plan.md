# v0.96 计划 — **把"大小写"纳入链接检查（判据不该是平台相关的）**

> 来源：[v0.95 复盘](./v0.95-retrospective.md) §4 候选 2 / 更早的候选（v0.94 §5 候选 3）。
>
> 一句话目标：`check-docs-links.sh` 的存在性判据在 Windows 与 Linux 上给出**不同结论**
> （同一份仓库、同一份判据）。把"大小写"这件事接到判据里。

---

## 1. 问题

| 平台 | `[x](./Guides/a.md)`（磁盘上是 `guides/`） |
|------|------------------------------------------|
| Windows | **通过**（文件系统不区分大小写） |
| Linux CI | **失败** |

同一个仓库、同一份判据、两个结论——这正是本项目反复吃亏的那种"看起来在检查"。

## 2. 为什么不在 shell 里做

shell 检查刚刚（v0.91）才从"每条链接一个子进程"降到"一个 awk 进程"（1.33s）；
逐段核对大小写要**读目录**，在 awk 里做不到，放回 shell 就又是一次 per-link 开销。

⇒ 分工：

| 检查 | 负责 | 实现 |
|------|------|------|
| 存在性 | shell（快、跨平台不敏感） | `check-docs-links.sh`（awk + 内建） |
| **大小写** | Go 判据（逐段 `ReadDir`，带目录缓存） | `TestV96DocLinkCaseIsExact` |

两者覆盖**同一批文件与链接**（`docs/**/*.md` + 根 `README.md`；行内代码剥掉；
跨仓 / 锚点 / 被忽略目录跳过；destination 按平衡括号解析——与 v0.92 同口径）。

## 3. 计划

| # | 项 | 验收 |
|---|----|------|
| 1 | 逐段核对磁盘上的真实大小写 | 全仓 2127 处链接**先量**：全部一致 ⇒ 0 处新红 |
| 2 | 报错要说清两边写法（写的是哪个、磁盘上叫哪个） | 牙齿（临时树）：恰好报 1 条，且两边的名字都在里面 |
| 3 | 核心函数收 `root` 参数 | 于是能用临时树上牙（真仓库里没有不一致的链接可试） |

## 4. 不做

- 不推 tag / jsonkit（仓库所有者的动作；**推送不再影响验证**，只剩发布与镜像覆盖）；
- 不把大小写检查塞回 shell（理由见 §2）；
- 不顺手把 shell 检查里 `.md`/`.txt` 的 `-f` 也搬过来（存在性归它，保持单一职责）。
