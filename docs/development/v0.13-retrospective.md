# v0.13 复盘 — 把"缺陷形状"固化成网

> 体例与各版一致：逐组验收 → 未达成项 → 设计偏离登记 → 缺陷清单 → 过程洞察 →
> 指标 → 下一版候选。
>
> 范围来源：[v0.12 复盘](./v0.12-retrospective.md) §5.5 与 §7 候选 #5；
> 实施计划：[v0.13 计划](./v0.13-plan.md)。
>
> 一句话结论：**本版没有发现新的产品缺陷，这是它作为"固化"版本的特点**——
> 它把 v0.12 抓到的两类形状变成了两张会自动变红的网（其中一张是**行为级**的），
> 并**主动拒绝**了一张会漏报的网。副产品是全仓过期读数扫描。

## 1. 逐组验收

### 1.1 A1 — "接受的输入被静默忽略"（v0.12 D3 的形状）

| 项 | 结果 | 证据 |
|----|------|------|
| 网：读 `fs.Arg` 的文件必须校验 `fs.NArg()` | ✅ | `TestV13PositionalArgsAreBounded`；覆盖 11 个读位置参数的文件 |
| 判据的代价写清楚 | ✅ | 测试注释写明它是**文件级**判据、**可能漏报**（若某命令把解析搬到别的文件） |
| **牙齿验证** | ✅ | 一次性探针（一个只读 `fs.Arg` 不校验个数的函数）→ 网变红并**点名文件**；删探针 → 恢复绿 |

### 1.2 A2 — "`--offline` 被绕过"（v0.12 D1 的形状）

| 项 | 结果 | 证据 |
|----|------|------|
| 行为级判据：冷 mirror + `--offline` ⇒ **0 次 git 子进程** | ✅ | 实测**精确为 0**（不是"很小"） |
| 报告必须说出真正的原因 | ✅ | 断言 `no local mirror`（只有 `offlineEnsureMirror` 会产出它） |
| **对照**：暖 mirror 必须起 git | ✅ | 实测 > 0，因此"零次"不是仪器坏了 |
| 用次数而不是输出文本 | ✅ | 与 v0.6 的 spawn 预算同源：**次数优先于秒数**，而且这里连秒数都不需要 |

### 1.3 A3 — 故意不做的网（**本版最该记住的一条**）

| 项 | 结果 |
|----|------|
| 一张"注册了 `--offline` 的命令文件必须把它交出去"的源码网 | ❌ **不做，并写明理由**：它在当前代码上全绿（6 个文件全过），**但 D1 也会通过它**——当时的 `outdated` 确实把 `Offline:` 交给了检查器，只是检查器自己只在 branch 分支读它。按项目自己的话：**会漏报的门禁等于没有** |

> 这是"判据的强度"第一次被**主动**用来否决一张网（此前只是被动地修误报）。

## 5. 过程洞察

### 5.1 "会漏报的门禁等于没有"——第一次**主动**应用

v0.12 学到的是"判据过严会误报 → 门禁被忽略"。本版遇到的是**反面**：
一张网在当前代码上全绿，但**它挡不住它要挡的那个缺陷**（D1 会通过它）。
处置不是"先加上再说"，而是**不加** + 把理由写进计划——**一张绿着的、挡不住东西的网，
比没有网更糟**，因为它会把下一个人的注意力消耗在"这里已经检查过了"。

### 5.2 对照不是仪式，它是"仪器在工作"的证据

A2 的断言是"0 次 spawn"。一个恒为零的计数器会让它永远变绿。
所以同一段里必须有"暖 mirror ⇒ > 0"。v0.11 的 `waitdelay_test.go`、
v0.12 的 `atomic_test.go` 都做过同一件事——这是第三次，
说明它已经从"个人习惯"变成**本项目的网的标准形状**：

> **每张断言"什么都没有发生"的网，都要配一条"确实会发生"的对照。**

### 5.3 凡是数字，都要能一条命令复读

B 组修掉的四处过期读数里，有三处是**数字**（锚点数、缺几个版本、最新可取版本）。
它们过期的原因都一样：**写下来的时候是真的，之后没人再读一遍**。
处置不是"下次注意"，而是给数字绑一条读数：

| 数字 | 它的读数 |
|------|---------|
| 锚点数 | `go test -run TestDocsAnchorsResolve -v ./cmd/ngm`（打印实测值） |
| GitHub release 缺哪些 | `bash scripts/check-release-status.sh --published` |
| Gitee 发行版缺哪些 | `powershell -File scripts/check-gitee-release-status.ps1` |
| tag 与复盘是否配对 | CI job `release-status` |

### 5.4 一个版本的"范围"可以不包含任何实现改动

v0.10 实现 0 行改动（把检查推到最外圈），v0.13 不新增能力（把形状固化成网）。
两者都在做同一件事：**让已经知道的结论不再依赖人的记忆**。
这类版本看起来"没做什么"，但它决定了下一个版本**不必再发现同一件事**。
