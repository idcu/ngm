# v0.56 计划 — **把更早那批契约网也审一遍**

> 范围来源：v0.53 §4 的遗留——"覆盖集来源表只登记了从 v0.41 起引入派生表的那批网"。
>
> 一句话目标：**登记表要覆盖到"该被审的网"**，而不是"我最近审过的网"。
> 审的方式是**普查**（逐个回答"覆盖集从哪来"），不是逐个读代码。

---

## 0. 起点

`netCoverageSources` 当时只有 **12 张网**，而 `cmd/ngm` 下 v0.2x~v0.3x 还有
**24 个契约测试函数**从未被问过"你的覆盖集从哪来"。

## 1. 普查（清单化，一次问清）

对每个早期契约网回答四件事：文件与真名 · 覆盖集来源（源码/文档/运行时表/手写表）·
若是手写表则条目是什么、有没有防漂移机制 · 该登记为"来自实现"还是"具名例外"。

**顺带要找的**：手写表且**没有任何防漂移机制**的网。

## 2. 预期产出

1. 登记表补全（并补上对应的**派生入口**名称）；
2. 普查发现的"手写且无防漂移"里，**能当场做掉的当场做掉**；
3. 做不掉的写进候选，并在复盘里说明为什么；

## 3. 验收

```bash
gofmt -l . && go vet ./... && go build ./...
go test -count=1 -run 'TestV53|TestV56|TestV35|TestV22' -v ./cmd/ngm
go test -count=1 ./...          # 整套，不手挑
bash scripts/check-docs-links.sh
```

**牙齿**：每条新判据都要有一个**照着回归路径**写的探针，并且要能报出具体的名字。
