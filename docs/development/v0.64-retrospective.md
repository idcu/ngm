# v0.64 复盘 — **`schemaFiles` 不再是一份要人记着的清单**

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：`schemaFiles` 那 3 条手写清单派生化之后，**"新增一份配置、忘加一行 ⇒
> 检查静默变松"** 这条路径没有了——现在那条路径是"文档加一行 ⇒ 判据红 ⇒ 清单被迫补齐"。

## 1. 逐组验收

### 1.1 派生：三处闸门

`TestV64SchemaFilesAreDerivedFromDocsAndSource`：

| 闸门 | 信号 | 为什么需要 |
|------|------|-----------|
| ① 文档侧 | `configuration.md` 的配置文件表（首格是反引号包着的 `.json` 名）⇒ 认出 **4 个名字**（`ngm.json` · `ngm.mappings.json` · `ngm.engines.json` · `config.json`） | 文档自己说"这些是配置文件" |
| ② 代码侧 | 名字出现在**代码行**（跳过纯注释行 ⇒ v0.57 那课）里，且是 `X = "…"` 或 `filepath.Join(…, "…")` | **定义方要解析路径**；消费者只是提到名字 |
| ③ 形状侧 | 该文件至少有一个带 json tag 的字段 | 它确实在定义 schema |

读数：**3 derived** ✓ ——
`internal/adapter/catalog.go` · `internal/config/config.go` · `internal/mappings/schema.go`，
与手写清单**逐字相同** ✓。

### 1.2 两条反例把形状钉死（这是本版最值钱的部分）

| 反例 | 为什么它**不该**进来 |
|------|-------------------|
| `internal/verify/graph.go`（`const UpstreamFile = "ngm.json"`） | 名字一样，但那处是**读上游清单**的地方——它没有任何 json tag 字段 ✓（闸门③把它拦住） |
| `internal/lock/schema.go`（11 个 json tag 字段） | 它命名的是 `ngm.lock`：不是 `.json`、也不在配置表里 ✓（闸门①②把它拦住） |

> 这就是"按行为派生"的可操作含义：**同一个名字在两种位置上出现——
> 定义方与消费者——区分它们的不是名字，是那个位置在做什么。**

### 1.3 牙齿 ✅

| 探针 | 判据说了什么 |
|------|------------|
| 清单**少一条**（去掉 `internal/config/config.go`） | `这些文件在**定义**用户可编辑的 schema（文档点名了它的文件名、它自己解析那个路径、而且有 json tag 字段），却不在 schemaFiles 里：internal/config/config.go` |
| 清单**多一条**（塞一个不存在的路径） | `schemaFiles 里的这些文件派生不出来（没有解析文档点名的 .json 名，或没有 json tag 字段）：internal/config/zz_probe.go` |

两道合起来是**双向**的 ✓：漏加与陈旧都会红 ✓。

### 1.4 那句注释本身也得改

`schemaFiles` 原来的注释写着"这是本检查唯一需要人工维护的地方，而漏加的表现是
'检查少了几个键'" ✗——这一版把检查做出来了之后，**那句话不再成立** ✓，
于是注释改成"它不再是一份需要人记着的清单" ✓。

> 一条纪律：**注释里说"这里靠人记着"，就是一个待办**。

## 5. 过程洞察

### 5.1 这是"来源要有出处"的第五次现形

| 版本 | 形态 |
|------|------|
| v0.45 | "按**文件名**找源码" → 改成按行为 |
| v0.46 | "覆盖集从哪来" → 立成可查的纪律 |
| v0.52 / v0.53 / v0.56 | **登记**里的用例名 / 测试函数名 / 子测试名可能指向空气 |
| v0.63 | 登记**落地**没有（四张活表被拼坏） |
| **v0.64** | **清单本身**没有来源（漏加即静默变松） |

> 五次都是同一件事：**凡是"我记着"的地方，都要问一句"那它错了谁会红"。**

### 5.2 判据的"闸门"要能被两条反例说清

三处闸门不是设计出来的，是**被两条反例逼出来的**：`graph.go`（名字对、位置错）与
`lock/schema.go`（形状对、名字错）各否掉一种更松的规则。写判据时先找这两条反例，
比先想"要查什么"更快定形状。
