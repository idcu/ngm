# v0.84 复盘 — **把"开工先对状态"变成读数（不是门禁）**

> 计划：[v0.84 计划](./v0.84-plan.md)
>
> 一句话结论：事故的直接后手落地了，但过程中得到一个**比原计划更有用的结论**——
> 判据存在 ≠ 会红；**"什么时候跑"才是那个变量**。于是这一版把两样东西写进收口脚本：
> 工作树状态读数 + "该跑哪两条命令"。

---

## 0. 那个反直觉的复核**

v0.83 的撞号（`adr-028-loopback-addresses.md` 与 `adr-028-dependency-graph-in-lock.md`）
**本来就会被抓到**：v0.71 那张网里有一条断言写着

```
ADR 编号 %03d 被两个文件使用: %s 与 %s
```

它没红，原因**不是判据缺失，而是收口时没跑它**（那一轮的收口只跑了 V79/78/77/76/58/25/26/DocsAnchors 等 ✗）。

⇒ **判据的价值 = 写了没有 × 什么时候跑**。后一半此前靠人记，本版把它交给脚本。

## 1. 交付

### 1.1 收口脚本里的两节（`scripts/check-release-status.sh`）

```
worktree state (read this before you touch anything):
  uncommitted (modified or untracked): N file(s)
  version artifacts NOT committed:
    docs/development/v0.99-plan.md
    ^ 这些文件**没有版本保护**：被覆盖就永久丢失（v0.83 复盘 §1 的教训）。
  snapshot docs edited in place (expected to be immutable):   # 就地改快照时才有

before you call it delivered:
  go test ./...                    # 全部判据（含 ADR 索引、读数、契约网）
  bash scripts/check-docs-links.sh # 文档链接
```

**为什么不做成门禁**：开发中途工作树本来就不干净（未提交是常态），恒红的门禁等于没有门禁。
它的价值在于"每次收口都打印出来"——于是"这里还有没提交的版本工件"不再依赖谁的记性。

判据 `TestV84WorktreeStateNamesUncommittedVersionArtifacts` 在**合成仓库**上跑
（`git init` + 一份复盘 + 一个附注 tag），四侧：干净不点名 · 未提交的版本工件被**点名** ·
提交后点名消失（证明认的是"未提交"而非"文件存在"）· 就地改快照单独一句话。

### 1.2 协议拍板：**不放宽 `git://`**

| 选项 | 决定 |
|------|------|
| 允许 `defaultProtocol: "git"`（让本机 daemon 的端到端跑通） | **不做**。理由：`git://` 无认证无加密；**产品规则不该为测试的方便让路**——测试性需求用脚本/夹具解决（ADR-029 §代价与边界里已写明这条边界） |
| 造一个本地 TLS git 服务器（走允许的 `https`） | **不做**：为一次测试造基础设施，复杂度不值；`subPath` 端到端的真实样本仍是"一次真人推送" |

⇒ `subPath` 端到端依旧等推送；三道门（地址 ✓ 已放行 · 权限 `net:localhost` ✓ 行为正确 · 协议 ✓ 有意拒绝）**全部写清**。

## 3. 一条一般的话

> **判据存在不等于会红**——v0.83 的撞号证明：写好的网如果没在收口时跑，
> 它的价值等于零。所以"该跑什么"要么由脚本说出来（本版做的），
> 要么由流程钉住；交给记性，它就是一张纸。
