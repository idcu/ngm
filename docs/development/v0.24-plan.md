# v0.24 计划 — 退出码的四方事实源必须对得上

> 范围来源：[v0.23 复盘](./v0.23-retrospective.md) §4 D1 的直接延长线（那处漏写是**人眼**发现的）。
>
> 一句话目标：退出码这件事有**四处**事实源，而它们此前**没有任何东西**在对账。

---

## 0. 为什么有这一版

v0.23 在 `docs/modules/p0-core.md`（**规范**）里抓到一处漏写：它写着「1 非预期漂移」，
而 `architecture/observability.md` 早就写准了。**规范与架构文档不一致，而错的那份是规范。**

那次是**人眼**发现的。这一版让它以后必须自己撞上去。

四处事实源：

| # | 位置 | 形态 |
|---|------|------|
| ① | `internal/errs/errs.go` | 实现（数值 + 名字） |
| ② | `docs/architecture/observability.md` | 契约的**规范**出处（"退出码约定（全局）"表） |
| ③ | `docs/modules/p0-core.md` | 规格里的错误模型（`ErrorCode` 常量块） |
| ④ | `docs/guides/cli.md` | 用户看到的那一行汇总 |

## 1. A 组 — 四方对账

- **① ↔ ③**：规格用 `iota + 1` 推出名字→数值，必须与实现的**显式数值**逐一相同。
  **这是本版最想钉的一条**：`iota` 的值取决于顺序，**重排一行，所有退出码静默平移**——
  而规格是给人抄的。
- **②**：0…5 六个码全部列出，且每行都有非空的「语义」与「典型来源」。
- **④**：同样 0…5，每段都有说明。
- 每一处的解析都带"**读不到就 Fatal**"的守卫：网的判据来源不许静默消失。

## 2. B 组 — 码 1 的来源必须写全

码 1 是**唯一**被四种情形共用的数字（verify 漂移 · 引擎运行失败 · audit 超阈值 · audit 钩子否决）。
文档里漏掉任何一处，读者都会以为"这个码与我无关"——v0.23 就是栽在这儿。

判据是一份**会自己过期**的关键词表：`漂移` / `引擎` / `漏洞` / `钩子`。
哪天真出现第五种来源，加进表里的同时必须把它写进文档；反之某个词从文档里消失，这一条会红。

**（开工前先量）**：`observability.md` 当时**没提钩子**——所以这一版预期会先修一处文档。

## 3. C 组 — 补上 v0.23 遗留的"改了但没网"

v0.23 给 audit 钩子的两条失败分支改了显示名（`AuditHook`），却**没有网**：
走到那两条分支需要真的用 Deno 跑一次脚本，而本环境没有 Deno（缺它会先退 5）。

处置：把判断抽成一个吃 `*security.Result` 的**纯函数**（`auditHookVerdict`），
用合成结果测三件事——**是谁否决的**（`AuditHook` 而非 `RefDrift`）、**数值仍是 1**、
**两种失败说的话必须不同**（"它说自己不过关" ≠ "它没能给出结论"）。

## 4. 明确不做

| 不做的 | 理由 |
|--------|------|
| 用网去核对**每个命令**的 `EXIT CODES` 与全局表的语义一致性 | 命令用法里的是**具体场景**，全局表是**语义分档**，逐字比对会误报。命令侧的判据由 v0.21/v0.22 两张网守着 |
| 把 `errs.Code` 改成从文档生成 | 实现是事实源，文档是它的投影；反过来会让"改文档=改行为" |
