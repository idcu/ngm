# v0.16 复盘 — 机器可读输出不能说谎

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 范围来源：[v0.15 复盘](./v0.15-retrospective.md) §7 候选 1；实施计划：[v0.16 计划](./v0.16-plan.md)。
>
> 一句话结论：7 个命令的 `--json` 是**给 CI 读的**，而它此前**只被零散覆盖**
> （三份测试分别只查"键存在"或"某场景等于 0"），**没有任何一条把报告里的退出码与
> 进程退出码绑在一起**；而它的**顶层形状在用户侧一个字都没有**。
> 本版把这两件事都钉住——并且在 20 个状态上**没有发现产品缺陷**。

## 1. 逐组验收

### 1.1 A 组 — 契约网

| 规矩 | 结果 |
|------|------|
| ① stdout 为空或**恰好一份**合法 JSON 文档 | ✅ 20 个状态全合规（无半份文档） |
| ② **`--json` 不改变退出码** | ✅ **17/17 组对照的退出码完全相同**（含失败态：1 / 2 / 3 / 4 / 5） |
| ③ 报告里的 `exitCode` / `summary.exitCode` 等于进程退出码 | ✅ 全部相等（**但见 §4 的诚实说明**：它在 verify/audit 上由构造成立） |
| ④ 输入错误时 stdout 为空；而**失败态不是输入错误** | ✅ 输入错误 3 条（exit 3 / 5 / 3）stdout 全空；`verify` 的 exit 1 与 exit 2 各带**完整报告** |

实测的逐状态退出码（`plain=json`）：`verify` 干净 0 · `--strict` 遇预期漂移 **1** ·
字节被篡改 **2** · `--deep` 篡改 **2** · `audit` 无漏洞 0 · 发现 HIGH **1** ·
`audit --offline` 无缓存 **4** · 引擎不在目录 **5** · 依赖不在图 **3**。

### 1.2 B 组 — 机器接口写进用户文档

**发现**：7 个命令的 JSON 顶层形状，用户侧**一处都没有**——
`engines list` / `engines info` 返回的是**数组**（因为一个名字可对应多种 kind），
这件事只写在 `internal/adapter/catalog.go` 旁边的代码注释里。

**处置**：`docs/guides/cli.md` 新增《`--json` 的形状（机器接口）》一节：
**实测**形状表（哪个命令带退出码字段、哪两个返回数组）+ 四条规矩。

**只记录，不统一**：数组与对象的差异是当前接口的一部分；统一形状是**破坏性变更**，
要另立决定——不在文档里顺手改（这是本版最该守的边界）。

## 2. 未能达成的项

**本版范围内没有未达成项。** 范围外（已写进计划的"不做"）：

| 不做的 | 理由 |
|--------|------|
| 逐条执行 `quickstart.md` 的示例（原计划候选 1） | 它的示例用**真实 GitHub 仓库与真实引擎**（`github:vuejs/core@v3.5.0`、`build --engine=esbuild`）。做成网就是**联网测试**，违反"网必须确定性、离线"——见 §3.1 |
| 统一 7 个命令的 JSON 顶层形状 | 破坏性变更，需另立决定 |
| 给 `--json` 加字段级 schema 校验 | 字段集合是**演进中**的；钉死它会让"加一个字段"就要改网 |

## 3. 设计偏离登记

| # | 计划写的 | 实际做的 | 为什么 |
|---|---------|---------|-------|
| 1 | 候选 1：检查示例命令**能否跑通** | **侦察后放弃**，改钉 `--json` 的契约 | quickstart 的示例依赖真实仓库与真实引擎。**放弃一条不能确定性地验证的线，本身就是结论**——把它硬做成网，等于给项目装一个迟早会红的联网门禁 |
| 2 | 网假定 JSON 顶层是**对象** | 改为"**恰好一份合法 JSON**"，并**记录**数组/对象的差异 | 第一版跑出来就红了：`engines list --json` 是数组。判据比事实窄，是**网的错**（v0.15 已为此收紧过四次判据） |
| 3 | 一份 fixture 直接开测 | 探针发现 fixture **缺 lock**：`verify`/`tree`/`outdated`/`audit` 全退 3（"no ngm.lock"） | 先测量再定契约——照自己的设想写断言，会把"fixture 没准备好"误判成"命令坏了" |
| 4 | 状态顺序未指定 | 重排为**干净 → 漂移 → 篡改** | 探针 v3 里先篡改，导致之后每个 `verify` 都退 2，**漂移语义再也测不出来**（`--strict` 的 1 被掩盖成 2）。状态互相掩盖是这类网最容易犯的错 |
| 5 | `audit` 的两条路需要 OSV 网络 | 用**既有的本地替身模式**（`NGM_OSV_URL` + `grantNetFor`） | 保持离线确定性：网跑在 `httptest` 上，不碰真实网络 |

## 4. 缺陷清单

| # | 缺陷 | 性质 | 状态 |
|---|------|------|------|
| — | **产品缺陷：0 处** | 20 个状态探过：退出码、形状、`exitCode` 字段、错误路径全部合规 | — |
| D1 | **文档缺口**：7 个命令的 `--json` 顶层形状用户侧未记录；`engines` 返回数组只在代码注释里 | **机器接口没有写给人看**——对"给脚本读"的输出，这本身就是缺陷 | ✅ 已在 `docs/guides/cli.md` 记录（实测表 + 四条规矩） |
| D2 | **关于网自身的诚实说明**：规矩③（报告退出码 == 进程退出码）在 `verify`/`audit` 上**由构造成立**——报告字段**就是**进程退出码的来源 | 不是缺陷，是**网的强度边界**（见下） | 记录在案：③ 防的是**未来分叉**，不是当前 bug |

**D2 是怎么发现的**：牙齿验证时把 `internal/verify/report.go` 的
`s.ExitCode = r.ExitCode()` 改成常量 `0` —— 结果**进程退出码也跟着变成 0**，
于是抓住它的是"每个状态该退几"的**期望值**，而不是相等性断言：

```
--strict must turn an expected advance into exit 1 (RefDrift); exit=0
tampered vendor bytes must be a digest mismatch (2); exit=0
--deep on tampered bytes must be 2; exit=0
```

这条记录的意义：**不把网说得比它实际更强**。本网真正的牙齿是
**逐状态期望值 + 两种模式的对照**；③ 是一道防未来分叉的栅栏。

**自己制造、当场处置的**：

| # | 现象 | 处置 |
|---|------|------|
| P1 | 第一版网把顶层假定为对象 → 误报 `engines list` | 收紧判据（"恰好一份合法 JSON"），并把差异写进文档 |
| P2 | 探针 fixture 缺 lock，四个命令"全坏" | 补 `install`；**是夹具的错，不是产品的错** |
| P3 | 探针把篡改排在漂移之前，掩盖了 `--strict` 的语义 | 状态重排；这条教训写进网的注释里（下一个人不该再踩） |

## 5. 过程洞察

### 5.1 放弃一条不可判定的线，是结论而不是退缩

候选 1 原本是"检查示例命令**能否跑通**"。侦察发现 quickstart 的示例要靠真实仓库与真实引擎，
**网会变成联网测试**——那与项目"确定性、离线"的纪律直接冲突。
于是本版改钉同族里**可判定**的那一半（给脚本读的 `--json`）。
**一条会时不时红的网，比没有网更糟**：它会训练人忽略红色。

### 5.2 探针第三次证明自己：网的第一版通常是错的

本版探针抓出两处**网的错误**（fixture 缺 lock、把数组当对象）与一处**顺序错误**
（篡改掩盖漂移）。它们没有一处能靠读代码发现——**只有真跑**。
这与 v0.12（五处静默失效）、v0.15（21 行泄漏）是同一个方法，只是这次抓住的是网自己。

### 5.3 牙齿验证除了"证明会红"，还会告诉你网的**真实强度**

把报告字段改成常量后，进程码跟着变，说明那条相等性**由构造成立**。
如果不做这一步，复盘里会写成"本网保证报告不说谎"——**那是把网说得比它强**。
诚实的说法是：它保证"每个状态退该退的码、两种模式一致、形状合规"。

### 5.4 没有产品缺陷，也可以有交付

这是第三次"绿着通过"（v0.13、v0.15 的 A 组、本版）。本版的交付是
**一条被钉住的契约 + 一处被写下来的接口**。写复盘时不把它说成"发现了重要问题"——
**没有发现问题就是没有发现问题**。
