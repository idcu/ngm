# v0.92 计划 — **关上那处已知漏检（带括号的链接）**

> 来源：[v0.91 计划](./v0.91-plan.md) §3 与 [v0.91 复盘](./v0.91-retrospective.md) §6 候选 4。
>
> 一句话目标：v0.91 写下"一处已知漏检（target 里有 `)` 时这条检查看不见它），
> 要改得单独论证"。这一版就是那次论证 + 改动。

---

## 1. 先取证：这类链接在仓库里有几处

| 问 | 答 |
|----|----|
| 全仓（253 个 `.md`）destination 里含 `(` 的链接 | **0 处** |
| destination 里含 `)` 的链接 | **0 处** |

⇒ 把检查变强**不会**引入新红（这一点必须先量，否则"改进"会变成"突然红一片"）。

## 2. 计划

| # | 项 | 验收 |
|---|----|------|
| 1 | destination 按**平衡括号**解析（`](./b(c).md)` 的结尾是最后一个配平的 `)`） | 前后对照：同一夹具旧实现报 1 条、新实现报 2 条 |
| 2 | 括号**不配平**时退回旧语义（取最后一个 `(` 之后） | 不把畸形写法顺手变哑 |
| 3 | 黄金用例补两侧：**带括号且存在**（不报）与**带括号且缺失**（报） | 证明新解析不是"见括号就报" |
| 4 | 真实仓库仍然全过 | `all docs links OK` |

## 3. 为什么这值得单独一版

一个**会漏检**的检查比没有检查更坏：它给人"查过了"的感觉。
这处漏检还特别隐蔽——写法完全合法（CommonMark 允许 destination 里有配平的括号），
而旧实现把它切成一个不存在的路径后**静默跳过**。

## 4. 不做

- 不推 tag / jsonkit（仓库所有者的动作）；
- 不动 `subPath` 端到端（等推送）；
- 不顺便改 label 里的括号语义（那部分本来就对：`[标签里有括号 (x)](./b.md)` 正常）。
