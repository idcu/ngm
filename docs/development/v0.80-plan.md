# v0.80 计划 — **嵌套 monorepo 的明确处置 + subPath 端到端的阻塞事实**

> 来源：[v0.79 复盘](./v0.79-retrospective.md) §6 候选 1（推 tag / 推 jsonkit）与候选 4（嵌套 monorepo）。
>
> 一句话目标：把 `subPath` 端到端**推到能推的最远处**（发现"本机无替代路径"这条事实），
> 并把嵌套 monorepo 从"用错理由红"改成"**说出来**的没查过"。

---

## 0. 起点

1. `subPath` 端到端缺一个真实远端（v0.78 起就记着）。本版先试**不依赖任何人**的路径。
2. 嵌套 monorepo 一直是"明确不做"，但**做错方式**：v0.79 实测它红的是
   `entry-resolvable`（"三层都没找到入口"）——那是**错理由**。

## 1. 计划

| # | 项 | 验收 |
|---|----|------|
| 1 | 试本地路径跑 `subPath` 端到端：预置 mirror + `install --offline` | 结论要有据：`--offline` 拒绝"没有 lock 的离线安装"**是设计** |
| 2 | 再试真实协议：本地 `git daemon`（`git://localhost`，默认端口 9418） | 结论要有据：daemon 能起，但 **ngm 的地址校验拒绝单标签主机名与 IP 字面量** |
| 3 | 嵌套 monorepo：说得对 + 不假装查过 + 不借机豁免 + 结论标"不完整" | 一条 `nested-monorepo` 记录（点名模式与"约 N 个子包没被体检"）；包专属判据记不适用；孙辈一条判据都不出现；根上的判据照旧生效；`complete:false` |
| 4 | 修 v0.79 自己在 `jsonkit` README 里写错的语法 | 子路径是 `#path=<sub>`，不是 `#<sub>` |

## 2. 不做

- 不为跑通测试去放宽 ngm 的地址校验（那是一条**产品决策**，不该由测试的方便决定）；
- 不递归嵌套 monorepo（仍是不做的形态，但**说清为什么**）。
