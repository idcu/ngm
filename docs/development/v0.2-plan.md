# v0.2 实施计划 — 供应链防护完整

> 范围以 [internals/roadmap.md](../internals/roadmap.md) 为唯一事实源。前置：v0.1 全部阶段完成并通过复盘。
> 开始前先做一次设计复核：用 v0.1 实测结果确认策略引擎与 OSV 集成的可行边界（必要时先修 ADR）。

---

## 设计复核结论（2026-09-29，开工前）

| 复核项 | 结论 |
|--------|------|
| `minimumReleaseAge` 的时间源 | 从本地 mirror 读 commit 的 committer date，**离线可用**；但**提交者可控、不可信**——该局限已在[供应链防护](../architecture/supply-chain.md)写明，无需改设计 |
| OSV 按 commit 查询 | `POST https://api.osv.dev/v1/query` 的 `commit` 字段可用；**覆盖率有限**（多数公告按 semver 记录），已在文档写明 |
| 白名单对传递依赖生效 | 可实现。但发现一处**必须先改数据结构**的地方：`resolve.Node.RequiredBy` 记录的是**依赖名**，而节点身份是 `name#subPath`；monorepo 多子路径下名字不唯一，直接用它拼来源链会**指错节点** → frontier 需携带 **Key** |
| `postInstallPolicy` 的执行 | **主动收窄**：v0.2 不引入执行入口（见下） |
| 策略失败语义 | 定为 `exit 3` + 完整来源链 |

**本轮新增 ADR**：[ADR-009：供应链策略的执行时机与失败语义](../adr/adr-009-supply-chain-policy.md)。
策略执行属"重大决策"，按纪律**先立 ADR 再改代码**。

## A — 供应链策略引擎

- [x] `internal/supplychain/policy.go`：策略 schema 加载与校验（字段最小集：allowedGitHosts / allowlistRepos / minimumReleaseAge / osvIgnoreSeverities / postInstallPolicy / verifyOnLock）
- [x] allowlist：host 精确匹配 + repo glob；**对传递依赖同样生效**（在解析阶段执行，命中失败 exit 3 且 Hint 指出来源链）
- [ ] postInstallPolicy：v0.2 中 ngm **不执行依赖脚本**（`deny` 为默认且为实际行为）；`prompt` / `allow` 只记录判定结果，并在输出中明确说明"该策略在 v0.2 不会导致脚本被执行"。
      **执行入口收窄到 v0.3**（它需要沙箱作为前置），依据 [ADR-009](../adr/adr-009-supply-chain-policy.md)
- [ ] `verifyOnLock`：install / update 后自动触发 verify（可关闭）

**验收**：策略 schema 非法 → exit 3；传递依赖命中未授权仓库 → 阻断并输出完整来源链；三种 postInstallPolicy 行为测试。

---

## B — minimumReleaseAge

- [x] 时间源：从 mirror 读取 commit 的 **committer date**（`git.CommitTime`），**不得使用 resolvedAt**
- [x] ISO 8601 duration 解析（`P3D` / `PT12H` / `P1W`；**年与月被刻意拒绝**——长度不固定会让阈值漂移）
- [x] install 门禁：`now - committerDate < 阈值` → 拒绝并给出最早可安装日期
- [x] 离线可用：mirror 已含 commit 时无需网络（`git show` 是本地操作）

**验收**：新 commit 被拒绝 / 到期后放行（测试用历史 fixture 时间戳）；审计说明中登记"Git 无可信时间戳"的局限。

---

## C — OSV 集成与 audit

- [ ] `internal/supplychain/osv.go`：按 commit 查询（本地 mirror 校验 commit 存在后再查）、24h 缓存（`~/.ngm/cache/osv/`）、`--no-cache` 刷新、离线只读缓存
- [ ] severity 过滤（`osvIgnoreSeverities`）
- [ ] `ngm audit`：报告格式化（human + `--json`）；退出码 0 无超阈值 / 1 有 / 3 配置错误 / 4 网络失败且无缓存
- [ ] 诚实输出：报告标注"commit 匹配覆盖率有限、零日不在库中"（[覆盖率局限](../architecture/supply-chain.md)）

**验收**：mock OSV 响应契约测试（离线）；缓存命中/过期/强制刷新三场景；退出码矩阵。

---

## D — 可观测性（why / tree / outdated）

- [ ] `ngm why <dep>`：从 root 到目标的全部路径（含传递链）
- [ ] `ngm tree`：依赖树 + 漂移（`⚠`）与漏洞（`✗`）标记
- [ ] `ngm outdated`：tag → mirror/host 最新 tag；branch → fetch 对比；commit → 无更新；输出 Drift 计算
- [ ] 全部命令支持 `--json`

**验收**：与 [observability 输出示例](../architecture/observability.md) 格式一致（快照测试）；outdated 在离线时的行为明确（报 stale）。

---

## E — adapter 扩展

- [ ] tsc adapter：typeCheck（`--noEmit`）+ typeDecl（`--emitDeclarationOnly`）
- [ ] deno adapter：typeCheck（`deno check`）；bundle 仅当 Deno >= 2.4（实验特性）时可用，低于该版本报 exit 5 并提示改用 esbuild
- [ ] postcss adapter：css（`--use` 插件参数处理）
- [ ] 引擎清单内置项更新（[engine-adapter](../architecture/engine-adapter.md)）+ `engines validate` 覆盖版本探测

**验收**：三 adapter 在样例项目上通过；版本不满足时错误可操作；`ngm typecheck --engine=typescript|deno` 输出一致结构。

---

## F — install 的 CI 模式

- [ ] `--frozen-lockfile`：禁止解析新 ref / 修改 lock；lock 缺失或与 ngm.json 不一致 → exit 3；**允许网络**（content store 未命中时下载）
- [ ] `--offline`：禁止一切网络访问，未命中本地 content / vendor → exit 4
- [ ] 组合 `--frozen-lockfile --offline`：完全离线可复现安装（CI 首选）
- [ ] CI 示例落地（[publishing](../guides/publishing.md) 的 release 流水线 + 一个 install-only 流水线）

**验收**：三模式行为矩阵测试；预置 content store 后断网安装成功；lock 不一致场景 exit 3。
