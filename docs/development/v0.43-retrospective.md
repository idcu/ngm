## 3.5 顺带修掉一处**旧判据的假阳性**

登记这一版时，**v0.27 那条网**红了：

```
the living docs name the json field "normalizeArgs" (in project-state.md), but no such json tag exists
```

`normalizeArgs` 是 **Go 函数名**，而那条判据的规则是「提到 `--json` 的行上、任何含大写的反引号标识符 = json 字段名」——
于是文档里提到一个函数名就被当成"编造了一个字段" ✗。

处置**不是**把它加进白名单（白名单会腐烂），而是给判据加一个**从源码派生**的同伴：
`packageIdentifiers` —— 仓库里**定义**的函数/类型/常量/变量名，文档提到它们时不算字段。

读数：`57 lines mention --json, 21 field names verified (原 22), 1 token skipped as code identifier` ✓。

## 5. 过程洞察

### 5.1 我的记忆不是"核对对象"——第三次了

初版的表是我**凭记忆**写的：

```go
"remove":   {"force"},      // ✗ remove 没有 --force
"typedecl": {"json"},       // ✗ 那一层的 flagset 里没有
"css":      {"sourcemap"},  // ✗ 只属于子命令
```

于是判据把「flag provided but not defined」当成"空值不等价"报了出来——
**红的不是产品，是我的表**。

这已经是同一族事故的**第三次**：

| 版本 | 我抄了什么 | 结果 |
|------|-----------|------|
| v0.33 | 合法命令清单 | 差点抄成常数（最后改成问运行时的命令表） |
| v0.42 | 参数形状 | 改成由 `withoutFlag` 从同一张表派生 |
| **v0.43** | flag 清单 | 改成从源码 `fs.Bool(` 派生 |

**结论固定成一条纪律**：判据的输入表**要么从源码派生、要么从运行时问**，
**绝不从我的记忆里抄**——记忆会漏、会多、会把两个命令的 flag 混在一起。

### 5.2 拍的阈值会把合格的现实报成缺陷

覆盖守卫我写了两个数：`checked >= 35` 与 `checked+skipped >= 45`。
实测是 **38 + 3 = 41**，于是第二条**红了**——而产品与判据都没问题，
**只是我那个 45 是拍出来的**。

处置：

- 能写成**结构性**的就写成结构性的（"派生表的总数 == 跑完 + 跳过"——这条不依赖任何数字）；
- 剩下必须用数字的，用**实测值之下的下限**，并在注释里写明"这是实测值，不是估的"。

这与 v0.42 那条经验是同一条的另一面：**判据的阈值和判据的内容一样，都要先落到现实上。**

### 5.3 最有价值的那条断言，对应的是产品**自己写下的一句话**

四条断言里，④（"布尔 flag 不吞 token"）是唯一一条**产品在注释里专门写过**的：

> 「`--all`（布尔）**绝不能吞掉**紧随其后的 positional」

而它要挡的正是**静默丢参数**那一族（v0.39 的 `junk-arg`、v0.19 的"多余位置参数被丢"）。
把它变成断言之后，牙齿一咬就中：**让那个 positional 被忽略 ⇒ ④ 立刻红**。

> 一条判据最好的来源，是产品自己已经承诺过、却没有东西在核对的那句话。

### 5.4 判据的假阳性：处置是**派生**，不是白名单

v0.27 那条网把文档里的 **Go 函数名**当成了"编造的 json 字段"（见 §3.5）。

最省事的修法是往它的白名单里加一条 `normalizeArgs`——但那是一条会腐烂的名单：
下一个被提到的函数名、类型名、常量名又会红一次，而每红一次都会诱使人再往名单里加一条 ✗。

改成**从源码派生**"哪些名字是这个仓库里的标识符"之后，
这类假阳性从根上消失，而且**不需要有人维护**。

这与本版 §5.1 是同一个方向的第三次：**判据的输入表，从源码或运行时来，别从我这儿来。**
只不过这次要派生的东西变成了"**哪些名字不该被当成字段**"。
