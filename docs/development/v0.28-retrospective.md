# v0.28 复盘 — 可行动的建议不许在包装时丢掉

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：普查"错误有没有下一步"时抓到一个**用户可见的真缺陷**——
> `hint:` 会在包装时丢掉（实测输出只剩 `cause:` 一行）。
> 修在**渲染处**：一次覆盖全仓库 300 个构造点，且不改任何错误数据。

---

## 1. 逐组验收

### 1.1 普查读数（`go/ast`，静态可复读）

| 范围 | 构造点 | 空 hint 字面量 |
|------|-------|--------------|
| 全仓库（非测试） | **300** | **129** |
| 用户层 `cmd/ngm` | **47** | **11** |

### 1.2 缺陷（探针实测）

```
inner : GitFetch: fetch failed
          hint:  check your credentials
outer : ConfigInvalid: cannot read the lock
          cause: GitFetch: fetch failed          ← 建议不见了
```

`FormatHuman` 只打印**最外层**那条错误的 hint；外层 `Wrap` 时给了空 hint，
内层那句"check your credentials"就**再也到不了用户眼前**。

### 1.3 A 组 — 修在渲染处 ✅

`FormatHuman` 在自身 hint 为空时，沿 `Cause` 链取**第一条**非空 hint。
实测输出：

```
outer : ConfigInvalid: cannot read the lock
          cause: GitFetch: fetch failed
          hint:  check your credentials
```

### 1.4 B 组 — 两张网 ✅

- `internal/errs`：1 层与 2 层包装都熬得住 · 自己的建议优先（**只显示一条**，最近的）·
  整条链无建议时**不许凭空造** · 标签仍来自最外层（v0.23 未被碰掉）· `Error()` 仍不含 hint。
- `cmd/ngm`：**棘轮**——用户层空 hint 构造点不许变多（**11/47**，上限就是 11）。

牙齿：摘掉继承 ⇒ 红，并原样打印出缺陷输出；给用户层加第 12 个空 hint 站点 ⇒ 红，**并列出全部站点**。

### 1.5 顺带 — `update:1` 的逐步骤量 ✅

把一条命令拆成"`verify` → `update` → `verify`"逐步量，看清了缺口为什么测不到：

| 步骤 | 读数 |
|------|------|
| 上游挪 tag、mirror 停在旧提交 → `verify` | **1**（确实看到漂移） |
| 同一状态下 `update --all`（verifyOnLock 开） | **0**，且 lock 里写的是**新提交** |
| 之后 `verify` | 0 |

⇒ `update` 的解析已经跟上新 ref，复检与它一致。走到 1 需要"上游在两步之间又动一次"——**竞态**。
声明的代码路径真实存在（`autoVerifyAfterLock` 原样返回 verify 的退出码），只是**无法被确定性触发**。
缺口记录已按这条实测链改写。

## 5. 过程洞察

### 5.1 修在"唯一的出口"，而不是修在"每一个入口"

129 个空 hint 的构造点很难逐个补——要凭空发明 129 句建议。
但**"丢掉"这件事只发生在一个地方**：渲染。于是改动只有一处，
却把 129 个站点全部修好，而且**不改动错误数据**（`--json` 与 `errors.As` 的消费者毫无察觉）。

**找"这件事发生在哪一层"，比找"有多少地方做错了"更省。**

### 5.2 棘轮比零容忍更现实

用户层还有 11 个空 hint 的站点。要求零会逼人给"这东西不存在"这类错误
硬写一句没用的下一步——那是**噪音**。所以判据写成**不许变坏**：
上限就是当前读数，且把读数写进测试输出（让数字可见，而不是只在失败时才出现）。

### 5.3 逐步骤量：把一条命令拆成"前—中—后"

`update:1` 追了三个版本。真正把它说清的不是"猜哪个源不一致"，
而是**把一条命令拆开量**：`verify`（前）→ `update`（中）→ `verify`（后）。
前一步就已经是 1，说明检测没问题；中一步把 lock 推到了新提交，说明复检不会再有话说。
**"测不到"本身也要有证据链**，否则它和"懒得测"分不出来。
