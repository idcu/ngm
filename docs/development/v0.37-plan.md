# v0.37 计划 — **枚举，而不是列举**

> 范围来源：[v0.36 复盘](./v0.36-retrospective.md) §7 候选 1。
>
> 一句话目标：v0.36 的扫描覆盖了 57 个用例，但那些用例来自两张**为别的目的建的表**。
> 这一版由**枚举**给出全称：**每一个命令 × 每一种配置错误** ⇒ 走上哪条输出通道，守哪条通道的契约。

---

## 0. 矩阵

| 维度 | 取值 |
|------|------|
| 命令 | **21**（来自运行时的 `commands` 表） |
| 配置形状 | 目录不存在 · 空目录（无清单）· 清单是坏 JSON |
| 合计 | **63 次运行** |

**这些形状都不需要夹具**（不需要 git、不需要 fake engine 产物），所以整个矩阵 **< 1 秒**。

## 1. 四条通道，各有各的契约

| 通道 | 契约 |
|------|------|
| **错误文本** | 必须带 `hint:` |
| **报告** | 必须带行动行 |
| **用法文本** | **不许出现**（配置形状下打用法 = 矩阵没走到配置层） |
| **静默** | 红（退出非零却什么都不说） |

第五种可能——"**其它**"（有输出但不属于任何已知通道）——**也是红**：
一条新通道是有人**有意识**做的决定，不该悄悄出现。

## 2. 为什么"用法文本不许出现"值得当成红

它恰好抓住两类事：

1. 矩阵对某个命令**给不出能到达配置层的参数**（参数表该补）；
2. 某个命令**悄悄变成了全局命令**（不接受 `--dir`），而 `globalCommands` 名单没跟上。

两种情况都该有人看一眼，而不是被静默容忍。

## 3. 参数表的完整性是判据的一部分

`matrixArgs` 里**每个命令都必须有名字**（可以是空切片）。`TestV37` 第一段就断言
`len(matrixArgs) == len(commands)`——**"某个命令不在矩阵里"这件事本身必须有人发现**。
