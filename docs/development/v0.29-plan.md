# v0.29 计划 — 第一次上手的错误必须有下一步

> 范围来源：[v0.28 复盘](./v0.28-retrospective.md) §7 候选 1。
>
> 一句话目标：v0.28 修好了"建议在包装时丢掉"，并把用户层的空 hint 钉成**棘轮（11/47）**。
> 这一版把那 11 处**逐条看过**——看下来的结论是：**每一处都能写出真实的下一步**。

---

## 0. 为什么有这一版

v0.28 定这个数时写的理由是：

> "有些错误（'这东西本来就不存在'）确实没有比'它不存在'更有用的下一步，硬写一句会变成噪音。"

这句话听起来对，但它**没有被验证过**。逐条打开看，11 处的真身是：

| 位置 | 真实场景 | 能写的下一步 |
|------|---------|------------|
| `--dir` 解析失败 ×5（`env` / `add` / `config`×2 / `init`） | 传了相对路径或跑错目录 | 传绝对 `--dir`，或从目标目录运行 |
| `init` 建目录 / 建 `src` / 写清单 / 写入口 ×4 | 不可写、父目录不存在 | 检查可写性；**并说清"已经写了什么、没写什么"** |
| `add` 依赖定义非法 | slug 形状或 `--ref-type` 不对 | 给出形状与 `--help` |
| `transform` 建输出目录失败 | 目标不可写 | 指向可写的 `--outdir` |

**"没法更好"这种结论，也得逐条看过才能下。**

## 1. A 组 — 给这 11 处补上真实的下一步

两条写法上的纪律：

- `init` 的失败要说清**已经发生了什么**（"目录已建、`ngm.json` 没写成"）——
  这比一句泛泛的"检查权限"有用得多，因为用户下一步的动作取决于那个事实；
- 不写"请检查日志"这类没有动作的建议。

## 2. B 组 — 棘轮收紧成**硬门禁**（0/47）

`emptyHintCeiling` 从 11 改成 **0**，并在注释里记下这次判断的翻案。

## 3. C 组 — 端到端对照

静态网只证明"源码里写了 hint"。再加一张**端到端**的：
让 `ngm init` 真撞一次建不出来的路径（父路径是**文件**，`MkdirAll` 必失败），
断言用户看到的文本里有 `hint:`、有可归因的线索（可写性），
并且**没有谎报"created"**（入口都没建出来）。

## 4. 读数（写进复盘）

全仓库 `errs.New/Wrap`：**300 个构造点 / 118 个空 hint**，其中用户层 **0**。
最大的一头是 `internal/vendor`（39）。

**不做的**：把 internal 那 118 处逐个补。理由：v0.28 的继承修好之后，
只要链上**任何一层**有建议，用户就看得到；剩下的是"这条链整体没有建议"，
那是个**运行时**性质（哪条链会在用户面前出现，静态判不出来），列为候选。
