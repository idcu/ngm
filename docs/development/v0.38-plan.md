# v0.38 计划 — 形状再枚举 · **"退 0" 必须登记**

> 范围来源：[v0.37 复盘](./v0.37-retrospective.md) §7 候选 1。
>
> 一句话目标：把配置矩阵的形状从 **3** 种扩到 **8** 种，
> 并堵上这张网唯一的口子——**退 0 的格子**。

---

## 0. 形状从 3 扩到 8

| 形状 | 造法 | 成本 |
|------|------|------|
| 目录不存在 | `--dir=<不存在>` | 0 |
| 空目录（无清单） | 空 `t.TempDir()` | 0 |
| 清单是坏 JSON | 写一个文件 | 0 |
| **清单缺 `name`** | 写一个文件 | 0 |
| **未知 `runtime`** | 写一个文件 | 0 |
| **依赖缺 `name`** | 写一个文件 | 0 |
| **`dependencies` 类型错** | 写一个文件 | 0 |
| **`ngm.lock` 损坏** | 一个合法项目 + 坏锁 | 约 0（不起 git） |

矩阵因此从 **63** 次运行变成 **168** 次（21 命令 × 8 形状），而整套仍在 **1 秒出头**。

## 1. 为什么"退 0"要单独管

四条通道的契约（v0.37）管的是**非零**退出：错误文本要有建议、报告要有行动行、
用法文本不许出现、静默要红。

**而退 0 的格子不受任何契约约束**——没有建议可给、也没有报告可查。
所以它们是这张网唯一能**悄悄攒起来**的地方：覆盖率数字很好看，实际上什么都没查。

处置与 v0.15 的负例名单、v0.22 的缺口名单同款：

- 每一格都要写下**为什么它是 0**（`exitZeroByDesign`）；
- **双向对账**：有格子没登记 ⇒ 红；登记了却没格子 ⇒ 红（登记会过期）。

## 2. 要另外取证的一件事

形状**看起来**到位了，不代表它**走到了那一层**。
v0.37 的经验（"用法文本不许出现"抓的正是这个）在这里同样适用：
`ngm.lock` 损坏这一形状，必须确认命令真的走到锁解析，而不是被更早的检查挡住。
