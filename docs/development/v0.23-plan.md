# v0.23 计划 — 名字必须说发生了什么

> 范围来源：[v0.22 复盘](./v0.22-retrospective.md) §7 候选 2（D1 的下半段）。
>
> 一句话目标：退出码 1 是**一个数字四种含义**（verify 漂移 / 引擎运行失败 /
> audit 超阈值 / audit 钩子否决），而它只有一个默认名 `RefDrift`。
> 于是跑 `ngm typecheck` 失败的人读到的前缀是 `RefDrift:`——**他在找一个不存在的漂移**。
>
> 这一版把"**显示名**"从"**数值**"里拆出来。

---

## 0. 为什么是"拆"而不是"改名"

直接改 `CodeRefDrift` 的名字解决不了问题：换成任何单一名字，另外三种用途照样读到自己不相关的词。
真正的问题是**一个数字被迫只有一个名字**。所以：

- **数值不动**：`Code`、退出码、`--json` 一字不变（v0.16 钉下的机器契约）；
- **名字可覆盖**：`NgmError.Label`（空则退回码的默认名）；
- 每一处**知道自己发生了什么**的构造点，给出贴切的显示名。

## 1. A 组 — 机制

`internal/errs`：`NgmError.Label` 字段 + `Labeled()`（返回**浅副本**，保住 `errors.Is/As`），
`Error()` 与 `FormatHuman()` 都改走 `label()`。

## 2. B 组 — 四处误标点

| 位置 | 之前显示 | 现在显示 |
|------|---------|---------|
| `internal/adapter/runner.go`（引擎跑过但失败） | `RefDrift` | **`EngineFailed`** |
| `internal/adapter/engine.go`（同上，另一条构造路径） | `RefDrift` | **`EngineFailed`** |
| `cmd/ngm/audit_hook.go`（钩子超时） | `RefDrift` | **`AuditHook`** |
| `cmd/ngm/audit_hook.go`（钩子否决依赖集） | `RefDrift` | **`AuditHook`** |

## 3. C 组 — 两张网

- `internal/errs`：`Labeled` **只**改显示名——码、退出码、`errors.Is/As` 一字不动；空标签退回默认名；原错误不受影响（返回的是副本）。
- `cmd/ngm`：端到端断言 `ngm typecheck` 失败时 stderr **含 `EngineFailed`、不含 `RefDrift`**，且**仍然退 1**；
  外加**对照**：新标签**不许泄漏**到 verify 的报告里。

## 4. D 组 — 规范与声明同步

- `docs/modules/p0-core.md`（**规范**）：`ErrRefDrift` 的注释此前写着"1 非预期漂移"——
  与 `observability.md` 已有的准确表述不一致。补上四个来源，并给结构体补 `Label` 字段。
- `cmd/ngm/update.go`：码 2 的声明与 `install` 同形，但对 `update` 而言它**重建**而非校验——
  补一句**实测的澄清**（不是改码，是改说明）。
