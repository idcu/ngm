# v0.57 复盘 — **码 1 的来源必须有据可查**

> 体例同各版：逐组验收 → 未达成项 → 设计偏离 → 缺陷清单 → 过程洞察 → 指标 → 下一版候选。
>
> 一句话结论：关于"码 1 有哪些来源"，**三处说法互不相同**（注释说 3 · 判据说 4 ·
> 源码里 27 处站点），而那条判据只有单向——**代码多一处来源不会红**。
> 这一版把来源改成从**行为**派生、双向对账，并因此改掉了文档的语义列：
> 码 1 不只是"策略失败"，它还兜着**"结论算出来了却说不出去"**这一类。

## 1. 逐组验收

### 1.1 起点：三处说法互不相同

| 出处 | 说有几个来源 | 是哪些 |
|------|------------|-------|
| `internal/errs/errs.go` 的注释 | **3** | 漂移 · 漏洞 · 引擎 |
| `TestV24…` 的手写关键词表 | **4** | 漂移 · 引擎 · 漏洞 · 钩子 |
| 源码里的站点 | **27 处 / 21 个函数** | 见 §1.3 |

那条关键词表只有**单向**：文档少一个词会红，**代码多一处来源不会红**——
它自己的注释也承认"哪天真出现第五种来源，加进这里的同时也必须写进文档"，
也就是**靠人记得**。

### 1.2 宇宙怎么划：按**行为**，不按**名字**

第一版想法是"扫 `CodeRefDrift`"——**它漏掉了最重要的一处**：

```go
func runWithRecovery(fn func() int) (exit int) {
	defer func() {
		if r := recover(); r != nil {
			fmt.Fprintf(os.Stderr, "ngm: internal panic: %v\n", r)
			exit = 1          // ← 连 CodeRefDrift 都不提，只写了个字面量
		}
	}()
	return fn()
}
```

代码里写了 `exit = 1`，注释里提了一句 `errs.CodeRefDrift (1)`——
**按名字扫永远看不到它**。所以宇宙按行为划：

- 字面量 `return 1` / `exit = 1`
- 提到 `CodeRefDrift`（构造错误 / 取退出码 / 设码变量）

**跳过纯注释行**（注释里提到名字不是站点）、跳过测试与 testdata。
站点按 `文件 :: 所在函数` 归并——行号会动，函数名是稳的。

### 1.3 量出来的事实（27 处 / 21 个函数 / 5 类）

| 类别 | 站点 |
|------|------|
| **策略漂移** | `internal/verify/report.go :: ExitCode`（漂移判定的唯一出口；`why` / `outdated` 的间接路径也走它） |
| **引擎运行失败** | `internal/adapter/engine.go :: AsNgmError` · `internal/adapter/runner.go :: runChain` |
| **漏洞超阈值** | `cmd/ngm/tree.go :: runTree`（`--osv`） |
| **审计钩子否决或超时** | `cmd/ngm/audit_hook.go :: auditHookVerdict`（两处） |
| **内部失败** | `runWithRecovery`（panic）**＋ 12 处"说不出去"** |

**"内部失败"这一类是本版的主要发现**：`cmd/ngm` 里那 12 处 `return 1`
几乎全是同一句话——命令已经跑完、结论也算出来了，但**说不出去**：

```
write report: %v   ·  write json: %v  ·  marshal json: %v
read stdin: %v     ·  write output: %v  ·  write bundle: %v
write css: %v      ·  write listing: %v  ·  encode report: %v
```

文档此前把码 1 的**语义**写成"策略失败"，**这 12 处不是策略问题**——
读文档的人（尤其是写 CI 的人）会以为码 1 一定是漂移或漏洞。

| 探针 | 结果 |

| 在**已登记的函数**里多写一处 `return 1` | 红：`` `cmd/ngm/why.go :: runWhy` 里现在有 **2** 处站点，而登记写着 1 条 `` |

## 5. 过程洞察

### 5.1 来源要按**行为**派生，不能按**名字**派生

`runWithRecovery` 那一处，代码写的是 `exit = 1`、注释里才提了一句码名。
任何"扫名字"的判据都看不见它——**而看不见的那一处，恰恰是错得最厉害的那一处**
（panic 被报成"引用漂移"）。

> 与 v0.45 那条"按**文件名**找源码"、v0.46 那条"按**手抄**取覆盖集"同一族：
> **判据要找的是行为，不是行为的名字。**

### 5.2 一个数字兜着两件事，文档就会说谎

码 1 的语义列写着"策略失败"，而它有 12 处来源与策略无关 ✗。
这不是笔误——是**一个数字承担了两种含义**的必然结果：文档只能挑一个来写，
而另一个就变成了"读文档的人以为与我无关"的东西。

> v0.23 栽的是"漏写一类来源"，这一版栽得更深一层：**语义本身就不完整**。
> 记账（把来源补全）解决不了它，只能改语义或改契约——本版改了语义，
> 契约的改法留给候选（§7-1）。

### 5.3 牙齿可以**改判据**，而不只是验证判据

第一道牙齿的第二重作用是它证明了**判据的粒度不够**：
键只到函数时，"同函数里多一处"不可检测。
**牙齿并不总是"我说对了"的证明，有时是"我说得还不够细"的证据。**
