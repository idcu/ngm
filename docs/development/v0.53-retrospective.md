## 1. 逐组验收

### 1.1 机器侧的**逐条计数**断言 ✅

v0.50 的网原本只查**内容**（"人读那句话必须逐字出现在 JSON 里"）。
它发现不了"**人读 7 条、机器只给 1 条**"——只要那 1 条恰好是其中一条的字句，它就绿了。

补上计数下限后，读数逐条可见：

```
verify/…                     human=1 json=1
audit/…                      human=1 json=1
tree/--osv 撞上漏洞           human=1 json=2   ← 报告级 + 条目级各一处
engines/目录里的声明与实装不符   human=7 json=7   ← 正是当初驱动这个字段的那条
```

### 1.2 **"覆盖集从哪来"**立成可查的纪律 ✅

v0.46 的结论是一句话（"判断标准不是这版有没有抄，而是覆盖集从哪来"），
而**口号管不住下一个人**——四次"来源"事故（v0.42 / v0.43 / v0.45 / v0.46）就是证据。

这一版把它变成一张**可查的表 + 两条机械判据**（`TestV53…`）：

| 判据 | 内容 |
|------|------|
| ① | 登记的键必须是**真的存在的测试函数**（否则"登记看着空气"） |
| ② | 它所在的**文件**必须读源码或运行时表（用一组认可的入口名认：`sourceFiles` / `flagsetBlocksOf` / `commands` / `surfaceCases` …）；若没有，必须在登记里写清 `why` |

读数：**10 张网登记 · 1 条具名例外**。

**这条纪律当场抓到我自己的两处**：

1. 我**编了一个测试函数名**（`TestV37ArgumentMatrixHoldsAcrossShapes`）——
   真实的叫 `TestV37EveryCommandUnderEveryConfigErrorUsesItsChannel`。
   判据报：*"登记的 … 在这个目录里找不到同名测试函数——登记看着空气"*。
2. `TestV52…`（登记表自己）所在文件里没有任何派生入口 ⇒ 必须写成**具名例外**：
   *"被查的对象是 `debts` 表本身，不声称覆盖任何实现"*。

## 5. 过程洞察

### 5.1 纪律立起来的第一件事，往往是抓到自己

这张表刚写完就报了两条红：一条是**我编的函数名**，一条是**我自己的表**没有派生入口。
两条都不是产品的问题——它们说明这条纪律**真的在看东西**（而不是"写完就绿"）。

> 这与 v0.47 那条"绿不等于它在盯着什么"是一体两面：
> **立判据时最该等的，就是它第一次红。**

### 5.2 "照着字面判"与"照着事实判"

第一版的 `why` 规则是"`source` 里含『手抄』就必须写 why"——这是**照着字面**判：
我把 `source` 写成"自证"，就绕过去了。

改成"**文件里没有派生入口**就必须写 why"之后，它立刻要求我给 `TestV52…` 写一条具名例外——
那是**照着事实**判。这与 v0.45 那次的教训（守卫要"走与网同一条路"而不是核对名字）是同一条。

### 5.3 棘轮往下走，才算它在工作

v0.52 立表时的读数是 8；这一版做完两条，`debtCeiling` 跟着降到 6。
**只涨不降的棘轮与没有棘轮是一回事**——所以每做掉一条，都要顺手把它调下来（写在同一次改动里）。
