# v0.26 计划 — 能被核对的形状，必须有一个名字

> 范围来源：[v0.25 复盘](./v0.25-retrospective.md) §7 候选 1（"反向判据"）。
>
> 一句话目标：v0.25 的两张网只证明"**表里写了的键都真的存在**"，
> **不**证明"**该写的键都写了**"。这一版补上反向，
> 并在过程中发现**反向判据有一个前提**：形状必须有一个名字。

---

## 0. 为什么有这一版

v0.25 把这条限制**写进了网、计划与复盘**："从文档里删掉一个键，它不会红。"
这一版把它补上——而补的方式暴露了一件更有意思的事。

## 1. 前提：形状必须有一个名字

反向判据要知道"这些键属于哪个类型"。查下去发现两处**没有名字**：

| 位置 | 形态 |
|------|------|
| `cmd/ngm/integrations.go` | 报告是**函数内的匿名结构体字面量**（嵌套的 `artifact` 也是） |
| `cmd/ngm/engines.go` | `engines validate` 的 payload 同样是匿名结构体 |

**匿名的形状，没有任何机械判据能把它与文档对齐。**
所以第一件事是把它们提成具名类型（`integrationsReport` / `integrationArtifact` / `enginesValidateReport`）。

## 2. A 组 — 反向判据（报告的每个顶层字段都必须被文档点名）

对形状表的**每一行**，取它背后具名类型的**顶层** json tag 集合，
断言每一个都在该行的键里出现过。

- 只取顶层：嵌套结构体的字段是另一份契约（由各自的类型/表负责）；
- 判据方向是"**该写的都写了**"——与 v0.25 那张正交。

## 3. B 组 — 每一行都要有具名类型兜着

`TestV26EveryDocumentedShapeIsANamedType`：形状表里的每一行都必须映射到一个具名类型。

**没有它，反向判据会静默少看几行**——而"少看几行"的表现与"全都对得上"一模一样。
反向也钉一条：映射表里不许有形状表里已经没有的行。

## 4. 顺带要修的文档缺口（预期会红）

开工前就知道会有两处：

| 缺口 | 为什么 |
|------|-------|
| `ngm engines list` / `info` 的**数组元素形状** | 表里只写"每个元素是一行引擎"，**11 个键一个都没列**——而数组元素是机器接口的一部分 |
| `WhyReport.subPath` | `ngm why --json` 有这个字段，文档从未点名 |
