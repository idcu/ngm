# v0.98 复盘 — **对账用在另一对：入口路径规范化（读出来就有两处分家）**

> 计划：[v0.98 计划](./v0.98-plan.md)
>
> 一句话结论：v0.97 把「两条实现必须一致」做成了判据（用在链接检查上）；
> 这一版把它用在**另一对**——入口路径规范化（产品 `relPath` / 自检器 `rel_path`）。
> 结果：**光读代码就看出两处分家**，而且两处**都在 Windows 上不可能被发现**。

---

## 1. 先挑对，再看它们会不会分家

| 候选 | 结论 |
|------|------|
| `subPath` 校验 | **不是成对**：v0.82 已统一（`config.validateDepPath` 转调 `resolve.ValidateSubPath`）⇒ 无事可做（这本身是个好消息） |
| `exports` 解析 | 成对，但**读下来两侧一致**（Go `parseExports` / shell 里那段 Node 内联脚本逐行对过）——仍给它加了 11 个边缘形态当体检 |
| **路径规范化** | 成对，而且**读下来就不一致** |

## 2. 两处分家（都是"同一份仓库，两台机器两个结论"的变体）

| 形态 | 产品旧行为 | 自检器 | 为什么在本机看不出来 |
|------|-----------|--------|---------------------|
| `main: "src\\x.js"` | 靠 `filepath.ToSlash`——**Windows 上转、Linux 上不转** | 一律 `tr '\\' '/'` | 本平台正好会转 ⇒ 本机"碰巧"是对的，Linux CI 上会给出 `./src\x.js` |
| `main: "//src/x.js"` | 只剥一个前导 `/` ⇒ `.//src/x.js` | 剥到不剩 ⇒ `./src/x.js` | 两个字符串指向同一个文件，但**打印出来不一样**——而"报告里写出来的就是产品会用的那一个"是这条链路的全部意义 |

修的是**产品侧**（产品是契约，自检器要对齐它）：反斜杠无条件转 `/`（package.json 的路径按 `/` 语义理解，这也是 npm 自己的口径）；前导斜杠剥到不剩。

## 3. 判据与牙齿

| 项 | 内容 |
|----|------|
| 单元判据 | `TestV98RelPathIsPlatformIndependent`：**12 格**（反斜杠 · `.\src\…` · `//` · `///` · `/abs` · 裸名 · `./` · `../` · 前后空白 · 空串 · `/`） |
| 对齐网 | 语料 11 → **22 种形态**（新增：`exports` 是数组/null/`"."` 是 null/`import` 是嵌套对象/`types` 在 `import` 之后/`import` 是空白串/目标带 `*` · `main` 反斜杠/多前导斜杠/前后空白/裸文件名）⇒ **27 个子测试全绿** |
| 牙齿 | 把 `TrimLeft` 改回 `TrimPrefix` ⇒ `//src/x.js` 与 `///src/x.js` **当场红**；恢复 ⇒ 绿 |

**一条诚实边界**（写进判据注释，不留给猜）：反斜杠那一格在本机**无法用行为分辨**——旧实现靠的 `ToSlash` 在 Windows 上恰好会转。它的价值在 **Linux CI**，那里它会红。所以我没有假装"本机验证过平台无关性"；能本机验证的是 `//` 那两格（它们确实红了），以及代码不再调用平台相关的 API 这一**结构性事实**。
