# ADR-021：`symlink` 落地模式保留降级

- **状态**：已定
- **日期**：2026-10-03
- **范围**：`vendor.linkMode = "symlink"` 在 v2 布局（[ADR-019](./adr-019-content-addressed-blobs.md)）下的行为
- **上游**：[ADR-019](./adr-019-content-addressed-blobs.md)（层 2 改按文件寻址）· [v0.8 复盘](../development/v0.8-retrospective.md)（那处用户可见变化）

> **结论**：`symlink` 模式在 v2 布局下**保留"退化为逐条目 hardlink"的现状**，
> **不实现**"按需物化一棵 hardlink 树"来恢复"整目录链接"的老语义。
>
> **代价**：`vendor/<dep>` 不再是一个指向 store 的符号链接，而是一棵真实目录 + N 个 hardlink。
> 磁盘收益**不变**（两者都不复制内容），变化的只是"它是一个链接"这件事本身。
> 这条代价是**可逆的**（见"重新考虑"），而且 v0.8 起就已经在文档里如实写了。

---

## 背景

ADR-019 把层 2 从"一棵已物化的树"改成 **blob 池 + 树清单**。`symlink` 模式的实现是
"把 `vendor/<dep>` 整目录链到 store 里那棵树"——**那棵树在 v2 下不存在了**。

v0.8 的处置（当时认定为**本版唯一一处用户可见的行为变化**）：

- v2 数据：退化为逐条目 hardlink，并在结果里**如实报告实际使用的 mode**
  （`vendor-layers.md` 的既有要求："所有链接失败路径必须可观测"）；
- v1 数据：仍走整目录 symlink（两种布局各自保持自己的语义）。

那个处置本身是对的（**不静默降级**），但它留下了一个待决问题：要不要把老语义**做回来**。

---

## 两个选项

| 选项 | 做法 | 成本 | 收益 |
|------|------|------|------|
| **(a) 恢复整目录链接** | 落地时**按需把该 digest 的 blob 物化成一棵 hardlink 树**（放在某处 cache），再把 `vendor/<dep>` 链到它 | 新增**第二份派生物**：谁创建、谁清理、与 store 的一致性如何挂钩、并发安装怎么办 | `vendor/<dep>` 重新是"一个链接"；与 v1 语义一致 |
| **(b) 保留降级**（本决策） | 什么都不做 | 无 | 无 |

### 为什么 (a) 的收益低于看起来的样子

`symlink` 模式的**初衷**是"不复制内容、且一眼能看出这是派生物"。在 v2 下：

- **不复制内容**：hardlink 已经做到（同一 inode，零额外字节）✓
- **一眼看出是派生物**：`ngm.vendor/` 整体就是派生物，README 与文档都这么写 ✓；
  单看某个依赖目录"是不是符号链接"并不承载额外信息。

它真正剩下的差别只有两条，且都很边际：

1. **inode 数量**：一个链接 vs N 个 hardlink（N = 该依赖的文件数）；
2. **目录级操作**：某些工具（监视器、容器挂载、备份）对"符号链接目录"与"真实目录"处理不同。

第 2 条是唯一真实的功能性差别——**但它需要证据**，而不是假设。

### 为什么 (a) 的成本高于看起来的样子

它引入的正是这两版一直在消除的东西：**第二份没人回收的派生物**。

- ADR-018（回收）刚因为"没有项目注册表 → 没人敢删"而选择不做回收；
- ADR-019 特意拒绝"就地迁移"，理由是"中途失败会留下半转换的 store"；
- v0.9 花了整个版本把"store 里什么占了地方、哪些能回收"变成可读的数。

再加一棵按需物化的 cache 树，等于**在刚把账算清的地方再开一本账**
（它的失效方式很隐蔽：cache 树在、store 里对应的 blob 被删 → 落地的 vendor 看起来没问题，
但重新 link 会失败）。

---

## 决策

1. **保留 v0.8 的降级行为**：v2 数据下 `symlink` 模式 = 逐条目 hardlink，并在输出里报告实际 mode。
   v1 数据保持整目录 symlink（两种布局各自保持语义）。
2. **不实现按需物化**（选项 a）。理由不是"做不到"，而是**收益没有证据、成本在刚清账的地方**。
3. **文档维持已写清的状态**：`vendor-layers.md`、`guides/configuration.md`、ADR-019 §修订 已如实
   记录这处行为变化；本 ADR 把它从"待决"变成"已决"。
4. **触发条件（任一成立即重开）**：
   - 出现**真实报告**：某工具或流程要求"依赖目录本身是符号链接"（例如容器挂载、
     备份工具跟随符号链接、Windows 路径长度限制）；
   - 出现**实测的 inode 压力**：某真实项目因 hardlink 数量导致可观测的问题
     （例如 inode 配额、`find` 类操作显著变慢）。
   两条都要求**具体的场景与数字**，不接受"符号链接更干净"这类偏好。

---

## 后果

- **一处已知的行为变化以"决定不改"结项**，而不是留一条永远的待办。
- **`symlink` 这个 mode 名的含义需要读者注意**：在 v1 数据上它仍指"整目录链接"，
  在 v2 数据上指"逐条目 hardlink"。这是本 ADR 的代价，已写在这里；
  如果这一点在将来造成误解（而不是偏好分歧），那是重开的第一个信号。
- **不做任何代码改动**：本 ADR 不新增实现，只固定判断。
