# ADR-020：`remote` adapter 正式搁置

- **状态**：已定
- **日期**：2026-10-03
- **范围**：`remote` adapter 的**投入决策**（不是它的信任边界——那由 ADR-013/017 定）
- **上游**：[ADR-013](./adr-013-remote-adapter.md)（信任边界）· [ADR-017](./adr-017-remote-adapter-release-decision.md)（发布门槛）

> **结论**：把 `remote` adapter **从候选池里移出，正式搁置**。
> 理由不是"信任问题没解决"，而是**它的成本此前被低估了一个量级**：
> 这个 adapter 在代码里**根本不存在**——`AdapterRemote` 只是一个"按决定排除"的目录项
> （声明它 → `exit 5`，见 `internal/adapter/catalog.go`）。因此"发布它"= **从零实现
> 一套远端执行协议 + 产物回传 + 抽样复算**，而不是打开一个开关。
>
> **代价**：把构建放到远端这件事，ngm 现在**没有、也不打算有**原生答案。
> 需要的人用 CI 矩阵或自建远端 runner——那些是通用工具已经解决的问题。

---

## 背景

这条线走过三步，每一步的结论都不同，且**都写在文档里**：

| 时间 | 文档 | 结论 |
|------|------|------|
| v0.3 | [ADR-013](./adr-013-remote-adapter.md) | **不发布**：远端构建与"本地可复算"冲突（信任边界） |
| v0.6 | [ADR-017](./adr-017-remote-adapter-release-decision.md) | 门槛 a（某个真实引擎的产物可复现）**已满足**；门槛 b（抽样构建的成本）**未测**；两条都成立**也不自动发布** |
| 现在 | 本 ADR | **搁置**：不是"等技术条件"，而是**成本结构变了判断** |

v0.5 的复核曾把门槛 a 判为"技术前提成立"（3 平台 × 7 形态字节一致），
v0.6 又补上了真实形态（代码分割 / 资产指纹 / 三钩子插件链）的跨机器结论。
**所以"能不能复现"不再是障碍**——这正是本 ADR 必须给出新理由的原因。

---

## 决定性的一个事实：这东西要从零写

`internal/adapter/catalog.go` 里 `AdapterRemote` 的注释是"**按决定排除**（ADR-013）→ exit 5"，
`runner.go` 里给用户的提示是"a remote engine would send your source off this machine,
and no local check could prove the artifact matches it"。

也就是说，目前**没有**任何一行远端执行代码。所谓"发布 remote adapter"实际包含：

1. **一套远端执行协议**（提交源码 + 环境描述 → 取回产物 + 引擎版本 + 执行日志）；
2. **产物的本地抽样复算**（把远端产物与本地对同一输入的重建结果比较——这是 ADR-013 信任边界
   的落点，也是门槛 b 要量的成本）；
3. **它自己的失败面**：远端不可达、超时、额度、版本漂移、以及"远端说它用的是 esbuild 0.25
   但实际不是"这类**无法在本地证明**的声明。

第 3 条是关键：这个 adapter 会引入一个**ngm 无法独立验证的外部事实**（远端到底跑了什么）。
ADR-013 已经论证过"签名证明谁说的，不证明说的是真的"，同一结构在这里复现——
而代价从"加一个配置项"变成了"维护一条协议"。

---

## 决策

1. **`remote` 从候选池移出**，本 ADR 记下最终状态：**搁置**（shelved）。
   能力矩阵里它保持 `排除（ADR-013）`，并指向本 ADR 说明"为什么不做"。
2. **不再把"门槛 b 的测量"当待办**。门槛 b 是"抽样构建的成本数字"，但它的意义取决于
   "有人想用远端构建"这一前提——而**没有任何需求信号**（GitHub 0 star / 0 fork / 无 issue）。
   在无需求的前提下测这个数字，量出来的只是一个没人会用的成本。
3. **触发条件（任一成立即重开，并修订本 ADR）**：
   - 出现**真实用户或团队**提出"我的构建必须在远端跑"（不是"如果支持就好了"）；
   - 出现**本地算力不足**的实测证据（例如某类真实项目在本机构建时间超过其 CI 时限）；
   - 出现**跨生态的远端构建标准**（像 SBOM 的 SPDX / CycloneDX 那样有公认格式与验证方式），
     且它包含"产物可由第三方复算"的语义——那时应**实现该标准**而非发明自己的协议。
4. **把它从"待决策"清单里删掉**：项目状态评估页里这一条不再列为"等你决策"，
   改为"已决：搁置（ADR-020），触发性重开"。

---

## 后果

- **待决策清单少一条**，而且少的是唯一一条**没有需求信号**的：剩下的三条
  （`symlink` 模式、blob 回收、3s 口径）都有实测数据或用户可见影响作为依据。
- **文档要一致**：ADR-013 保持"决策快照"不动（它是历史），ADR-017 已承接"发布与否"，
  本 ADR 承接"投入与否"——三层各管一件事，互不覆盖。
- **用户的期望写清**：ngm 不提供远端构建，也不提供"远端产物可被本地证明"的机制。
  这条限制写在这一页，不在别处含糊过去（与 ADR-014 的处置方式相同）。
