# ADR-017：remote adapter 的发布决策（v0.5 判定）

- **状态**：已定
- **日期**：2026-10-02
- **范围**：引擎 adapter 模型（`remote`）；供应链信任边界
- **与 ADR-013 的关系**：**修订**（不推翻其结论）。ADR-013 的决策第 3 条写着"将来若要发布，
  **必须先修订本 ADR**"——本文件就是那次修订，而它决定的正是"发布与否"这件事本身。

> **结论：仍不发布 `remote` adapter。** ADR-013 的结论不变，但**理由的构成变了**：
> 翻案条件第 1 条的技术前提（"先实测某个真实引擎能做到"）**已有实测支撑**，
> 剩下的**不是待补的工程，而是两个产品问题**。本 ADR 把这两个问题写成可判定的形式，
> 并写明"凭什么数据、由谁"来做下一次判定。
>
> **用户可见行为完全不变**：声明 `adapter: remote` 的条目仍按 ADR-013 报"按 ADR 排除"，
> 不新增任何实现，也不出现 "planned" 一类措辞。

---

## 为什么现在写这个 ADR

不是为了改变结论，而是因为**不写它，结论就会开始腐烂**。三件事同时到期：

1. ADR-013 的决策第 3 条明确要求"发布与否"必须由**新的** ADR 记录；
2. [v0.5 复盘](../development/v0.5-retrospective.md)已把它登记为收尾项——B 组的实测改变了
   **理由的构成**，而原文只写了"条件正在收敛"；
3. 那段实测（跨机器一致性）恰好会让人得出一个**错误的推论**："既然产物可复现，
   那就可以发布了"。本 ADR 的主要篇幅就在拆这个推论。

---

## 本 ADR 只决定一件事

**发布与否。** 它**不**重新论证 ADR-013 的那三个问题（发给谁 / 如何证明没被替换 / 失败如何不静默降级）。
那三问的答案不变，尤其是第 2 问：**这是结构性问题，不是工程问题。**

---

## 现状：哪一半已经证了，哪一半没有

| 项 | 状态 | 证据 |
|----|------|------|
| 产物**可复现**（同一源码 + 同一引擎版本 → 相同字节） | ✅ **已实测** | 3 平台（Linux x86_64 / Windows x86_64 / macOS arm64）× 7 形态字节一致（`treeA=7412c584ca107988`），且各自路径无关；对照组敏感（[ADR-013 第三/四批](./adr-013-remote-adapter.md)） |
| 跨机器比对是**机器判定**而非人读 | ✅ | `scripts/compare-probe-results.mjs` 四层判定，含**引擎版本一致** |
| 用户能**抽样本地复现** | ⚠️ **机制成立，代价未测** | 机制上成立（路径无关已证）；但"一条命令复现某个远端产物并比对"没有原型，成本无数字 |
| 形态覆盖到**真实项目** | ⚠️ **帽子只摘了一半** | 有插件链 / loader 链 / 压缩链，但插件是**我们自己写的最小插件**；代码分割、资产指纹、真实插件生态未测 |
| 远端**只用了你送出的源码**（没有偷读本地文件） | ❌ **未答** | 与字节一致性**无关**：一个只读了你一半源码、其余凭本机状态的构建，照样能产出稳定的字节 |
| ADR-013 第 1 问：远端的**身份**可认定 | ❌ 答不上来（不变） | 见 ADR-013 §1 |
| ADR-013 第 2 问：**如何证明没被替换** | ❌ 结构性问题（不变） | 见 ADR-013 §2 |

**倒数第二行是本 ADR 最想强调的**：v0.5 那一组实测证明的是**确定性**，
而"远端是否只用了你送出的源码"证明的是**输入边界**。两者是正交的——
字节一致不能推出"它没读别的东西"，反过来也一样。**把前者读成后者，正是那个错误的推论。**

---

## 决策

### 1. 仍不发布

理由不是"还差点工程"，而是：**剩下的两个问题，我一个都不该替使用者回答。**

| 剩下的问题 | 为什么不能由维护者单方面回答 |
|-----------|---------------------------|
| 用户是否愿意为一次远端构建**在本地抽样构建一遍**？ | 抽样构建的代价**正好是远端想省下的东西**。愿不愿意付，只有用户知道；而我若替他接受了，就等于替他接受了一个新的信任假设 |
| "真实项目形态"是否也成立？ | 这是**证据缺口**，不是判断分歧——补它的方式明确（下节门槛 a），但没补上之前不能假定 |

ADR-013 第 2 问的结论在这里再次生效：ngm 无法把"远端是诚实的"变成**可验证**的假设，
因此唯一与项目立场一致的形状就是"用户自己抽样验证"，**而这个验证要花用户的时间**。

### 2. 判定门槛写死（两条**同时**成立，才进入"发布"这个决策）

- **a. 真实形态的可复现证据**：至少一种**真实**工具链（真实插件生态，或代码分割 + 资产指纹
  这类真实项目必然打开的形态）在三平台 × 两个不同路径下字节一致，且比对仍由机器判定。
  *合成夹具上的 7 个形态不满足这一条。*
- **b. 抽样构建的可用性有数字**：给出"在本机用一条命令复现远端产物并比对"的成本——
  例如"100 依赖项目抽样 3 个包 < 10s"——而不是"抽一下就行"。没有这个数字，
  门槛 a 即使成立也只是技术可行，产品上仍不可判。

### 3. 两条都成立**也不自动发布**

到那时仍需**再次修订本 ADR**，把那两条的结果写进来再决定。
"技术可行"与"要发布一个会把源码送出本机的功能"是两件事——这一条是 ADR-013 决策第 3 条的延续，
不是仪式：它保证发布这个动作**必须有人明确签字**，而不会因为某个 PR "顺手把门打开了"。

### 4. 本 ADR 不新增任何实现

`internal/adapter` 里没有 `remote.go`，这一版也不会有。`adapter: remote` 的错误信息与
ADR-013 的形状一致（指向 ADR-013；如需追溯本 ADR，从 ADR-013 的"相关文档"进）。

---

## 什么情况下这个"不发布"会被推翻

- **门槛 a + b 同时成立**，且 b 给出的数字被判定为"可接受"（判定人 = 使用者，不是维护者）
- 或者出现 **ADR-013 第 2 条**那种更简单的形态："远端只接触**已经公开**的源码，
  且用户能独立核对取回的产物与公开源的对应关系"——那时第 1、2 问都退化了，
  本 ADR 应被修订为"发布"
- 也可能**永远不成立**：如果代码分割产物在某个真实工具链上实测**不可复现**，
  那么门槛 a 就无法满足，`remote` adapter 就永久停留在"已决定不发布"——
  **这也是一个可接受的结局**，而且比发布一个"看起来有验证、其实是擦边"的功能好

---

## 后果

- v0.5 复盘 §7 候选 1 由"待决策"变为"**门槛明确、等待证据**"；
  v0.6 的范围据此**只做门槛 a 的证据补齐**（真实形态探针），不进入实现
- 给使用者一个明确答复：**为什么实测了跨机器一致性却仍不发布**——因为那条实测证明的是确定性，
  而缺的是输入边界与抽样成本
- ADR-013 保持"已定"不动（决策快照），本 ADR 承接它第 3 条留下的动作，两篇互为引用
- 任何"把源码或产物送出本机再取回"的新能力（远端 verify、远端缓存、远端审计）仍要回答
  ADR-013 的第 2 问，且必须单独走一次"发布与否"的决策——本 ADR 的门槛写法可以复用
