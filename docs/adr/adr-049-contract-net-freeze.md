# ADR-049：契约网冻结（停止新建，保留复核节奏）

- **状态**：已定（确认并执行停止清单）
- **日期**：2026-11-20
- **范围**：全部 `test_*.go` / `vNNN_*_test.go` 里的源码扫描 / AST 契约网
- **依据**：[roadmap 停止清单](../internals/roadmap.md) · [全维度评估 2026-11-20 §4](../analysis/ngm-full-assessment-2026-11-20.md)

> **结论**：维持"停止新建契约网"的纪律——新判据必须先指着一个**已经发生的产品缺陷**，
> 不为假想问题造网。已有的约 39 个契约网文件保留（它们是历史缺陷的回归档案），
> 但新增需要过门槛；同时给"何时复核/精简存量网"定一个节奏。

## 背景

`docs/internals/roadmap.md` 的停止清单已记录外部评估结论（v0.72 对账维持）：
"它抓的最后一个**产品**缺陷是 v0.55；之后 10 版抓的全是文档与判据自己的问题"。
全维度评估 §2.3 也把"契约网过剩"列为结构性债，并观察到用判据维持冗余、而非消除冗余。

但"冻结"不等于"全部拆掉"：这些网大多是真实缺陷留下的回归档案，
删除它们（连同 ADR / 逐版本归档）会让引用它们的判据变红（17+ 测试依赖），
且与文档范围选择冲突。第一批 A–G 与此刻的 H/I 批都遵守了纪律——
新判据只针对已发生的真实缺陷（net 门禁旁路、`verify --json` 顺序、gc 退出码、
WASM OOM、混合 link 树、scp 提示、覆盖率不可见），不为假想问题加网。

## 决策

1. **停止新建契约网**：任何新的"源码扫描 / AST 对账 / 文档↔代码"判据，必须在提交说明里
   指着一个**已经发生**的产品缺陷（issue / 评估报告条目 / 缺陷 commit）；纯防御性设想不批。
2. **存量网保留**，不因"数量多"删除；与 ADR / 逐版本归档一同视为回归档案。
3. **复核节奏**：仅在以下情形复核存量网是否需要精简——
   - 某张网连续 **3 个版本**因自身（文档措辞、判据实现）而红、却从未抓到产品缺陷；
   - 删除它不影响任何产品不变量，且能明确减少维护成本（给出具体数字）。
4. 本 ADR 与 roadmap 停止清单同源；两者之一更新时另一处同步。

## 后果

- "下一张网必须先指着一个已发生的缺陷"从口头纪律变成有 ADR 背书的决策。
- 复核有门槛，避免"定期清理"变成周期性地重写 golden。
