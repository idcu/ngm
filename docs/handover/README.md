## 跨仓约定（**唯一事实源**，四份文档都引用这里）

| 约定 | 值 |
|------|-----|
| 切片产物目录 | `packages/**/<pkg>/ngm-dist/`——**不要用 `dist/`**（根 `.gitignore` 排除它） |
| 切片入口 | `./ngm-dist/index.mjs` 与 `./ngm-dist/index.d.ts` |
| 切片清单 | 包根 `ngm.json`（`schemaVersion` / `name` / `version` / `runtime` + `main`/`types`） |
| 消费方的 `#path=` | L0 包就是它的目录：`packages/common/packages/<name>` |
| 标签 | `v<version>-ngm.<n>`；**先验证预发布后缀能过库标准的语义化标签判据**再定版本线 |
| 库侧自检 | `powershell -NoProfile -File <ngm>\scripts\check-library-standard.ps1 -Dir <repo>`（`.sh` 是唯一实现，`.ps1` 只转调） |
| 产物侧自检 | `powershell -NoProfile -File <ngm>\scripts\check-vendored-standard.ps1 -Dir <project>`（退出码 **2** = "一个依赖都没查"，与"全查过且都合格"必须分开） |
| 离线验收 | `ngm install --frozen-lockfile --offline` + 断网双击 `index.html` |

## 许可与商业化：已经定下来的事

qforge 与 plotpin **确定要走商业化**，许可因此已决策（不再是"待选"）：

| 项目 | 核心代码 | 商业能力 | 内容资产 |
|------|---------|---------|---------|
| **qforge** | MIT | 专有（独立私有仓或 `enterprise/`） | 真实题库：单独许可，**不进公开仓** |
| **plotpin** | 保持 MIT | 专有（独立私有仓或 `enterprise/`） | 行业符号库/模板：单独许可 |
| **lytjs** | MIT（不变） | — | — |
| **ngm** | MIT（不变） | — | — |

**为什么是 open-core**：① **付费方是组织**，买的是责任、合规、集成与内容，不是这些代码本身；核心开源
降低试用与内审门槛——而**没有许可证的仓库，客户法务那一关过不去**（qforge 今天正是这个状态）；
② 四个项目是一条可解释的线（ngm / lytjs 是 MIT，内核也 MIT，商业能力专有）；
③ 真正会被抄走的是**内容与行业 know-how**，不是这几千行代码。
**不选 AGPL / BUSL**：会挡住"内网、涉密、政企"客户或让你失去开源身份，而这两个产品是离线单机，
被"云厂商白嫖"的风险极低。

**退出通道**：两个应用**现在就加 CLA / DCO**——已发布的 MIT 版本不可撤回，但**未来版本**可以改；
等第一个外部 PR 进来再立规矩就晚了。

## 三条硬约束（四份方案共同遵守）

1. **要进 lytjs 的模块必须是 MIT 兼容许可**——lytjs 是 MIT，AGPL/GPL 的代码进不去。
2. **许可边界 = 目录边界**：商业能力必须在 `enterprise/**`（或独立私有仓），**不在公开仓出现**。
3. **提取完成前不删旧实现**——半搬状态会让两个应用同时不可运行。

## 两条使用提醒

- 四份文档里的相对链接（例如 `../internals/…`）只在**本仓库内**成立。复制到对应项目仓库时，
  请换成绝对路径或 URL——**跨仓的相对链接只在作者的机器上成立**（v0.75 的教训）。
- 两个应用仓库**现在还没有标签**：还没有人用 `refType=tag` 锁定过它们的提交。要换许可、调整形态或
  重置历史，**现在成本最低**；一旦有人锁定，改写历史在 `ngm verify` 里会显示为 `unexpected` 漂移。
